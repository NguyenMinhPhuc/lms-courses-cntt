BÀI 10 - Kiểm thử, gỡ lỗi & tối ưu hiệu năng (5 tiết: 2 LT / 3 TH)

Ứng dụng của nhóm đã "chạy được". Nhưng nếu tuần sau một bạn sửa hàm tính tổng tiền, ai sẽ phát hiện nó tính sai? Và trên chiếc điện thoại Android cũ của giảng viên, danh sách món có còn cuộn mượt như trên máy của bạn?

Mục tiêu: Viết được unit test và component test cho ứng dụng; kiểm thử được stored procedure bằng script T-SQL; sử dụng được công cụ gỡ lỗi; đánh giá và cải thiện được hiệu năng và khả năng truy cập (accessibility).

Nội dung:

  • Ý chính 1 - Kiểm thử tự động: Jest + React Native Testing Library; test logic nghiệp vụ, test component, mock API; kiểm thử stored procedure bằng T-SQL.
  • Ý chính 2 - Gỡ lỗi: React Native DevTools, xem log, request mạng, sự kiện socket; quy trình tái hiện lỗi (liên hệ học phần Kiểm thử phần mềm).
  • Ý chính 3 - Hiệu năng: vẽ lại thừa, React.memo/useCallback, tối ưu FlatList và ảnh; đo trước và sau khi sửa.
  • Ý chính 4 - Accessibility và test do AI sinh: nhãn cho trình đọc màn hình, cỡ chữ hệ thống, vùng chạm; kiểm chứng test AI sinh ra có thật sự bắt được lỗi.

Kết quả cần đạt: LHU Food có bộ test chạy bằng npm test, kịch bản kiểm thử thủ tục; nhóm có bug log và ít nhất một cải tiến hiệu năng có số liệu trước/sau.

CLO liên quan: CLO1.

📚 2. Học liệu chính ▼

2.1. Thiết lập Jest cho dự án Expo

Theo hướng dẫn của Expo, cài jest-expo (preset cấu hình sẵn Jest cho React Native) và React Native Testing Library:

npx expo install jest-expo jest @types/jest -- --save-dev
npx expo install @testing-library/react-native -- --save-dev

Thêm vào package.json:

"scripts": { "test": "jest --watchAll" },
"jest": { "preset": "jest-expo" }

File test đặt trong thư mục __tests__/ hoặc đặt tên *.test.ts(x). Chạy bằng npm test. Store giỏ hàng dùng AsyncStorage (bài 07) cần mock AsyncStorage trong file thiết lập Jest bằng mock có sẵn của thư viện.

2.2. Unit test và component test

Unit test kiểm tra một hàm hoặc một store, không cần giao diện:

// stores/__tests__/cart.test.ts
import { useCart } from '../cart';

beforeEach(() => useCart.setState({ items: [] }));

test('thêm trùng món thì cộng dồn số lượng', () => {
  useCart.getState().add({ id: 1, name: 'Cơm gà', price: 35000 });
  useCart.getState().add({ id: 1, name: 'Cơm gà', price: 35000 });
  expect(useCart.getState().items).toHaveLength(1);
  expect(useCart.getState().items[0].quantity).toBe(2);
  expect(useCart.getState().total()).toBe(70000);
});

test('giảm số lượng về 0 thì xóa món khỏi giỏ', () => {
  useCart.getState().add({ id: 2, name: 'Trà đào', price: 20000 });
  useCart.getState().decrease(2);
  expect(useCart.getState().items).toEqual([]);
});

Component test vẽ component và thao tác như người dùng: tìm theo chữ hiển thị, bấm, kiểm tra kết quả:

// components/__tests__/ProductCard.test.tsx
import { render, screen, fireEvent } from '@testing-library/react-native';
import { ProductCard } from '../ProductCard';

test('hiển thị tên món và gọi onAdd khi bấm nút', () => {
  const onAdd = jest.fn();
  render(<ProductCard name="Bún bò Huế" price={40000} onAdd={onAdd} />);

  expect(screen.getByText('Bún bò Huế')).toBeTruthy();
  fireEvent.press(screen.getByText('Thêm vào giỏ'));
  expect(onAdd).toHaveBeenCalledTimes(1);
});
  • Mock API: test màn hình có gọi API thì thay lib/api bằng jest.mock('@/lib/api') và quy định dữ liệu trả về, để test không phụ thuộc server.
  • Test hành vi, không test chi tiết cài đặt: tìm phần tử theo chữ người dùng thấy hoặc accessibilityLabel, không theo tên biến hay cấu trúc bên trong.
  • Mỗi test độc lập: beforeEach đặt lại state để thứ tự chạy không ảnh hưởng kết quả.

2.3. Kiểm thử stored procedure

Logic dữ liệu nằm trong thủ tục, nên thủ tục cũng phải được kiểm thử. Chạy trên CSDL kiểm thử riêng (tạo từ thư mục database/), không chạy trên CSDL thật.

-- tests/test-order-create.sql (chạy trên CSDL LhuFood_Test)
UPDATE Products SET Stock = 1, IsAvailable = 1 WHERE ProductId = 1;

-- TC-01: đặt quá tồn kho phải báo lỗi 50409 và không tạo đơn
DECLARE @before INT = (SELECT COUNT(*) FROM Orders);
BEGIN TRY
  EXEC sp_Order_Create @UserId = 1, @ItemsJson = N'[{"productId":1,"quantity":2}]';
  PRINT N'FAIL TC-01: không báo lỗi';
END TRY
BEGIN CATCH
  IF ERROR_NUMBER() = 50409 AND (SELECT COUNT(*) FROM Orders) = @before
    PRINT N'PASS TC-01';
  ELSE
    PRINT N'FAIL TC-01: ' + ERROR_MESSAGE();
END CATCH

-- TC-02: đặt đúng 1 suất thì tồn kho về 0
EXEC sp_Order_Create @UserId = 1, @ItemsJson = N'[{"productId":1,"quantity":1}]';
IF (SELECT Stock FROM Products WHERE ProductId = 1) = 0 PRINT N'PASS TC-02' ELSE PRINT N'FAIL TC-02';

Thiết kế ca kiểm thử theo kỹ thuật đã học ở môn Kiểm thử phần mềm: giá trị hợp lệ, không hợp lệ (JSON sai, số lượng âm), giá trị biên (đặt đúng bằng tồn kho, lớn hơn 1).

2.4. Gỡ lỗi

  • React Native DevTools: nhấn j trong cửa sổ npx expo start để mở; có Console, đặt breakpoint, xem cây component và Profiler.
  • Màn hình đỏ (RedBox): đọc dòng đầu tiên của stack trace thuộc mã của bạn (không phải trong node_modules); đó thường là nơi phát sinh lỗi.
  • Lỗi mạng: log URL, mã trạng thái và nội dung lỗi trả về; thử cùng request bằng Swagger để biết lỗi ở app hay ở API.
  • Socket: lắng nghe connect_error để biết vì sao không kết nối được (token, địa chỉ, phiên bản).

Quy trình xử lý một lỗi (bug log của nhóm):

  1. Tái hiện: ghi lại các bước, dữ liệu, thiết bị, phiên bản để lỗi xảy ra lại được.
  2. Khoanh vùng: lỗi ở app, API, thủ tục hay dữ liệu? Kiểm tra từng ranh giới.
  3. Viết test tái hiện lỗi (test phải đỏ), sửa mã, test chuyển xanh.
  4. Ghi vào bug log: mô tả, mức độ, nguyên nhân, cách sửa, commit.

2.5. Hiệu năng

Vẽ lại thừa: khi màn hình cha đổi state, mọi component con vẽ lại, kể cả khi props không đổi. Với danh sách 200 món, mỗi lần gõ một ký tự vào ô tìm kiếm có thể làm 200 thẻ vẽ lại.

// Chỉ vẽ lại ProductCard khi props thật sự đổi
export const ProductCard = React.memo(function ProductCard({ name, price, onAdd }: Props) { ... });

// Giữ nguyên tham chiếu hàm giữa các lần vẽ, nếu không memo sẽ vô tác dụng
const handleAdd = useCallback((item: Product) => add(item), [add]);
const renderItem = useCallback(
  ({ item }: { item: Product }) => <ProductCard {...item} onAdd={() => handleAdd(item)} />,
  [handleAdd],
);
  • FlatList: keyExtractor ổn định; initialNumToRender vừa đủ một màn hình; getItemLayout khi các dòng có chiều cao cố định.
  • Ảnh: dùng ảnh có kích thước phù hợp từ server; thư viện expo-image có bộ nhớ đệm và hiệu ứng hiện ảnh mượt hơn Image mặc định.
  • Đo trước khi sửa: dùng Profiler trong React Native DevTools để xem component nào vẽ lại nhiều và mất bao lâu; ghi số liệu trước và sau.
  • Đo ở chế độ gần thật: chế độ phát triển chậm hơn bản phát hành; chạy npx expo start --no-dev --minify và thử trên một máy Android tầm trung.

2.6. Accessibility và test do AI sinh

  • Trình đọc màn hình (TalkBack): nút chỉ có biểu tượng phải có accessibilityLabel ("Thêm vào yêu thích") và accessibilityRole="button".
  • Cỡ chữ hệ thống: người dùng có thể tăng cỡ chữ; kiểm tra giao diện không vỡ khi chữ lớn hơn.
  • Vùng chạm: tối thiểu khoảng 44–48 dp; dùng hitSlop cho biểu tượng nhỏ.
  • Độ tương phản: chữ xám nhạt trên nền trắng khó đọc ngoài trời.

Test do AI sinh: Copilot sinh test rất nhanh, nhưng test có thể "luôn xanh" mà không kiểm tra gì. Dùng mutation thủ công để kiểm chứng:

  1. Cố ý sửa sai logic (ví dụ đổi price * quantity thành price + quantity).
  2. Chạy test: nếu vẫn xanh, test đó không có giá trị.
  3. Hoàn lại mã; bổ sung khẳng định (expect) cho đến khi bản sửa sai làm test đỏ.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): Test và tối ưu LHU Food

  1. Cài và cấu hình Jest theo mục 2.1; chạy test mẫu.
  2. Viết test cho store giỏ hàng (thêm, cộng dồn, giảm, xóa, tổng tiền) và test cho ProductCard.
  3. Viết tests/test-order-create.sql và chạy trên CSDL kiểm thử.
  4. Mở Profiler, gõ vào ô tìm kiếm ở Trang chủ và ghi số lần vẽ lại của danh sách; áp dụng React.memo và useCallback; đo lại.
  5. Thêm accessibilityLabel cho các nút chỉ có biểu tượng; thử bằng TalkBack.

✍️ Thực hành không hướng dẫn (1 tiết): Test có giá trị

Chọn một module tự làm (form đăng ký, hàm khoảng cách, store xác thực…). Viết tối thiểu 5 test (có thể nhờ AI sinh), sau đó áp dụng mutation thủ công với ít nhất 3 lỗi cố ý.

Hoàn thành khi: 5 test pass; nộp bảng gồm lỗi cố ý, test nào bắt được, test bổ sung cho lỗi chưa bị bắt; ghi prompt sinh test vào PROMPTS.md.

🆘 4. Góc trợ giúp và mở rộng ▼

Test báo lỗi khi import thư viện native (AsyncStorage, SecureStore…): môi trường Jest không có mã native; mock thư viện đó bằng jest.mock(...) hoặc dùng mock có sẵn của thư viện.

Test giỏ hàng ảnh hưởng lẫn nhau: store Zustand dùng chung giữa các test; đặt lại bằng useCart.setState({ items: [] }) trong beforeEach.

Lỗi chỉ xảy ra trên bản APK, không xảy ra khi chạy Expo Go: thường do biến môi trường, quyền chưa khai báo trong app.json, hoặc kết nối HTTP bị chặn; bài 11 xử lý các trường hợp này.

Kiến thức mở rộng: Kiểm thử đầu-cuối (E2E) bằng Maestro, chạy kịch bản thao tác trên emulator như người dùng thật.

Tự đánh giá: Nếu ngày mai một bạn trong nhóm sửa sp_Order_Create, nhóm có cách nào biết ngay thủ tục vẫn chặn được đặt quá tồn kho không?
