BÀI 09 - Thông báo thời gian thực với Socket.IO - BẮT BUỘC (5 tiết: 1 LT / 4 TH)

Bạn đặt món xong và ngồi chờ. Không ai muốn cứ 10 giây lại kéo màn hình để xem "món của mình xong chưa". Làm sao để ngay khi nhân viên căn tin bấm "Sẵn sàng", điện thoại của bạn sáng lên báo tin?

Mục tiêu: Giải thích được cơ chế giao tiếp thời gian thực (WebSocket/Socket.IO) và so sánh với polling; xây dựng được thông báo realtime từ NestJS tới ứng dụng, có xác thực và lưu lịch sử trên SQL Server; trình bày được luồng dữ liệu realtime bằng sơ đồ tuần tự.

Nội dung:

  • Ý chính 1 - Realtime là gì: polling và WebSocket; Socket.IO với kết nối, sự kiện, room, tự kết nối lại; sơ đồ tuần tự luồng thông báo.
  • Ý chính 2 - NestJS Gateway: @WebSocketGateway, xác thực kết nối bằng JWT, gửi sự kiện theo room người dùng/vai trò, lưu thông báo qua stored procedure.
  • Ý chính 3 - Phía ứng dụng: socket.io-client, kết nối theo trạng thái đăng nhập, cập nhật cache TanStack Query khi nhận sự kiện.
  • Ý chính 4 - Hiển thị thông báo: banner trong app, badge chưa đọc, thông báo cục bộ bằng expo-notifications, bấm thông báo mở đúng màn hình; mở rộng: push khi app đã tắt.

Kết quả cần đạt: Khi nhân viên đổi trạng thái đơn, người đặt nhận thông báo ngay; màn hình đơn hàng tự cập nhật; nhóm hoàn thành Checkpoint Sprint 3 với ít nhất một luồng realtime và sơ đồ tuần tự.

CLO liên quan: CLO1, CLO3.

2.1. Polling, WebSocket và Socket.IO

Cách làmHoạt độngNhận xét
PollingApp hỏi API định kỳ: "có gì mới không?"Đơn giản nhưng chậm (phụ thuộc chu kỳ hỏi), tốn pin và tải server khi không có gì mới
WebSocketMột kết nối mở liên tục; server chủ động gửi khi có sự kiệnGần như tức thời; phải tự xử lý kết nối lại, xác thực, nhóm người nhận
Socket.IOThư viện xây trên WebSocketCó sẵn sự kiện có tên, room, tự kết nối lại, gửi kèm dữ liệu xác thực khi kết nối

Khái niệm chính của Socket.IO:

  • Sự kiện (event): thông điệp có tên, ví dụ order:status, kèm dữ liệu JSON.
  • Room: nhóm kết nối do server quản lý. Mỗi người dùng vào room user:<mã>; nhân viên vào thêm room staff. Gửi tới room thì mọi máy của người đó (hoặc mọi nhân viên) đều nhận.
  • Handshake auth: dữ liệu gửi kèm lúc kết nối; dùng để gửi JWT.

2.2. CSDL và thủ tục cho thông báo

Thông báo được lưu vào SQL Server trước rồi mới gửi qua socket. Nhờ vậy người dùng đang tắt app vẫn xem lại được lịch sử khi mở app.

CREATE TABLE Notifications (
  NotificationId INT IDENTITY(1,1) PRIMARY KEY,
  UserId         INT NOT NULL REFERENCES Users(UserId),
  Title          NVARCHAR(100) NOT NULL,
  Body           NVARCHAR(300) NOT NULL,
  OrderId        INT NULL REFERENCES Orders(OrderId),
  IsRead         BIT NOT NULL DEFAULT 0,
  CreatedAt      DATETIME2 NOT NULL DEFAULT SYSDATETIME()
);
CREATE INDEX IX_Notifications_UserId ON Notifications (UserId, IsRead, CreatedAt DESC);
GO

CREATE OR ALTER PROCEDURE sp_Order_UpdateStatus
  @OrderId INT, @Status NVARCHAR(20)
AS
BEGIN
  SET NOCOUNT ON;
  IF NOT EXISTS (SELECT 1 FROM Orders WHERE OrderId = @OrderId)
    THROW 50404, N'Không tìm thấy đơn hàng', 1;

  UPDATE Orders SET Status = @Status
  OUTPUT inserted.OrderId AS orderId, inserted.UserId AS userId, inserted.Status AS status
  WHERE OrderId = @OrderId;
END;
GO

Tương tự, viết sp_Notification_Create (trả về thông báo vừa tạo), sp_Notification_GetList (phân trang), sp_Notification_CountUnread và sp_Notification_MarkRead (chỉ đánh dấu được thông báo của chính @UserId). Ràng buộc CK_Orders_Status ở bài 07 tự chặn trạng thái không hợp lệ.

2.3. NestJS Gateway

Cài: npm install @nestjs/websockets @nestjs/platform-socket.io socket.io.

// src/notifications/notifications.gateway.ts
import { OnGatewayConnection, WebSocketGateway, WebSocketServer } from '@nestjs/websockets';
import { JwtService } from '@nestjs/jwt';
import { Server, Socket } from 'socket.io';

@WebSocketGateway()
export class NotificationsGateway implements OnGatewayConnection {
  @WebSocketServer() server!: Server;

  constructor(private readonly jwt: JwtService) {}

  async handleConnection(client: Socket) {
    try {
      const payload = await this.jwt.verifyAsync(client.handshake.auth?.token);
      client.data.user = payload;
      client.join(`user:${payload.sub}`);
      if (payload.role === 'staff') client.join('staff');
    } catch {
      client.disconnect();                 // không có token hợp lệ thì ngắt ngay
    }
  }

  toUser(userId: number, event: string, data: unknown) {
    this.server.to(`user:${userId}`).emit(event, data);
  }

  toStaff(event: string, data: unknown) {
    this.server.to('staff').emit(event, data);
  }
}
// src/orders/orders.service.ts: đổi trạng thái → lưu thông báo → gửi realtime
const STATUS_LABEL: Record<string, string> = {
  preparing: 'đang được chuẩn bị', ready: 'đã sẵn sàng, mời bạn đến nhận',
  completed: 'đã hoàn tất', cancelled: 'đã bị hủy',
};

async updateStatus(orderId: number, status: string) {
  const [order] = await this.db.execute<{ orderId: number; userId: number; status: string }>(
    'sp_Order_UpdateStatus',
    { OrderId: { type: sql.Int, value: orderId }, Status: { type: sql.NVarChar(20), value: status } },
  );
  const [notification] = await this.db.execute('sp_Notification_Create', {
    UserId: { type: sql.Int, value: order.userId },
    Title: { type: sql.NVarChar(100), value: 'Cập nhật đơn hàng' },
    Body: { type: sql.NVarChar(300), value: `Đơn #${orderId}: ${STATUS_LABEL[status]}` },
    OrderId: { type: sql.Int, value: orderId },
  });
  this.gateway.toUser(order.userId, 'order:status', { order, notification });
  return order;
}
  • Gateway mặc định chạy chung cổng với API (cùng HTTP server), nên app dùng chung địa chỉ EXPO_PUBLIC_API_URL.
  • Khi khách đặt đơn mới, gọi toStaff('order:new', …) để màn hình của nhân viên hiện đơn ngay.
  • Socket không thay API: mọi thao tác ghi vẫn đi qua API và stored procedure; socket chỉ dùng để báo tin.

2.4. Phía ứng dụng: kết nối và nhận sự kiện

Cài: npx expo install socket.io-client expo-notifications.

// hooks/useRealtime.ts: gọi một lần trong app/_layout.tsx
import { useEffect } from 'react';
import { io } from 'socket.io-client';
import { useQueryClient } from '@tanstack/react-query';
import * as Notifications from 'expo-notifications';
import { useAuth } from '@/stores/auth';

export function useRealtime() {
  const token = useAuth((s) => s.token);
  const queryClient = useQueryClient();

  useEffect(() => {
    if (!token) return;                                   // chỉ kết nối khi đã đăng nhập
    const socket = io(process.env.EXPO_PUBLIC_API_URL!, {
      auth: { token },
      transports: ['websocket'],
    });

    socket.on('order:status', async ({ order, notification }) => {
      queryClient.invalidateQueries({ queryKey: ['orders'] });
      queryClient.invalidateQueries({ queryKey: ['notifications'] });
      await Notifications.scheduleNotificationAsync({
        content: {
          title: notification.title,
          body: notification.body,
          data: { url: `/order/${order.orderId}` },
        },
        trigger: null,                                    // hiện ngay
      });
    });

    return () => { socket.disconnect(); };                // đăng xuất hoặc đổi token
  }, [token, queryClient]);
}
// app/_layout.tsx: hiện thông báo cả khi app đang mở, bấm thông báo mở đúng màn hình
Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldShowBanner: true, shouldShowList: true, shouldPlaySound: true, shouldSetBadge: false,
  }),
});

useEffect(() => {
  Notifications.requestPermissionsAsync();
  const sub = Notifications.addNotificationResponseReceivedListener((response) => {
    const url = response.notification.request.content.data?.url;
    if (typeof url === 'string') router.push(url);
  });
  return () => sub.remove();
}, []);
  • Thông báo cục bộ (do chính app tạo khi nhận sự kiện socket) chạy được trong Expo Go và là phần bắt buộc.
  • Socket chỉ hoạt động khi app đang mở hoặc vừa chạy nền. Khi mở lại app, gọi lại API danh sách thông báo để không bỏ sót.
  • Mở rộng: nhận thông báo cả khi app đã tắt cần push notification (Expo Push Token, lưu token ở backend, gửi qua dịch vụ push của Expo) và development build; xem tài liệu Expo Notifications.
  • Tên các tùy chọn của setNotificationHandler có thể khác giữa các phiên bản Expo SDK; đối chiếu tài liệu của phiên bản dự án đang dùng.

2.5. Trải nghiệm người dùng với thông báo

  • Chỉ báo điều người dùng quan tâm: đơn của tôi sẵn sàng, đơn bị hủy. Không báo mọi thay đổi nhỏ.
  • Có badge chưa đọc trên tab hoặc biểu tượng chuông; mở màn hình Thông báo thì đánh dấu đã đọc.
  • Cho phép tắt từng loại thông báo trong Cài đặt của app.
  • Xin quyền có giải thích: hỏi quyền thông báo sau khi người dùng đặt đơn đầu tiên ("Bật thông báo để biết khi món sẵn sàng?"), không hỏi ngay khi mở app.

🧑‍🏫 Thực hành có hướng dẫn (2 tiết): Đơn hàng realtime LHU Food

  1. Tạo bảng Notifications và các thủ tục ở mục 2.2; chạy thử bằng EXEC.
  2. Tạo NotificationsGateway (mục 2.3); PATCH /orders/:id/status (chỉ staff) gọi updateStatus.
  3. Trong app: useRealtime(), setNotificationHandler, xử lý bấm thông báo.
  4. Dùng hai thiết bị (hoặc một máy thật + một emulator): một tài khoản staff, một tài khoản customer. Nhân viên đổi đơn sang "Sẵn sàng" → khách nhận thông báo, màn hình đơn hàng tự cập nhật.
  5. Đặt đơn mới từ máy khách → màn hình đơn mới của nhân viên hiện ngay (sự kiện order:new).
  6. Vẽ sơ đồ tuần tự của luồng vừa làm bằng draw.io.

✍️ Thực hành không hướng dẫn (1,5 tiết): Màn hình Thông báo

Màn hình "Thông báo" hiển thị lịch sử lấy từ API (cuộn vô hạn), bấm một thông báo thì đánh dấu đã đọc và mở đơn hàng tương ứng; badge số chưa đọc trên tab cập nhật ngay khi có sự kiện socket; màn hình Cài đặt có công tắc bật/tắt thông báo (lưu bằng AsyncStorage).

Hoàn thành khi: tắt app, nhân viên đổi trạng thái 2 đơn, mở lại app vẫn thấy đủ 2 thông báo chưa đọc; người dùng A không đánh dấu đọc được thông báo của người dùng B (API kiểm tra qua thủ tục).

🆘 4. Góc trợ giúp và mở rộng ▼

App không kết nối được socket: dùng cùng địa chỉ IP LAN như API, không dùng localhost; đặt transports: ['websocket']; kiểm tra phiên bản socket.io-client tương thích với socket.io phía server (cùng v4).

Kết nối được rồi bị ngắt ngay: token gửi trong auth không hợp lệ hoặc đã hết hạn; sau khi làm mới token (bài 06), effect trong useRealtime chạy lại và kết nối với token mới.

Nhận sự kiện nhưng không hiện thông báo: chưa xin quyền thông báo, hoặc chưa gọi setNotificationHandler nên thông báo bị ẩn khi app đang mở.

Kiến thức mở rộng: Push notification bằng Expo Push Service khi app đã tắt; Socket.IO adapter (ví dụ Redis) khi API chạy nhiều tiến trình.

Tự đánh giá: Nếu server gửi sự kiện realtime nhưng không lưu thông báo vào SQL Server, người dùng đang tắt app sẽ mất gì?
