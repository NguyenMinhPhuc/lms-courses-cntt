BÀI 06 - Xác thực & bảo mật ứng dụng (5 tiết: 2 LT / 3 TH)

Hiện tại ai mở được LHU Food cũng đặt được hàng, và đơn hàng không biết thuộc về ai. Nhân viên căn tin và khách hàng dùng chung một app nhưng phải thấy các màn hình khác nhau. Làm sao để app "biết bạn là ai" sau mỗi lần mở, mà không lưu mật khẩu trên điện thoại?

Mục tiêu: Triển khai được đăng ký/đăng nhập bằng JWT ở cả API và ứng dụng; lưu trữ token an toàn; bảo vệ được màn hình và API theo trạng thái đăng nhập và vai trò.

Nội dung:

  • Ý chính 1 - Luồng xác thực JWT: đăng ký, đăng nhập, access token và refresh token; băm mật khẩu bằng bcrypt ở backend; dữ liệu người dùng đọc/ghi qua stored procedure.
  • Ý chính 2 - Lưu token đúng chỗ: Expo SecureStore cho token, AsyncStorage cho thiết lập không nhạy cảm; không bao giờ lưu mật khẩu.
  • Ý chính 3 - Bảo vệ route và phân quyền: chuyển hướng khi chưa đăng nhập trong Expo Router; Guard kiểm tra token và vai trò trong NestJS.
  • Ý chính 4 - Rủi ro bảo mật trên mobile: khóa bí mật trong bundle, log nhạy cảm, chỉ kiểm tra quyền ở app; tài khoản SQL Server chỉ có quyền EXECUTE.

Kết quả cần đạt: LHU Food có đăng ký/đăng nhập, tự đăng nhập lại khi mở app, phân quyền khách hàng/nhân viên; nhóm hoàn thành Checkpoint Sprint 2 và nộp bản nháp báo cáo vai trò cá nhân.

CLO liên quan: CLO1, CLO4.

📚 2. Học liệu chính ▼

2.1. Luồng xác thực JWT giữa app và NestJS

1. App gửi email + mật khẩu       → POST /auth/login
2. API gọi sp_User_GetByEmail, so mật khẩu với PasswordHash bằng bcrypt
3. API trả về accessToken (ngắn hạn, ~15 phút) + refreshToken (dài hạn, ~7 ngày)
4. App lưu token vào SecureStore
5. Mỗi request sau đó gửi header:  Authorization: Bearer <accessToken>
6. accessToken hết hạn → app gọi POST /auth/refresh bằng refreshToken để lấy token mới
  • JWT là chuỗi đã ký, chứa thông tin như mã người dùng và vai trò. Server kiểm tra chữ ký nên không cần tra CSDL ở mỗi request.
  • Access token ngắn hạn giảm thiệt hại nếu bị lộ; refresh token giúp người dùng không phải đăng nhập lại liên tục.
  • Mật khẩu được băm bằng bcrypt trong NestJS trước khi gọi thủ tục; CSDL chỉ lưu PasswordHash, không bao giờ lưu mật khẩu gốc.

2.2. Bảng Users và stored procedure

CREATE TABLE Users (
  UserId       INT IDENTITY(1,1) PRIMARY KEY,
  FullName     NVARCHAR(100) NOT NULL,
  Email        NVARCHAR(255) NOT NULL UNIQUE,
  PasswordHash NVARCHAR(255) NOT NULL,
  Role         NVARCHAR(20)  NOT NULL DEFAULT N'customer'
               CHECK (Role IN (N'customer', N'staff')),
  CreatedAt    DATETIME2 NOT NULL DEFAULT SYSDATETIME()
);
GO

CREATE OR ALTER PROCEDURE sp_User_Register
  @FullName NVARCHAR(100), @Email NVARCHAR(255), @PasswordHash NVARCHAR(255)
AS
BEGIN
  SET NOCOUNT ON;
  IF EXISTS (SELECT 1 FROM Users WHERE Email = @Email)
    THROW 50409, N'Email đã được sử dụng', 1;

  INSERT INTO Users (FullName, Email, PasswordHash)
  VALUES (@FullName, @Email, @PasswordHash);

  SELECT CAST(SCOPE_IDENTITY() AS INT) AS userId;
END;
GO

CREATE OR ALTER PROCEDURE sp_User_GetByEmail
  @Email NVARCHAR(255)
AS
BEGIN
  SET NOCOUNT ON;
  SELECT UserId, FullName, Email, PasswordHash, Role FROM Users WHERE Email = @Email;
END;
GO

Refresh token cũng nên được lưu (dạng băm) qua thủ tục, ví dụ sp_RefreshToken_Save và sp_RefreshToken_Revoke, để có thể thu hồi khi người dùng đăng xuất. Bổ sung bảng Users vào ERD và thêm khóa ngoại Orders.UserId.

2.3. Đăng nhập và Guard trong NestJS

Cài: npm install @nestjs/jwt bcrypt và npm install -D @types/bcrypt. Khóa bí mật JWT đặt trong .env của backend, không bao giờ đưa vào app.

// src/auth/auth.service.ts
async login(email: string, password: string) {
  const [user] = await this.db.execute<UserRow>('sp_User_GetByEmail', {
    Email: { type: sql.NVarChar(255), value: email },
  });
  if (!user || !(await bcrypt.compare(password, user.PasswordHash))) {
    throw new UnauthorizedException('Email hoặc mật khẩu không đúng');
  }
  const payload = { sub: user.UserId, role: user.Role };
  return {
    accessToken: await this.jwt.signAsync(payload, { expiresIn: '15m' }),
    refreshToken: await this.jwt.signAsync(payload, {
      secret: process.env.JWT_REFRESH_SECRET, expiresIn: '7d',
    }),
  };
}

async register(dto: RegisterDto) {
  const passwordHash = await bcrypt.hash(dto.password, 10);
  const [row] = await this.db.execute<{ userId: number }>('sp_User_Register', {
    FullName: { type: sql.NVarChar(100), value: dto.fullName },
    Email: { type: sql.NVarChar(255), value: dto.email },
    PasswordHash: { type: sql.NVarChar(255), value: passwordHash },
  });
  return row;
}
// src/auth/auth.guard.ts  (theo mẫu trong tài liệu NestJS)
@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private jwt: JwtService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();
    const [type, token] = request.headers.authorization?.split(' ') ?? [];
    if (type !== 'Bearer' || !token) throw new UnauthorizedException();
    try {
      request.user = await this.jwt.verifyAsync(token);
    } catch {
      throw new UnauthorizedException();
    }
    return true;
  }
}

// Dùng: chỉ người đã đăng nhập mới đặt hàng được
@UseGuards(AuthGuard)
@Post()
create(@Req() req, @Body() dto: CreateOrderDto) {
  return this.ordersService.create(req.user.sub, dto);
}

Phân quyền theo vai trò: tạo thêm RolesGuard đọc request.user.role; ví dụ chỉ staff được gọi PATCH /orders/:id/status. Mã người dùng lấy từ token (req.user.sub), không lấy từ body do app gửi lên.

2.4. Lưu token và bảo vệ màn hình trong app

Expo SecureStore lưu dữ liệu đã mã hóa bằng kho khóa của hệ điều hành (Android Keystore, iOS Keychain). AsyncStorage lưu dạng văn bản thường, chỉ dùng cho thiết lập không nhạy cảm như chế độ sáng/tối. Cài: npx expo install expo-secure-store.

// stores/auth.ts
import * as SecureStore from 'expo-secure-store';
import { create } from 'zustand';

type AuthState = {
  token: string | null;
  ready: boolean;
  signIn: (accessToken: string, refreshToken: string) => Promise<void>;
  signOut: () => Promise<void>;
  restore: () => Promise<void>;
};

export const useAuth = create<AuthState>((set) => ({
  token: null,
  ready: false,
  signIn: async (accessToken, refreshToken) => {
    await SecureStore.setItemAsync('accessToken', accessToken);
    await SecureStore.setItemAsync('refreshToken', refreshToken);
    set({ token: accessToken });
  },
  signOut: async () => {
    await SecureStore.deleteItemAsync('accessToken');
    await SecureStore.deleteItemAsync('refreshToken');
    set({ token: null });
  },
  restore: async () => {
    const token = await SecureStore.getItemAsync('accessToken');
    set({ token, ready: true });
  },
}));
// app/(tabs)/_layout.tsx: chưa đăng nhập thì chuyển sang màn hình đăng nhập
import { Redirect, Tabs } from 'expo-router';
import { useAuth } from '@/stores/auth';

export default function TabLayout() {
  const { token, ready } = useAuth();
  if (!ready) return null;                       // đang đọc token từ SecureStore
  if (!token) return <Redirect href="/login" />;
  return <Tabs>{/* các tab như bài 03 */}</Tabs>;
}

// lib/api.ts: tự gắn token vào mọi request
const token = useAuth.getState().token;
headers: { Authorization: token ? `Bearer ${token}` : '', ... }

Gọi useAuth.getState().restore() một lần khi app khởi động (trong app/_layout.tsx). Đăng nhập thành công thì dùng router.replace('/') để nút Back không quay về màn hình đăng nhập.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): Đăng nhập LHU Food

  1. Tạo bảng Users, các thủ tục ở mục 2.2; tạo tài khoản SQL Server riêng cho API, chỉ cấp quyền EXECUTE; đổi .env của API sang tài khoản này.
  2. Module auth trong NestJS: POST /auth/register, POST /auth/login; gắn AuthGuard cho POST /orders.
  3. App: màn hình Đăng nhập và Đăng ký (dùng form bài 04); store auth với SecureStore; restore() khi mở app.
  4. Bảo vệ nhóm (tabs) bằng Redirect; lib/api.ts tự gắn header Authorization.
  5. Nút Đăng xuất ở tab Tài khoản; kiểm tra: tắt app mở lại vẫn đăng nhập, đăng xuất rồi bấm Back không vào lại được.

✍️ Thực hành không hướng dẫn (1 tiết): Token hết hạn

Xử lý khi API trả về 401: app gọi POST /auth/refresh bằng refresh token, lưu token mới và gửi lại request ban đầu đúng một lần; nếu refresh cũng thất bại thì đăng xuất và về màn hình đăng nhập kèm thông báo "Phiên đăng nhập đã hết hạn".

Hoàn thành khi: đặt expiresIn của access token còn 1 phút để thử; sau 1 phút app vẫn hoạt động bình thường; xóa refresh token trong CSDL thì app tự về màn hình đăng nhập.

🆘 4. Góc trợ giúp và mở rộng ▼

API luôn trả 401: kiểm tra header có đúng dạng Bearer <token> (có dấu cách); khóa bí mật khi ký và khi kiểm tra phải giống nhau.

Màn hình nháy về trang đăng nhập rồi mới vào app: app chưa đọc xong token từ SecureStore đã kiểm tra; dùng cờ ready như mục 2.4.

Lỗi cài bcrypt trên Windows: bcrypt cần biên dịch mã native; nếu lỗi, dùng bcryptjs (cùng cách gọi hash/compare).

Kiến thức mở rộng: Tìm hiểu đăng nhập bằng vân tay/khuôn mặt với expo-local-authentication để mở khóa token đã lưu.
