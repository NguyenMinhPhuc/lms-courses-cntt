BÀI 04 - Quản lý trạng thái, danh sách & form (5 tiết: 1 LT / 4 TH)

Người dùng thêm một món vào giỏ ở màn hình Chi tiết, rồi chuyển sang tab Giỏ hàng. Làm sao để tab Giỏ hàng biết ngay có món mới? Và khi thực đơn có 500 món, làm sao để cuộn vẫn mượt?

Mục tiêu: Phân biệt được trạng thái cục bộ, trạng thái toàn cục và trạng thái từ server; hiển thị được danh sách lớn hiệu quả bằng FlatList; xây dựng được form có kiểm tra dữ liệu bằng React Hook Form và Zod.

Nội dung:

  • Ý chính 1 - Ba loại trạng thái: cục bộ (useState, useReducer), toàn cục dùng chung nhiều màn hình (Zustand), và dữ liệu từ server (bài 05).
  • Ý chính 2 - Danh sách hiệu quả: FlatList chỉ vẽ phần đang hiển thị; keyExtractor, danh sách rỗng, kéo để tải lại, nhiều cột.
  • Ý chính 3 - Form có kiểm tra dữ liệu: React Hook Form + Zod, thông báo lỗi tiếng Việt, bàn phím phù hợp và không che ô nhập.
  • Ý chính 4 - Vibe coding cho quy tắc nghiệp vụ: AI sinh schema Zod từ đặc tả; bạn tự viết các trường hợp biên để kiểm tra lại.

Kết quả cần đạt: Giỏ hàng LHU Food dùng chung giữa các màn hình; danh sách món dùng FlatList; form đăng ký kiểm tra đủ quy tắc; người phụ trách backend của nhóm đã khởi tạo NestJS kết nối SQL Server.

CLO liên quan: CLO1.

💡 Giỏ hàng toàn cục với Zustand:

// stores/cart.ts
import { create } from 'zustand';

type CartItem = { id: number; name: string; price: number; quantity: number };

type CartState = {
  items: CartItem[];
  add: (product: Omit<CartItem, 'quantity'>) => void;
  remove: (id: number) => void;
  total: () => number;
};

export const useCart = create<CartState>((set, get) => ({
  items: [],
  add: (product) =>
    set((state) => {
      const found = state.items.find((i) => i.id === product.id);
      return {
        items: found
          ? state.items.map((i) => (i.id === product.id ? { ...i, quantity: i.quantity + 1 } : i))
          : [...state.items, { ...product, quantity: 1 }],
      };
    }),
  remove: (id) => set((state) => ({ items: state.items.filter((i) => i.id !== id) })),
  total: () => get().items.reduce((sum, i) => sum + i.price * i.quantity, 0),
}));

// Ở bất kỳ màn hình nào
const items = useCart((state) => state.items);
const add = useCart((state) => state.add);

Mỗi màn hình chỉ "chọn" phần state mình cần (state => state.items), nên màn hình chỉ vẽ lại khi phần đó thay đổi.

2.2. Danh sách hiệu quả với FlatList

ScrollView vẽ tất cả phần tử ngay khi mở màn hình. Với 500 món, máy phải dựng 500 thẻ cùng lúc. FlatList chỉ vẽ những phần tử đang hiển thị (và một ít phía trước/sau), nên cuộn mượt và tốn ít bộ nhớ.

<FlatList
  data={products}
  keyExtractor={(item) => String(item.id)}
  renderItem={({ item }) => <ProductCard {...item} onAdd={() => add(item)} />}
  numColumns={2}
  columnWrapperStyle={{ gap: 16 }}
  contentContainerStyle={{ padding: 16, gap: 16 }}
  ListEmptyComponent={<Text>Chưa có món nào trong danh mục này.</Text>}
  refreshing={refreshing}
  onRefresh={reload}
/>
  • keyExtractor trả về khóa duy nhất và ổn định (mã món), không dùng chỉ số mảng.
  • ListEmptyComponent: luôn có trạng thái rỗng, đừng để màn hình trắng trơn.
  • refreshing + onRefresh: kéo xuống để tải lại (bài 05 nối với API thật).
  • SectionList: danh sách chia nhóm có tiêu đề, ví dụ món theo từng danh mục.

2.3. Form với React Hook Form + Zod

Zod mô tả quy tắc dữ liệu một lần (schema); React Hook Form quản lý giá trị, lỗi và việc gửi form. Cài: npx expo install react-hook-form zod @hookform/resolvers.

import { useForm, Controller } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const orderNoteSchema = z.object({
  phone: z.string().regex(/^0\d{9}$/, 'Số điện thoại gồm 10 chữ số, bắt đầu bằng 0'),
  note: z.string().max(200, 'Ghi chú tối đa 200 ký tự').optional(),
});
type OrderNote = z.infer<typeof orderNoteSchema>;

export function OrderNoteForm({ onSubmit }: { onSubmit: (data: OrderNote) => void }) {
  const { control, handleSubmit, formState: { errors } } = useForm<OrderNote>({
    resolver: zodResolver(orderNoteSchema),
  });

  return (
    <View>
      <Controller
        control={control}
        name="phone"
        render={({ field: { onChange, onBlur, value } }) => (
          <TextInput value={value} onChangeText={onChange} onBlur={onBlur}
            keyboardType="phone-pad" placeholder="Số điện thoại" />
        )}
      />
      {errors.phone && <Text style={{ color: 'red' }}>{errors.phone.message}</Text>}
      <Button title="Xác nhận" onPress={handleSubmit(onSubmit)} />
    </View>
  );
}
  • So khớp hai trường (mật khẩu và xác nhận mật khẩu): dùng .refine((d) => d.password === d.confirm, { message: 'Mật khẩu xác nhận không khớp', path: ['confirm'] }).
  • Bàn phím: chọn keyboardType đúng loại (email, số điện thoại); bọc form trong KeyboardAvoidingView để bàn phím không che ô đang nhập.
  • Kiểm tra ở app chưa đủ: API ở bài 05–06 vẫn phải kiểm tra lại, vì request có thể không đi từ app của bạn.

2.4. Vibe coding cho quy tắc nghiệp vụ

  1. Viết đặc tả bằng lời: "Họ tên 2–100 ký tự; email đúng định dạng; số điện thoại 10 chữ số bắt đầu bằng 0; mật khẩu tối thiểu 8 ký tự, có chữ và số; xác nhận mật khẩu phải khớp."
  2. Nhờ Copilot Chat sinh schema Zod với thông báo lỗi tiếng Việt.
  3. Tự viết bảng trường hợp biên rồi thử từng trường hợp: họ tên 1 ký tự và 2 ký tự; số điện thoại 9 và 10 chữ số; mật khẩu 7 và 8 ký tự; mật khẩu chỉ có chữ.
  4. Trường hợp nào AI viết sai, sửa schema và ghi vào PROMPTS.md.

Vì sao không tin ngay? AI hay viết biểu thức chính quy "gần đúng", ví dụ chấp nhận số điện thoại 11 chữ số hoặc quên chặn khoảng trắng. Kỹ thuật kiểm tra giá trị biên bạn đã học ở môn Kiểm thử phần mềm dùng được ngay ở đây.

🧑‍🏫 Thực hành có hướng dẫn (2 tiết): Giỏ hàng & thực đơn LHU Food

  1. Cài Zustand: npx expo install zustand; tạo stores/cart.ts theo mục 2.1.
  2. Nút "Thêm vào giỏ" ở Chi tiết món gọi add(); tab Giỏ hàng hiển thị danh sách và tổng tiền; nút xóa từng món.

Xây form Đăng ký tài khoản với các trường họ tên, email, số điện thoại, mật khẩu, xác nhận mật khẩu theo đặc tả ở mục 2.4.

Hoàn thành khi: mọi quy tắc báo lỗi tiếng Việt ngay dưới ô nhập; nút Đăng ký chỉ gửi khi form hợp lệ; bàn phím đúng loại cho từng ô và không che ô đang nhập; nộp kèm bảng trường hợp biên đã thử (đạt/không đạt).

🆘 4. Góc trợ giúp và mở rộng ▼

Cảnh báo "VirtualizedLists should never be nested inside plain ScrollViews": bạn đặt FlatList bên trong ScrollView. Bỏ ScrollView, đưa phần đầu trang vào ListHeaderComponent của FlatList.

Giỏ hàng không cập nhật: kiểm tra hàm cập nhật trả về mảng mới (map, filter, spread), không sửa trực tiếp mảng cũ bằng push.

Form không báo lỗi: kiểm tra đã truyền resolver: zodResolver(schema) và tên trường trong Controller name khớp với schema.

Kiến thức mở rộng: Tìm hiểu middleware persist của Zustand để giữ giỏ hàng khi tắt app (bài 07 sẽ dùng).

Tự đánh giá: Nếu xóa store Zustand và chuyển giỏ hàng về useState trong màn hình Chi tiết, tab Giỏ hàng sẽ gặp vấn đề gì?
