BÀI 05 - Thiết kế CSDL, stored procedure, API NestJS & kết nối ứng dụng (5 tiết: 2 LT / 3 TH)

Đến giờ LHU Food vẫn dùng dữ liệu giả trong một file TypeScript. Hôm nay dữ liệu chuyển về đúng chỗ của nó: SQL Server. Câu hỏi là: đi từ màn hình điện thoại tới một dòng trong bảng Products phải qua những lớp nào, và lớp nào được phép làm gì?

Mục tiêu: Thiết kế được CSDL SQL Server đáp ứng đặc tả và trình bày bằng ERD; viết được stored procedure cho các thao tác dữ liệu; xây dựng được REST API NestJS chỉ truy cập CSDL qua stored procedure; tích hợp và quản lý được dữ liệu server trong ứng dụng.

Nội dung:

  • Ý chính 1 - Thiết kế CSDL: khóa chính/ngoại, quan hệ 1-n và n-n, ràng buộc cơ bản; hoàn thiện ERD từ bản sơ bộ ở bài 03.
  • Ý chính 2 - Stored procedure: quy ước đặt tên, tham số, phân trang OFFSET/FETCH, báo lỗi bằng THROW; vì sao học phần bắt buộc dùng thủ tục.
  • Ý chính 3 - API NestJS với mssql: module, controller, service, DTO; DatabaseService dùng chung để gọi request.execute().
  • Ý chính 4 - Kết nối ứng dụng: lớp api tập trung, địa chỉ API cho emulator và máy thật, TanStack Query (useQuery, useMutation, cuộn vô hạn).

Kết quả cần đạt: LHU Food hiển thị thực đơn và đặt hàng qua API thật; nhóm có ERD hoàn chỉnh, danh mục stored procedure và API có Swagger.

CLO liên quan: CLO1, CLO2, CLO3.

📚 2. Học liệu chính ▼

2.1. Kiến trúc: dữ liệu đi qua những lớp nào?

Ứng dụng (React Native)
   │  HTTP + JSON   (useQuery / useMutation)
   ▼
API NestJS: Controller → Service → DatabaseService
   │  mssql: request.input(...) + request.execute('sp_...')
   ▼
SQL Server: Stored procedure → Bảng
  • App không bao giờ kết nối thẳng vào SQL Server; app chỉ gọi API.
  • API không viết câu SQL; API chỉ gọi stored procedure có tham số.
  • Stored procedure chứa toàn bộ câu lệnh đọc/ghi dữ liệu.

2.2. Hoàn thiện thiết kế CSDL

Từ ERD sơ bộ ở bài 03, bổ sung kiểu dữ liệu, khóa và ràng buộc. Dùng NVARCHAR cho chuỗi tiếng Việt, DECIMAL cho tiền.

CREATE TABLE Categories (
  CategoryId INT IDENTITY(1,1) PRIMARY KEY,
  Name       NVARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE Products (
  ProductId   INT IDENTITY(1,1) PRIMARY KEY,
  CategoryId  INT NOT NULL REFERENCES Categories(CategoryId),
  Name        NVARCHAR(150) NOT NULL,
  Price       DECIMAL(12,0) NOT NULL CHECK (Price >= 0),
  ImageUrl    NVARCHAR(500) NULL,
  IsAvailable BIT NOT NULL DEFAULT 1
);

CREATE TABLE Orders (
  OrderId   INT IDENTITY(1,1) PRIMARY KEY,
  UserId    INT NOT NULL,          -- khóa ngoại tới Users (bài 06)
  Status    NVARCHAR(20) NOT NULL DEFAULT N'pending',
  Note      NVARCHAR(200) NULL,
  CreatedAt DATETIME2 NOT NULL DEFAULT SYSDATETIME()
);

CREATE TABLE OrderItems (
  OrderId   INT NOT NULL REFERENCES Orders(OrderId),
  ProductId INT NOT NULL REFERENCES Products(ProductId),
  Quantity  INT NOT NULL CHECK (Quantity > 0),
  UnitPrice DECIMAL(12,0) NOT NULL,
  PRIMARY KEY (OrderId, ProductId)
);

💡 Vì sao lưu UnitPrice trong OrderItems? Giá món có thể đổi sau này; đơn hàng cũ phải giữ đúng giá tại thời điểm đặt. Vẽ lại ERD hoàn chỉnh bằng dbdiagram.io hoặc draw.io và lưu vào docs/.

2.3. Stored procedure: quy ước và ví dụ

Vì sao học phần bắt buộc dùng stored procedure?

  • Tách logic dữ liệu khỏi mã nguồn backend; đổi câu truy vấn không cần build lại API.
  • Phân quyền chặt: tài khoản SQL Server của API chỉ cần quyền EXECUTE, không đọc/ghi bảng trực tiếp (bài 06).
  • Chống SQL injection: giá trị luôn đi vào tham số có kiểu, không ghép chuỗi.

Quy ước đặt tên: sp_<Thực thể>_<Hành động>, ví dụ sp_Product_GetList, sp_Product_GetById, sp_Order_Create, sp_Order_GetHistory.

CREATE OR ALTER PROCEDURE sp_Product_GetList
  @CategoryId INT = NULL,
  @Page       INT = 1,
  @PageSize   INT = 20
AS
BEGIN
  SET NOCOUNT ON;
  SELECT ProductId AS id, CategoryId AS categoryId, Name AS name,
         Price AS price, ImageUrl AS imageUrl
  FROM Products
  WHERE IsAvailable = 1
    AND (@CategoryId IS NULL OR CategoryId = @CategoryId)
  ORDER BY ProductId
  OFFSET (@Page - 1) * @PageSize ROWS FETCH NEXT @PageSize ROWS ONLY;
END;
GO

CREATE OR ALTER PROCEDURE sp_Product_GetById
  @ProductId INT
AS
BEGIN
  SET NOCOUNT ON;
  IF NOT EXISTS (SELECT 1 FROM Products WHERE ProductId = @ProductId)
    THROW 50404, N'Không tìm thấy món ăn', 1;

  SELECT ProductId AS id, CategoryId AS categoryId, Name AS name,
         Price AS price, ImageUrl AS imageUrl, IsAvailable AS isAvailable
  FROM Products WHERE ProductId = @ProductId;
END;
GO

Bí danh camelCase (ProductId AS id): thủ tục trả dữ liệu cho app đặt tên cột theo quy ước JSON, để API trả thẳng kết quả mà app dùng được ngay, không cần viết mã chuyển đổi.

Mã lỗi tự đặt (từ 50000 trở lên) giúp backend biết lỗi gì để trả mã HTTP phù hợp: ví dụ 50404 → 404 Not Found. Viết xong thủ tục nào, chạy thử ngay trong SSMS bằng EXEC sp_Product_GetList @Page = 1;.

2.4. API NestJS gọi stored procedure bằng mssql

Cài thư viện: npm install mssql. Tạo một DatabaseService dùng chung giữ connection pool và chỉ có một cách gọi CSDL: chạy thủ tục với tham số có kiểu.

// src/database/database.service.ts
import { Injectable, OnModuleDestroy, OnModuleInit } from '@nestjs/common';
import * as sql from 'mssql';

type Param = { type: sql.ISqlType | (() => sql.ISqlType); value: unknown };

@Injectable()
export class DatabaseService implements OnModuleInit, OnModuleDestroy {
  private pool!: sql.ConnectionPool;

  async onModuleInit() {
    this.pool = await new sql.ConnectionPool({
      server: process.env.DB_SERVER!,
      database: process.env.DB_NAME!,
      user: process.env.DB_USER!,
      password: process.env.DB_PASSWORD!,
      options: { encrypt: false, trustServerCertificate: true },
    }).connect();
  }

  async onModuleDestroy() {
    await this.pool?.close();
  }

  async execute<T>(procedure: string, params: Record<string, Param> = {}): Promise<T[]> {
    const request = this.pool.request();
    for (const [name, p] of Object.entries(params)) {
      request.input(name, p.type, p.value);
    }
    const result = await request.execute<T>(procedure);
    return result.recordset;
  }
}
// src/products/products.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';
import * as sql from 'mssql';
import { DatabaseService } from '../database/database.service';

@Injectable()
export class ProductsService {
  constructor(private readonly db: DatabaseService) {}

  findAll(page = 1, categoryId?: number) {
    return this.db.execute('sp_Product_GetList', {
      CategoryId: { type: sql.Int, value: categoryId ?? null },
      Page: { type: sql.Int, value: page },
      PageSize: { type: sql.Int, value: 20 },
    });
  }

  async findOne(id: number) {
    try {
      const [product] = await this.db.execute('sp_Product_GetById', {
        ProductId: { type: sql.Int, value: id },
      });
      return product;
    } catch (err: any) {
      if (err.number === 50404) throw new NotFoundException(err.message);
      throw err;
    }
  }
}
  • Controller nhận request (@Get(), @Get(':id'), @Post()), kiểm tra dữ liệu bằng DTO + ValidationPipe, gọi service.
  • Swagger (@nestjs/swagger) sinh tài liệu API tại /api, để người làm mobile biết endpoint và dữ liệu trả về.
  • Vibe coding: đưa ERD cho Antigravity sinh thủ tục và service; review từng thủ tục (đủ tham số, có SET NOCOUNT ON, có kiểm tra tồn tại) và tìm trong mã backend chuỗi SELECT/INSERT để chắc chắn AI không viết SQL trực tiếp.

2.5. Kết nối ứng dụng với API

Địa chỉ API: khai báo trong file .env của dự án Expo: EXPO_PUBLIC_API_URL=http://192.168.1.10:3000. Biến có tiền tố EXPO_PUBLIC_ được đưa vào ứng dụng, nên không bao giờ đặt mật khẩu hay khóa bí mật vào đây.

  • Điện thoại thật: dùng IP LAN của máy chạy API (ipconfig), không dùng localhost vì localhost trên điện thoại là chính điện thoại.
  • Android emulator: dùng 10.0.2.2 để trỏ về máy tính đang chạy emulator.
  • Tường lửa Windows có thể chặn cổng 3000; nếu điện thoại không gọi được, kiểm tra cổng đã được mở.
// lib/api.ts
const API_URL = process.env.EXPO_PUBLIC_API_URL;

export async function api<T>(path: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`${API_URL}${path}`, {
    ...init,
    headers: { 'Content-Type': 'application/json', ...init?.headers },
  });
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new Error(body.message ?? `Lỗi ${res.status}`);
  }
  return res.json();
}

TanStack Query lo phần khó: đang tải, lỗi, cache, tải lại. Bọc ứng dụng trong QueryClientProvider ở app/_layout.tsx, sau đó:

// Đọc dữ liệu
const { data, isLoading, isError, refetch, isRefetching } = useQuery({
  queryKey: ['products'],
  queryFn: () => api<Product[]>('/products'),
});

// Ghi dữ liệu, xong thì làm mới danh sách đơn hàng
const queryClient = useQueryClient();
const createOrder = useMutation({
  mutationFn: (body: NewOrder) =>
    api('/orders', { method: 'POST', body: JSON.stringify(body) }),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['orders'] }),
});

// Cuộn vô hạn cho lịch sử đơn hàng
const orders = useInfiniteQuery({
  queryKey: ['orders'],
  initialPageParam: 1,
  queryFn: ({ pageParam }) => api<Order[]>(`/orders?page=${pageParam}`),
  getNextPageParam: (lastPage, pages) => (lastPage.length < 20 ? undefined : pages.length + 1),
});
// <FlatList data={orders.data?.pages.flat()} onEndReached={() => orders.hasNextPage && orders.fetchNextPage()} />

Luôn xử lý đủ 4 trạng thái trên màn hình: đang tải, lỗi (kèm nút thử lại), rỗng, có dữ liệu.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): API LHU Food

  1. Chạy script tạo bảng (mục 2.2) và dữ liệu mẫu trong SSMS; vẽ ERD hoàn chỉnh.
  2. Viết sp_Product_GetList, sp_Product_GetById, sp_Category_GetList, sp_Order_Create (bản đơn giản, chưa có giao dịch); chạy thử từng thủ tục bằng EXEC.
  3. Tạo DatabaseService, module products và orders trong NestJS; bật Swagger; thử API bằng Swagger.
  4. Trong app: tạo lib/api.ts, bọc QueryClientProvider, thay dữ liệu giả ở Trang chủ và Chi tiết món bằng useQuery.
  5. Nút "Xác nhận đặt hàng" gọi useMutation; đặt xong xóa giỏ hàng và chuyển sang tab Đơn hàng.

✍️ Thực hành không hướng dẫn (1 tiết): Lịch sử đơn hàng

Viết thủ tục sp_Order_GetHistory (tham số @UserId, @Page, @PageSize, sắp xếp mới nhất trước), endpoint GET /orders?page= và màn hình Lịch sử đơn hàng cuộn vô hạn.

Hoàn thành khi: mã backend không có câu SQL trực tiếp; cuộn tới cuối tự tải trang tiếp và dừng khi hết dữ liệu; có đủ trạng thái đang tải, lỗi kèm nút thử lại, rỗng.

🆘 4. Góc trợ giúp và mở rộng ▼

App báo "Network request failed": đang dùng localhost trên điện thoại; hoặc điện thoại và máy tính khác mạng; hoặc tường lửa chặn cổng API. Thử mở http://<IP>:3000/api bằng trình duyệt trên điện thoại trước.

API không kết nối được SQL Server: kiểm tra SQL Server đã bật TCP/IP và đăng nhập bằng SQL Server Authentication; tên server, cổng và mật khẩu trong .env đúng.

Lỗi "Could not find stored procedure": thủ tục chưa được tạo trong đúng CSDL, hoặc tên gọi trong execute() sai chính tả.

Kiến thức mở rộng: Tìm hiểu tham số OUTPUT của stored procedure và cách đọc bằng request.output() trong mssql.

Tự đánh giá: Nếu đổi tên cột Price thành UnitPrice trong bảng Products, bạn phải sửa những file nào? Câu trả lời đúng nên là: các stored procedure liên quan, không phải mã NestJS.
