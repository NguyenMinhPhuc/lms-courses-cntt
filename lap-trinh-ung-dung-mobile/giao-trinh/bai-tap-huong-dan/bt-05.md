## Bài tập hướng dẫn theo dự án LHU Food

**Nhiệm vụ:** dựng CSDL SQL Server và backend NestJS của LHU Food cho module Thực đơn và Đơn hàng (bản đầu), chỉ truy cập dữ liệu qua stored procedure; thay dữ liệu giả trong ứng dụng bằng API thật, thêm lịch sử đơn hàng.

- **Tài liệu dùng kèm:** SRS mục 5.3 (M02), 5.5 (F04.1, F04.2), mục 7 (bảng, script), mục 8 (danh mục API).
- **User story:** US-G01, US-G03, US-G07, US-C04 (bản đầu, chưa có giao dịch), US-C06.
- **Thời lượng gợi ý:** 2,5 tiết trên lớp, hoàn thiện ở nhà.

### Chuẩn bị môi trường

1. Cài SQL Server (bản Developer hoặc Express) và SQL Server Management Studio (SSMS); bật kết nối TCP/IP và đăng nhập bằng SQL Server Authentication.
2. Tạo CSDL và login cho API (mục 6.6.1 sẽ giới hạn quyền; giai đoạn này có thể dùng login riêng có quyền trên CSDL `LhuFood`):

```sql
CREATE DATABASE LhuFood;
```

3. Tạo dự án backend:

```bash
npx @nestjs/cli new lhu-food-api
cd lhu-food-api
npm install mssql @nestjs/config @nestjs/swagger class-validator class-transformer
npm install -D @types/mssql
```

4. Trong dự án ứng dụng: `npx expo install @tanstack/react-query`; file `.env` có `EXPO_PUBLIC_API_URL=http://<IP-máy-bạn>:3000` (không dùng `localhost` khi chạy trên điện thoại).

### Các bước triển khai

**Bước 1. Script CSDL.** `database/01-tables.sql` theo mục 5.2.2 (đối chiếu SRS mục 7.1); `database/99-seed.sql` với 3 danh mục và 10 món thật của căn tin.

**Bước 2. Stored procedure.** `database/02-procedures.sql`: `sp_Category_GetList`, `sp_Product_GetList` (phân trang, lọc danh mục), `sp_Product_GetById` (50404), `sp_Order_Create` (bản đầu), `sp_Order_GetHistory`. Chạy thử từng thủ tục trong SSMS (mục 5.3.5), kể cả trường hợp lỗi.

**Bước 3. DatabaseService** (mục 5.4.2): một hàm `execute(procedure, params)` duy nhất; chuyển mã 50400/50404/50409 thành HTTP 400/404/409.

**Bước 4. Module Products, Categories, Orders** (mục 5.4.3, 5.4.4): controller, service, DTO; bật Swagger ở `/docs`; `app.listen(port, '0.0.0.0')`.

**Bước 5. Kiểm tra API bằng Swagger** đủ các dòng của SRS mục 8 thuộc phạm vi chương: `GET /categories`, `GET /products`, `GET /products/:id`, `POST /orders`, `GET /orders`. Giai đoạn này `userId` của đơn lấy tạm từ body; Chương 6 thay bằng token (BR-06).

**Bước 6. Nối ứng dụng.** `lib/api.ts` (mục 5.5.2), `QueryClientProvider` ở `app/_layout.tsx`, hook `useProducts`, màn hình Trang chủ xử lý đủ bốn trạng thái: đang tải, lỗi (nút Thử lại), rỗng, có dữ liệu (mục 5.5.4); kéo xuống để tải lại (US-G07); cuộn vô hạn (mục 5.5.6).

**Bước 7. Đặt món và lịch sử.** Nút Đặt món ở Giỏ hàng gọi `useMutation` (mục 5.5.5), thành công thì xóa giỏ; tab Đơn hàng hiển thị lịch sử từ `GET /orders?page=`.

**Bước 8. Cập nhật ERD hoàn chỉnh** (mục 5.2.3) và danh mục stored procedure dạng bảng trong `docs/`.

### Vibe coding

Cung cấp cho AI `database/01-tables.sql`, quy ước thủ tục (mục 5.3.2) và mô tả chức năng trong SRS:

```text
Đọc AGENTS.md. Dựa trên bảng trong database/01-tables.sql và đặc tả F04.2 trong SRS:
<dán F04.2>
Viết stored procedure sp_Order_GetHistory cho SQL Server: tham số @UserId INT, @Page INT, @PageSize INT;
SET NOCOUNT ON; trả orderId, createdAt, status, total (tổng UnitPrice*Quantity), itemCount;
mới nhất trước; phân trang OFFSET/FETCH; bí danh cột camelCase; THROW 50400 khi @Page < 1.
```

Prompt tiếp theo:

```text
Viết OrdersController và OrdersService NestJS cho GET /orders?page=, gọi
this.db.execute('sp_Order_GetHistory', {...}) của DatabaseService có sẵn (đính kèm).
Không dùng TypeORM, Prisma hay câu SQL viết trực tiếp. Thêm decorator Swagger.
```

Kiểm tra kết quả AI:

- Có câu `SELECT`, `INSERT` hay ghép chuỗi SQL trong mã TypeScript không? Bắt buộc loại bỏ (ràng buộc kiến trúc SRS mục 2.3).
- AI có tự thêm ORM vào `package.json` không?
- Tham số có kiểu (`sql.Int`, `sql.NVarChar(...)`) đầy đủ chưa?
- Thủ tục trả cột camelCase đúng như ứng dụng đang đọc?
- Chạy thủ tục trong SSMS với dữ liệu biên (trang vượt quá số đơn, người dùng chưa có đơn) trước khi nối API.

### Kiểm tra và hoàn thành

- ☐ Dựng lại CSDL từ `database/` trên một CSDL trống không lỗi.
- ☐ Mọi endpoint trong phạm vi chạy được trên Swagger; lỗi trả đúng mã 400/404/409.
- ☐ Ứng dụng không còn dữ liệu giả; mất mạng thì hiện thông báo và nút Thử lại.
- ☐ Đặt món tạo đơn trong SQL Server; lịch sử đơn cuộn vô hạn.
- ☐ ERD hoàn chỉnh và danh mục thủ tục có trong `docs/`.
