## Bài tập hướng dẫn theo dự án LHU Food

**Nhiệm vụ:** triển khai backend và CSDL của LHU Food lên Windows Server của Khoa, build APK kết nối server, cài trên điện thoại của người ngoài nhóm để chạy luồng chính, phát hành bản cập nhật OTA; viết README triển khai và hồ sơ cửa hàng.

- **Tài liệu dùng kèm:** SRS mục 5.13 (M12), mục 7.3 (script CSDL), mục 9 (NFR-01, NFR-05, NFR-09, NFR-10).
- **User story:** US-SYS04, US-SYS05; kiểm thử chấp nhận toàn bộ story Must trên bản APK.
- **Thời lượng gợi ý:** 3 tiết trên lớp (phối hợp bộ phận hỗ trợ triển khai).

### Chuẩn bị môi trường

- Thông tin server theo bảng mục 11.1.2 (địa chỉ, cách truy cập, instance SQL Server, cổng được cấp).
- Trên máy cá nhân:

```bash
npm install -g eas-cli
eas login
cd lhu-food && git checkout main && git pull && git checkout -b release/1.0.0
npx expo install expo-updates
```

- Trên server: Node.js bản LTS cùng phiên bản chính với máy phát triển, Git, SQL Server Management Studio hoặc `sqlcmd`.

### Các bước triển khai

**Bước 1. Danh sách kiểm tra trước khi triển khai.** Mọi test xanh (Chương 10); `database/` dựng được CSDL trống; `.env.example` liệt kê đủ biến; không còn địa chỉ `192.168...` viết cứng trong mã.

**Bước 2. CSDL trên server** (mục 11.2): chạy script theo thứ tự số bằng vòng lặp `sqlcmd`; tạo login `EXECUTE`; kiểm tra quyền (SELECT bị từ chối, EXEC chạy được).

**Bước 3. Backend** (mục 11.3): `npm ci`, `npm run build`, `.env` của server với `JWT_SECRET` mới; thêm `/health` (`database/09-health.sql`); chạy thành dịch vụ nền theo hướng dẫn của bộ phận hỗ trợ; mở cổng; kiểm tra 4 bước ở mục 11.3.4.

**Bước 4. Cấu hình ứng dụng** (mục 11.4): `app.config.ts` (tên, package `vn.edu.lhu.<tên-nhóm>`, icon, splash, Google Maps API key qua biến môi trường), `eas.json` profile `preview` trỏ về server Khoa; xử lý kết nối HTTP theo mục 11.4.3.

**Bước 5. Build APK** (mục 11.5): `npx expo-doctor`, rồi `eas build -p android --profile preview`; cài từ mã QR.

**Bước 6. Kiểm thử chấp nhận trên APK.** Đi lần lượt tiêu chí của mọi story Must (SRS mục 4.7) trên điện thoại của **người không thuộc nhóm**, dùng 4G nếu server cho phép; ghi kết quả từng tiêu chí (Đạt / Không đạt / Ghi chú) vào `docs/acceptance-test.md`.

**Bước 7. EAS Update** (mục 11.6): sửa một lỗi giao diện tìm được ở bước 6, gửi `eas update --channel preview`, xác nhận APK đã cài nhận được.

**Bước 8. README và hồ sơ.** README backend có mục "Triển khai trên Windows Server" (mục 11.9); thư mục `store-listing/` (mục 11.7).

### Vibe coding

Ở bước này AI hữu ích cho **cấu hình và tài liệu**, nhưng mọi lệnh chạy trên server phải được bạn hiểu trước khi chạy.

```text
Đọc AGENTS.md và cấu trúc thư mục backend (đính kèm). Viết mục README "Triển khai trên Windows Server"
cho LHU Food API gồm: yêu cầu hệ thống, thứ tự chạy script trong database/ bằng sqlcmd,
tạo login chỉ có quyền EXECUTE, danh sách biến môi trường (KHÔNG ghi giá trị thật),
lệnh build, cách kiểm tra /health, cách cập nhật phiên bản. Phần chạy dịch vụ nền để mục
"theo hướng dẫn của bộ phận hỗ trợ Khoa" và chừa chỗ ghi tên dịch vụ.
```

Prompt tiếp theo:

```text
Chuyển app.json hiện tại (đính kèm) thành app.config.ts: giữ nguyên quyền và plugin;
android.package = 'vn.edu.lhu.lhufood', versionCode 1; googleMaps apiKey đọc từ process.env.GOOGLE_MAPS_API_KEY.
Viết eas.json có profile development, preview (APK, channel preview, EXPO_PUBLIC_API_URL của server Khoa),
production (app-bundle, channel production).
```

Kiểm tra kết quả AI:

- README có lộ mật khẩu, `JWT_SECRET`, địa chỉ nội bộ không được phép công khai không?
- `app.config.ts` có làm mất quyền hoặc plugin đã khai báo trong `app.json` không? So sánh từng dòng.
- Lệnh PowerShell do AI sinh có xóa hay ghi đè dữ liệu (`DROP DATABASE`, `Remove-Item`) không? Không chạy lệnh mình chưa hiểu trên server Khoa.
- Đối chiếu tên trường `eas.json` với tài liệu Expo (mục 11.5.2).

- ☐ Một bản EAS Update đã được nhận trên APK.
