## Bài tập hướng dẫn theo dự án LHU Food

**Nhiệm vụ:** tích hợp tính năng thiết bị vào LHU Food: đổi ảnh đại diện bằng camera hoặc thư viện ảnh (tải lên API, lưu đường dẫn qua stored procedure), bản đồ các quầy căn tin, quầy gần vị trí hiện tại; mở rộng chọn quầy nhận khi đặt món.

- **Tài liệu dùng kèm:** SRS mục 5.7 (M06), 5.8 (F07.2, F07.4), mục 6 (BR-12, BR-13), mục 3.2.6 (dịch vụ bản đồ).
- **User story:** US-C12, US-G06; mở rộng US-C15, US-C05, US-C17.
- **Thời lượng gợi ý:** 2,5 tiết trên lớp.

### Chuẩn bị môi trường

```bash
cd lhu-food && git checkout main && git pull && git checkout -b feature/device
npx expo install expo-image-picker expo-location react-native-maps

cd ../lhu-food-api && git checkout -b feature/upload
npm install -D @types/multer
```

Khai báo quyền và chuỗi giải thích trong `app.json` (mục 8.1.3). Thử trên **điện thoại Android thật** (camera của emulator chỉ là ảnh giả). Bản đồ chạy được trong Expo Go; bản APK cần Google Maps API key ở Chương 11.

### Các bước triển khai

**Bước 1. Quyền đúng lúc.** Chỉ xin quyền camera khi người dùng bấm "Chụp ảnh", quyền vị trí khi bấm "Quầy gần tôi" (mục 8.1.2, BR-12). Bị từ chối thì hiện hướng dẫn mở Cài đặt, ứng dụng vẫn dùng được.

**Bước 2. Chọn và chụp ảnh** với hook `hooks/useAvatarPicker.ts` (mục 8.2.1): `allowsEditing`, `aspect: [1, 1]`, `quality: 0.6`.

**Bước 3. Tải ảnh lên** (mục 8.2.2): `FormData` + `fetch` trực tiếp, **không** đặt `Content-Type` thủ công; gắn `Authorization`.

**Bước 4. Backend nhận file** (mục 8.2.3, 8.2.4): `FileInterceptor` giới hạn loại và dung lượng file; lưu `uploads/avatars`; `database/06-avatar.sql` và `sp_User_UpdateAvatar`; `useStaticAssets` phục vụ file.

**Bước 5. Hiển thị ảnh** ở tab Tài khoản bằng `EXPO_PUBLIC_API_URL + avatarUrl`.

**Bước 6. Quầy và bản đồ** (mục 8.3): `database/07-counters.sql` với tọa độ thật của các quầy trong khuôn viên (lấy từ Google Maps), `GET /counters`, màn hình `app/map.tsx` có marker.

**Bước 7 (mở rộng). Quầy gần tôi và chọn quầy nhận.** Tính khoảng cách (mục 8.3.3), sắp xếp quầy; thêm cột `Orders.CounterId` bằng script mới và tham số `@CounterId` cho `sp_Order_Create`; Giỏ hàng có ô chọn quầy (SRS F06.3).

**Bước 8 (mở rộng). Đánh giá món kèm ảnh** theo SRS F07.4.

### Vibe coding

```text
Đọc AGENTS.md. Viết hook hooks/useAvatarPicker.ts cho Expo:
- Hai hàm pickFromLibrary() và takePhoto(); xin quyền bằng expo-image-picker NGAY TRƯỚC khi mở,
  bị từ chối thì trả về null và hiện Alert hướng dẫn mở Cài đặt.
- allowsEditing true, aspect [1,1], quality 0.6.
- Hàm uploadAvatar(uri) gửi FormData field "file" tới POST /users/me/avatar bằng fetch,
  gắn Authorization từ stores/auth.ts, KHÔNG đặt header Content-Type.
Không dùng thư viện ngoài expo-image-picker.
```

```text
Viết màn hình app/map.tsx dùng react-native-maps: tải quầy từ GET /counters bằng TanStack Query,
mỗi quầy một Marker có title; nút "Quầy gần tôi" xin quyền expo-location khi bấm,
lấy vị trí, tính khoảng cách haversine, đưa bản đồ tới quầy gần nhất.
```

Kiểm tra kết quả AI:

- AI hay đặt `'Content-Type': 'multipart/form-data'` thủ công: thiếu `boundary`, server không đọc được file. Xóa dòng đó.
- Quyền có bị xin ngay khi mở màn hình không? Chuyển vào sự kiện bấm nút.
- Backend có kiểm tra loại file và dung lượng không? Thử tải lên một file `.txt`.
- Tọa độ quầy có đúng thứ tự (vĩ độ, kinh độ) không? Marker nằm giữa biển là đảo ngược.
- Dùng API của thư viện đã cũ (ví dụ `MediaTypeOptions` của expo-image-picker)? Đối chiếu tài liệu phiên bản đang cài.

### Kiểm tra và hoàn thành

- ☐ Đổi ảnh đại diện bằng camera và thư viện trên Android thật; tắt mở lại vẫn thấy ảnh mới.
- ☐ CSDL chỉ lưu đường dẫn; file nằm trong `uploads/avatars`.
- ☐ Từ chối quyền không làm ứng dụng lỗi.
- ☐ Bản đồ hiển thị đủ quầy với tọa độ thật.
- ☐ Ghi trong `PROMPTS.md` lỗi API lỗi thời hoặc lỗi header mà AI đã sinh (nếu có).
