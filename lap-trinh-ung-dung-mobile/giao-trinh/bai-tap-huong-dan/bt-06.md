## Bài tập hướng dẫn theo dự án LHU Food

**Nhiệm vụ:** hoàn thiện module Xác thực (M01) ở cả API và ứng dụng: đăng ký, đăng nhập, giữ đăng nhập, đăng xuất, phân quyền khách hàng/nhân viên; lấy `userId` từ token cho mọi API đơn hàng; review bảo mật mã do AI sinh. Chuẩn bị Checkpoint Sprint 2.

- **Tài liệu dùng kèm:** SRS mục 5.2 (F01.1–F01.5), mục 4.7 (tiêu chí US-G04, G05, C13, C14, S01), mục 6 (BR-01 đến BR-06).
- **User story:** US-G04, US-G05, US-C13, US-C14, US-S01.
- **Thời lượng gợi ý:** 2 tiết trên lớp, hoàn thiện ở nhà.

### Chuẩn bị môi trường

```bash
# backend
cd lhu-food-api && git checkout -b feature/auth

# thêm JWT_SECRET vào .env (chuỗi ngẫu nhiên dài)

# ứng dụng
cd ../lhu-food && git checkout -b feature/auth
npx expo install expo-secure-store @react-native-async-storage/async-storage
```

### Các bước triển khai

**Bước 1. CSDL.** `database/03-auth.sql` theo mục 6.3.2: bảng `Users`, `RefreshTokens`, khóa ngoại `Orders.UserId`; thủ tục `sp_User_Register`, `sp_User_GetByEmail`, `sp_RefreshToken_Save`, `sp_RefreshToken_Use`, `sp_RefreshToken_Revoke`. Seed một tài khoản `customer` và một tài khoản `staff`.

**Bước 2. AuthService và AuthController** (mục 6.4.2): `POST /auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout`. Băm mật khẩu bằng bcrypt; thông báo lỗi đăng nhập chung (BR-03).

**Bước 3. Guard** (mục 6.4.3, 6.4.4): `AuthGuard` cho mọi API cần đăng nhập; `RolesGuard` + `@Roles(['staff'])`. Sửa `OrdersController`: `userId` lấy từ `req.user.sub`, bỏ trường `userId` khỏi DTO (BR-06).

**Bước 4. Ứng dụng.** `stores/auth.ts` (mục 6.5.2) lưu token bằng SecureStore; `lib/api.ts` gắn `Authorization` và tự làm mới token một lần khi gặp 401 (mục 6.5.3, 6.5.5); màn hình `app/login.tsx`; nối form đăng ký ở Chương 4 với API.

**Bước 5. Bảo vệ màn hình** (mục 6.5.4) và **giao diện theo vai trò**: tài khoản `staff` thấy tab "Đơn mới" (khung màn hình, hoàn thiện ở Chương 9) thay cho tab Giỏ hàng.

**Bước 6. Đăng xuất** ở tab Tài khoản: gọi `/auth/logout`, xóa token, xóa giỏ hàng (`useCart.getState().clear()`).

**Bước 7 (nâng cao). Khách vãng lai xem thực đơn.** Thay vì chặn toàn bộ `(tabs)`, chỉ chặn Giỏ hàng, Đơn hàng, Tài khoản; bấm "Thêm vào giỏ" khi chưa đăng nhập thì mở màn hình Đăng nhập, xong quay lại (SRS mục 3.2.1).

**Bước 8. Tài khoản SQL chỉ có quyền EXECUTE** (mục 6.6.1); kiểm tra API vẫn chạy.

**Bước 9. Checkpoint Sprint 2** (mục 6.7).

### Vibe coding

Xác thực là phần AI dễ sinh mã **chạy được nhưng không an toàn**. Đính kèm `database.service.ts`, đặc tả F01.2, F01.3 và bảng rủi ro mục 6.6:

```text
Đọc AGENTS.md. Viết AuthService NestJS theo đặc tả F01.2 và F01.3 (đính kèm):
- Dùng DatabaseService.execute với sp_User_GetByEmail, sp_RefreshToken_Save, sp_RefreshToken_Use.
- bcrypt.compare cho mật khẩu; access token 15 phút bằng @nestjs/jwt, secret đọc từ process.env.JWT_SECRET.
- Refresh token: chuỗi ngẫu nhiên crypto.randomBytes, chỉ lưu SHA-256 của nó vào CSDL.
- Sai email hoặc mật khẩu đều trả UnauthorizedException('Email hoặc mật khẩu không đúng').
- Không bao giờ trả PasswordHash về client.
```

Sau khi nhận mã, yêu cầu AI tự review rồi **tự bạn** kiểm tra lại từng dòng theo bảng mục 6.6:

```text
Review đoạn mã trên theo danh sách: khóa bí mật viết cứng, lấy userId từ body,
endpoint thiếu Guard, log dữ liệu nhạy cảm, trả PasswordHash, thông báo lỗi tiết lộ email.
Chỉ ra dòng cụ thể nếu vi phạm.
```

Kiểm tra kết quả AI:

- Tìm trong toàn repo: `secret:`, `'abc`, `console.log(token`, `PasswordHash` trong response.
- Gọi `PATCH /orders/:id/status` bằng token `customer`: phải nhận 403.
- Gọi `POST /orders` với `userId` của người khác trong body: đơn vẫn phải thuộc người đang đăng nhập.
- Ghi vào `PROMPTS.md` ít nhất một lỗi bảo mật AI đã sinh và cách bạn phát hiện.
