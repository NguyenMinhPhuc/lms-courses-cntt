BÀI 08 - Tính năng thiết bị: Camera, Ảnh, Vị trí & Bản đồ (5 tiết: 1 LT / 4 TH)

Đây là thứ web app làm không tốt nhưng ứng dụng di động làm rất tự nhiên: chụp ảnh, biết bạn đang ở đâu, chỉ đường tới quầy căn tin gần nhất. Nhưng điện thoại sẽ hỏi người dùng "Cho phép LHU Food truy cập camera?". Nếu họ bấm "Từ chối" thì sao?

Mục tiêu: Xin và xử lý được quyền truy cập thiết bị; tích hợp được camera, thư viện ảnh và vị trí; tải được ảnh lên API NestJS và lưu thông tin ảnh vào SQL Server qua stored procedure.

Nội dung:

  • Ý chính 1 - Quyền truy cập: mô hình xin quyền trên Android (và iOS ở phần mở rộng); xin đúng lúc, giải thích lý do, xử lý khi bị từ chối.
  • Ý chính 2 - Camera và ảnh: expo-image-picker chụp/chọn ảnh, nén ảnh; upload multipart/form-data lên NestJS; lưu đường dẫn ảnh qua thủ tục.
  • Ý chính 3 - Vị trí và bản đồ: expo-location lấy vị trí hiện tại; react-native-maps hiển thị điểm; tính khoảng cách.
  • Ý chính 4 - Expo Go và development build: khi nào thư viện native buộc phải dùng development build; cấu hình quyền trong app.json.

Kết quả cần đạt: LHU Food đổi được ảnh đại diện bằng camera/thư viện và lưu lên server; có bản đồ các quầy căn tin; nhóm tích hợp được ít nhất một tính năng thiết bị có ý nghĩa với đề tài.

CLO liên quan: CLO1.

📚 2. Học liệu chính ▼

2.1. Quyền truy cập (permission)

Camera, thư viện ảnh và vị trí là dữ liệu riêng tư. Hệ điều hành chỉ cho ứng dụng dùng khi người dùng đồng ý, và người dùng có thể thu hồi quyền bất cứ lúc nào trong Cài đặt.

  • Xin đúng lúc: chỉ hỏi khi người dùng bấm "Chụp ảnh", không hỏi tất cả quyền ngay lúc mở app.
  • Giải thích trước: một dòng "LHU Food cần camera để chụp ảnh đại diện" giúp người dùng dễ đồng ý hơn.
  • Xử lý từ chối: ứng dụng vẫn chạy bình thường; tính năng đó hiện hướng dẫn mở Cài đặt (Linking.openSettings()).
import * as ImagePicker from 'expo-image-picker';
import { Alert, Linking } from 'react-native';

async function ensureCameraPermission() {
  const { status, canAskAgain } = await ImagePicker.requestCameraPermissionsAsync();
  if (status === 'granted') return true;
  Alert.alert(
    'Chưa có quyền camera',
    canAskAgain ? 'Bạn cần cho phép camera để chụp ảnh.' : 'Hãy bật quyền camera trong Cài đặt.',
    canAskAgain ? undefined : [{ text: 'Mở Cài đặt', onPress: () => Linking.openSettings() }, { text: 'Để sau' }],
  );
  return false;
}

Khai báo lời giải thích quyền trong app.json qua cấu hình plugin của từng thư viện (ví dụ "cameraPermission" của expo-image-picker); lời này hiện trên iOS và được dùng khi build bản cài đặt.

2.2. Chụp/chọn ảnh và tải lên server

Cài: npx expo install expo-image-picker. Ảnh chụp từ điện thoại có thể vài MB; giảm quality và cho phép cắt ảnh vuông để file nhỏ, tải lên nhanh.

async function pickAvatar(fromCamera: boolean) {
  if (fromCamera && !(await ensureCameraPermission())) return;
  const options: ImagePicker.ImagePickerOptions = {
    mediaTypes: ['images'], allowsEditing: true, aspect: [1, 1], quality: 0.6,
  };
  const result = fromCamera
    ? await ImagePicker.launchCameraAsync(options)
    : await ImagePicker.launchImageLibraryAsync(options);
  if (result.canceled) return;
  await uploadAvatar(result.assets[0].uri);
}

async function uploadAvatar(uri: string) {
  const form = new FormData();
  form.append('file', { uri, name: 'avatar.jpg', type: 'image/jpeg' } as any);
  // Gọi fetch trực tiếp, KHÔNG đặt Content-Type: fetch tự thêm boundary cho multipart/form-data
  const res = await fetch(`${process.env.EXPO_PUBLIC_API_URL}/users/me/avatar`, {
    method: 'POST',
    body: form,
    headers: { Authorization: `Bearer ${useAuth.getState().token}` },
  });
  if (!res.ok) throw new Error('Tải ảnh lên thất bại');
}

Phía NestJS: dùng FileInterceptor (Multer) nhận file, giới hạn kích thước và loại file, lưu vào thư mục uploads/, rồi gọi thủ tục lưu đường dẫn.

@UseGuards(AuthGuard)
@Post('me/avatar')
@UseInterceptors(FileInterceptor('file', {
  storage: diskStorage({
    destination: './uploads/avatars',
    filename: (req: any, file, cb) => cb(null, `${req.user.sub}-${Date.now()}.jpg`),
  }),
  limits: { fileSize: 2 * 1024 * 1024 },                       // tối đa 2 MB
  fileFilter: (_req, file, cb) => cb(null, /^image\/(jpeg|png)$/.test(file.mimetype)),
}))
async uploadAvatar(@Req() req, @UploadedFile() file: Express.Multer.File) {
  if (!file) throw new BadRequestException('Chỉ nhận ảnh JPEG hoặc PNG');
  const url = `/uploads/avatars/${file.filename}`;
  await this.db.execute('sp_User_UpdateAvatar', {
    UserId: { type: sql.Int, value: req.user.sub },
    AvatarUrl: { type: sql.NVarChar(500), value: url },
  });
  return { avatarUrl: url };
}
  • Phục vụ file tĩnh: trong main.ts tạo app kiểu NestExpressApplication và gọi app.useStaticAssets('uploads', { prefix: '/uploads' }).
  • CSDL chỉ lưu đường dẫn ảnh (cột AvatarUrl NVARCHAR(500)), không lưu nội dung ảnh vào bảng.
  • Không tin tên file do app gửi lên; tự đặt tên theo mã người dùng và thời điểm.

2.3. Vị trí và bản đồ

Cài: npx expo install expo-location react-native-maps.

import * as Location from 'expo-location';
import MapView, { Marker } from 'react-native-maps';

const { status } = await Location.requestForegroundPermissionsAsync();
if (status === 'granted') {
  const pos = await Location.getCurrentPositionAsync({ accuracy: Location.Accuracy.Balanced });
  setMyLocation(pos.coords);            // { latitude, longitude, accuracy... }
}

<MapView style={{ flex: 1 }} showsUserLocation
  initialRegion={{ latitude: 10.9577, longitude: 106.8426, latitudeDelta: 0.01, longitudeDelta: 0.01 }}>
  {counters.map((c) => (
    <Marker key={c.id} coordinate={{ latitude: c.lat, longitude: c.lng }} title={c.name} />
  ))}
</MapView>
  • Chỉ xin quyền vị trí "khi dùng ứng dụng" (foreground); vị trí nền (background) cần lý do rõ ràng và quy trình duyệt khắt khe hơn trên cửa hàng.
  • Accuracy.Balanced đủ cho bản đồ khuôn viên và tiết kiệm pin hơn độ chính xác cao nhất.
  • Khoảng cách giữa hai tọa độ tính bằng công thức Haversine; dùng để sắp xếp "quầy gần bạn nhất".
  • Tọa độ trong ví dụ chỉ để minh họa; tọa độ thật của các quầy lấy từ bảng Counters qua API.
  • Bản cài đặt Android dùng bản đồ Google cần khai báo Google Maps API key trong app.json (android.config.googleMaps.apiKey); khi chạy thử bằng Expo Go thì chưa cần.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (2 tiết): Ảnh đại diện & bản đồ căn tin

  1. Thêm cột AvatarUrl vào Users, viết sp_User_UpdateAvatar; endpoint upload và phục vụ file tĩnh trong NestJS.
  2. Tab Tài khoản: bấm ảnh đại diện → chọn "Chụp ảnh" hoặc "Chọn từ thư viện" → cắt vuông → tải lên → hiển thị ảnh mới.
  3. Thử từ chối quyền camera rồi bấm lại: app hiện hướng dẫn mở Cài đặt, không bị treo.
  4. Tạo bảng Counters (tên, vĩ độ, kinh độ) và sp_Counter_GetList; màn hình Bản đồ hiện các quầy và vị trí người dùng.
  5. Sắp xếp danh sách quầy theo khoảng cách tới vị trí hiện tại.

✍️ Thực hành không hướng dẫn (1,5 tiết): Báo cáo sự cố

Chức năng "Báo cáo sự cố" (ví dụ: món ăn có vấn đề, bàn ăn hỏng): chụp ảnh, tự lấy vị trí hiện tại, nhập mô tả, gửi lên API; API lưu ảnh và gọi sp_Incident_Create lưu mô tả, tọa độ, đường dẫn ảnh, người gửi.

Hoàn thành khi: chạy được trên máy Android thật; từ chối quyền camera hoặc vị trí thì vẫn gửi được (bỏ trống phần tương ứng) và có thông báo rõ ràng; ảnh lớn hơn 2 MB bị API từ chối với thông báo dễ hiểu.

🆘 4. Góc trợ giúp và mở rộng ▼

Upload báo lỗi "Network request failed" hoặc API không nhận file: thường do tự đặt header Content-Type: multipart/form-data mà thiếu boundary. Để fetch tự đặt header; tên trường trong form.append('file', …) phải trùng với FileInterceptor('file').

Ảnh đại diện không hiện sau khi tải lên: đường dẫn trả về là đường dẫn tương đối; ghép với EXPO_PUBLIC_API_URL khi hiển thị, và kiểm tra đã bật phục vụ file tĩnh.

Emulator không có vị trí: trong Android Emulator mở Extended controls → Location để đặt tọa độ giả.

Kiến thức mở rộng: Tìm hiểu expo-image-manipulator để thu nhỏ ảnh trước khi gửi, và lưu ảnh lên dịch vụ lưu trữ đối tượng thay vì thư mục trên server.

Tự đánh giá: Ứng dụng của nhóm có màn hình nào vẫn hoạt động được khi người dùng từ chối mọi quyền không? Nếu không, đó là dấu hiệu cần thiết kế lại.
