BÀI 07 - Module quản trị trên backend của nhóm (5 tiết: 2 LT / 3 TH)

Hai sprint đầu, web của nhóm sống nhờ API mẫu của giảng viên. Từ hôm nay nhóm tự chịu trách nhiệm toàn bộ: CSDL, stored procedure, API và trang web. Backend của đồ án di động chưa biết "quản lý" là ai, chưa khóa được tài khoản, chưa xóa được danh mục. Việc đầu tiên không phải là viết code, mà là tìm ra backend còn thiếu những gì.

Mục tiêu: Phân tích được nghiệp vụ quản trị từ SRS thành thay đổi CSDL, stored procedure và API; viết được script CSDL phiên bản mới chạy lại an toàn; xây dựng được API quản trị có phân quyền admin và tài liệu Swagger; chuyển được web từ API mẫu sang backend của nhóm và kiểm thử hồi quy.

Nội dung:

  • Ý chính 1 - Phân tích nghiệp vụ quản trị: từ user story US-A01…A04 tới dữ liệu, thủ tục, API, trang; tìm khoảng trống của backend hiện tại.
  • Ý chính 2 - Stored procedure quản trị: CRUD có ràng buộc nghiệp vụ, mã lỗi 50400/50404/50409, script phiên bản mới.
  • Ý chính 3 - API quản trị: phân quyền admin, DTO, Swagger, khóa tài khoản.
  • Ý chính 4 - Chuyển web sang backend nhóm: so khớp hợp đồng API, lớp chuyển đổi, kiểm thử hồi quy Sprint 1–2.

Kết quả cần đạt: Backend nhóm có module quản trị danh mục, quầy và tài khoản (gọi stored procedure, phân quyền admin); web chạy trên backend nhóm, các test case Sprint 1–2 vẫn đạt.

CLO liên quan: CLO1.

2.1. Phân tích nghiệp vụ quản trị

Mỗi user story quản trị được lần theo năm tầng. Bảng này là phần "phân tích module quản trị" của báo cáo (CLO1) và là danh sách việc của Sprint 3.

Khoảng trống của backend hiện tại. Đối chiếu với CSDL đã xây trong học phần di động (Chương 5–7):

  • Cột Users.Role chỉ cho phép customer và staff: chưa có vai trò quản lý.
  • Chưa có cột khóa tài khoản; BR của US-A04 yêu cầu tài khoản bị khóa không đăng nhập và không làm mới token được.
  • Chưa có thủ tục thêm, sửa, xóa danh mục. Quy tắc: không xóa danh mục còn món (409); món đã có trong đơn chỉ được ngừng bán, không xóa hẳn (BR-16).
  • Bảng Counters do Chương 8 di động tạo (07-counters.sql) chưa có cột mô tả và trạng thái hoạt động.

2.2. Script CSDL và stored procedure quản trị

Thay đổi CSDL viết thành file mới, không sửa file mà các thành viên đã chạy. Giáo trình di động dùng các số 01–09, nên module quản trị của web dùng số từ 20 để không trùng: database/20-admin.sql. Mỗi lệnh đổi cấu trúc đều kiểm tra trước, chạy lại nhiều lần không lỗi.

-- database/20-admin.sql: vai trò admin, khóa tài khoản, quản trị danh mục
-- 1) Mở rộng ràng buộc vai trò (ràng buộc cũ không đặt tên nên tìm theo nội dung)
IF OBJECT_ID('dbo.CK_Users_Role') IS NULL
BEGIN
  DECLARE @ck SYSNAME = (SELECT TOP 1 name FROM sys.check_constraints
                         WHERE parent_object_id = OBJECT_ID('dbo.Users') AND definition LIKE '%customer%');
  IF @ck IS NOT NULL EXEC('ALTER TABLE dbo.Users DROP CONSTRAINT ' + QUOTENAME(@ck));
  ALTER TABLE dbo.Users ADD CONSTRAINT CK_Users_Role CHECK (Role IN (N'customer', N'staff', N'admin'));
END;
GO
-- 2) Khóa tài khoản
IF COL_LENGTH('dbo.Users', 'IsLocked') IS NULL
  ALTER TABLE dbo.Users ADD IsLocked BIT NOT NULL CONSTRAINT DF_Users_IsLocked DEFAULT 0;
GO

-- 3) Danh mục: thêm, sửa, xóa có ràng buộc
CREATE OR ALTER PROCEDURE dbo.sp_Category_Create @Name NVARCHAR(100)
AS
BEGIN
  SET NOCOUNT ON;
  IF LEN(LTRIM(RTRIM(@Name))) < 2 THROW 50400, N'Tên danh mục tối thiểu 2 ký tự', 1;
  IF EXISTS (SELECT 1 FROM dbo.Categories WHERE Name = @Name)
    THROW 50409, N'Tên danh mục đã tồn tại', 1;
  INSERT INTO dbo.Categories (Name)
  OUTPUT inserted.CategoryId AS id, inserted.Name AS name
  VALUES (@Name);
END;
GO

CREATE OR ALTER PROCEDURE dbo.sp_Category_Delete @CategoryId INT
AS
BEGIN
  SET NOCOUNT ON;
  IF NOT EXISTS (SELECT 1 FROM dbo.Categories WHERE CategoryId = @CategoryId)
    THROW 50404, N'Không tìm thấy danh mục', 1;
  IF EXISTS (SELECT 1 FROM dbo.Products WHERE CategoryId = @CategoryId)
    THROW 50409, N'Danh mục còn món, không xóa được', 1;
  DELETE FROM dbo.Categories WHERE CategoryId = @CategoryId;
END;
GO
-- sp_Category_Update: kiểm tra 50404 và trùng tên 50409 (trừ chính nó), OUTPUT dòng đã sửa

-- 4) Khóa / mở khóa tài khoản; không cho tự khóa chính mình
CREATE OR ALTER PROCEDURE dbo.sp_User_SetLocked @UserId INT, @IsLocked BIT, @ActorId INT
AS
BEGIN
  SET NOCOUNT ON;
  IF @UserId = @ActorId THROW 50400, N'Không thể tự khóa tài khoản của mình', 1;
  IF NOT EXISTS (SELECT 1 FROM dbo.Users WHERE UserId = @UserId)
    THROW 50404, N'Không tìm thấy tài khoản', 1;
  UPDATE dbo.Users SET IsLocked = @IsLocked
  OUTPUT inserted.UserId AS userId, inserted.FullName AS fullName, inserted.Role AS role, inserted.IsLocked AS isLocked
  WHERE UserId = @UserId;
  IF @IsLocked = 1                                                          -- thu hồi phiên đang mở
    UPDATE dbo.RefreshTokens SET RevokedAt = SYSDATETIME() WHERE UserId = @UserId AND RevokedAt IS NULL;
END;
GO
-- Tài khoản admin đầu tiên: tạo bằng script seed riêng (mật khẩu đã băm bcrypt), không tạo qua API
Mã lỗi trong thủ tụcHTTP (DatabaseService)Ví dụ trong module quản trị
50400400 Bad RequestTự khóa chính mình; tọa độ ngoài phạm vi
50404404 Not FoundSửa danh mục không tồn tại
50409409 ConflictTrùng tên danh mục; xóa danh mục còn món

Ràng buộc nghiệp vụ đặt trong thủ tục (và ràng buộc CSDL) nên web, ứng dụng di động hay Swagger gọi vào đều bị kiểm tra như nhau. Tên thủ tục và tham số theo quy ước sp_<Đối tượng>_<Hành động> của Chương 5 giáo trình di động.

2.3. API quản trị trên NestJS

Học phần khuyến khích dùng chung backend NestJS với đồ án di động. Nhóm dùng backend khác (Express, ASP.NET…) vẫn phải gọi stored procedure, phân quyền ở server và có Swagger.

// src/admin/dto/category.dto.ts
import { ApiProperty } from '@nestjs/swagger';
import { IsString, Length } from 'class-validator';

export class CategoryDto {
  @ApiProperty({ example: 'Đồ uống' })
  @IsString() @Length(2, 100)
  name!: string;
}

// src/admin/admin-categories.controller.ts
@ApiTags('Admin - Categories')
@ApiBearerAuth()
@Controller('admin/categories')
@UseGuards(AuthGuard, RolesGuard)
@Roles(['admin'])                                   // áp dụng cho mọi route của controller
export class AdminCategoriesController {
  constructor(private readonly db: DatabaseService) {}

  @Post()
  async create(@Body() dto: CategoryDto) {
    const [row] = await this.db.execute('sp_Category_Create', { Name: { type: sql.NVarChar(100), value: dto.name } });
    return row;
  }

  @Put(':id')
  async update(@Param('id', ParseIntPipe) id: number, @Body() dto: CategoryDto) {
    const [row] = await this.db.execute('sp_Category_Update', {
      CategoryId: { type: sql.Int, value: id }, Name: { type: sql.NVarChar(100), value: dto.name },
    });
    return row;
  }

  @Delete(':id') @HttpCode(204)
  async remove(@Param('id', ParseIntPipe) id: number) {
    await this.db.execute('sp_Category_Delete', { CategoryId: { type: sql.Int, value: id } });
  }
}
  • RolesGuard của giáo trình di động so khớp đúng tên vai trò, nên admin không tự có quyền của staff. Sửa các route nhân viên thành @Roles(['staff', 'admin']) theo ma trận phân quyền bài 05, hoặc cho guard coi admin bao gồm staff. Ghi quyết định này vào báo cáo.
  • Khóa tài khoản: sp_User_GetByEmail trả thêm IsLocked; AuthService.login trả 403 "Tài khoản đã bị khóa" khi IsLocked = 1; làm mới token cũng kiểm tra lại. Nếu @Roles đặt trên controller, đọc bằng reflector.getAllAndOverride(Roles, [context.getHandler(), context.getClass()]).
  • Mã người quản lý (@ActorId) lấy từ token (req.user.sub), không lấy từ body.
  • Swagger (/api) là hợp đồng giữa người làm backend, người làm web và người làm mobile: mỗi route có ví dụ body và mã lỗi.

2.4. Chuyển web sang backend của nhóm

Đổi API_URL trong .env.local là bước cuối cùng, không phải bước đầu. Trước đó, so khớp hợp đồng API giữa API mẫu (tài liệu tại /docs) và backend nhóm (/api):

Endpoint web đang dùngĐiểm cần so khớpVí dụ khác biệt hay gặp
GET /productsTham số lọc, kiểu trả về (mảng hay object phân trang), tên trườngNhóm chưa hỗ trợ keyword, includeUnavailable
GET /countersTên trường tọa độlat/lng (Chương 8 di động) so với latitude/longitude
POST /auth/loginDạng phản hồi, mã lỗi 401/403Không trả role ở ngoài, chỉ có trong token
GET /orders/staffĐường dẫn, các trường hiển thịThiếu summary, customerName

Hai cách xử lý khác biệt: sửa backend cho đúng hợp đồng chung (ưu tiên, vì ứng dụng di động cũng dùng), hoặc thêm hàm chuyển đổi trong lib/api.ts để trang web không phải sửa:

// lib/api.ts: chỉ một chỗ biết khác biệt giữa backend và kiểu dữ liệu của web
type CounterDto = { id: number; name: string; lat: number; lng: number };
export const toCounter = (c: CounterDto): Counter =>
  ({ id: c.id, name: c.name, latitude: c.lat, longitude: c.lng, isActive: true });

Kiểm thử hồi quy. Sau khi đổi API_URL, chạy lại toàn bộ test case Sprint 1–2 (TC-01…05, 11…17, 21…28, 31…37) trên backend nhóm, ghi vào cột "Kết quả trên backend nhóm". Test nào trước đạt mà giờ không đạt là một lỗi hồi quy, phải có thẻ trên board.

Trang /admin/categories dùng lại mẫu Server Action của bài 06: requireRole('admin'), gọi apiAuth('/admin/categories', …), bắt 409 để hiện "Danh mục còn món, không xóa được", rồi revalidatePath.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): Quản lý danh mục từ CSDL đến web

  1. Viết database/20-admin.sql, chạy hai lần liên tiếp trên CSDL nhóm để chứng minh chạy lại không lỗi; tạo tài khoản admin bằng script seed.
  2. Chạy thử từng thủ tục trong SSMS: xóa danh mục còn món phải nhận lỗi 50409.
  3. Tạo AdminCategoriesController, DTO, cập nhật RolesGuard; thử trên Swagger bằng token admin và token staff (mong đợi 403).
  4. Trang /admin/categories trên web: danh sách, thêm, sửa, xóa qua Server Action, gọi backend nhóm.

✍️ Thực hành không hướng dẫn (1 tiết): Quản lý quầy

Bổ sung vào 20-admin.sql các cột Description, IsActive cho bảng Counters (có kiểm tra trước), thủ tục sp_Counter_Create và sp_Counter_Update (tên 2–100 ký tự, vĩ độ −90…90, kinh độ −180…180, sai thì THROW 50400); API POST/PUT /admin/counters chỉ cho admin, có Swagger.

Hoàn thành khi: nộp link repo, ảnh chụp Swagger và kết quả 4 lần gọi: tạo hợp lệ (201), vĩ độ 91 (400), sửa quầy không tồn tại (404), gọi bằng token staff (403).

🆘 4. Góc trợ giúp và mở rộng ▼

Lỗi 547 khi thêm ràng buộc CK_Users_Role: trong bảng đã có dòng mang vai trò khác ba giá trị cho phép. Tìm bằng SELECT DISTINCT Role FROM dbo.Users và sửa dữ liệu trước.

Token admin vẫn nhận 403 ở route nhân viên: RolesGuard so khớp đúng tên vai trò. Thêm 'admin' vào @Roles hoặc sửa guard (mục 2.3).

Lỗi 500 thay vì 409: thủ tục dùng RAISERROR hoặc mã lỗi khác 50400/50404/50409, nên DatabaseService không chuyển được thành mã HTTP. Dùng THROW với đúng mã.

Web lỗi sau khi đổi API_URL: mở tab Network của trình duyệt không thấy gì vì Next.js gọi API từ server. Xem log ở terminal chạy npm run dev và so với Swagger của nhóm.

Kiến thức mở rộng: nhật ký thao tác quản trị (bảng AuditLogs ghi ai sửa gì, lúc nào) bằng trigger hoặc ghi trong thủ tục; kiểm thử hợp đồng API tự động bằng cách so file OpenAPI của hai backend.
