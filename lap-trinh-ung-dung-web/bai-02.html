BÀI 02 - Routing, layout & giao diện với Tailwind CSS (5 tiết: 1 LT / 4 TH)

Quản lý căn tin cần một khu quản trị có thanh menu bên trái, còn sinh viên cần trang thực đơn gọn trên điện thoại. Hai khu vực, hai bố cục, nhưng cùng một ứng dụng. Bắt đầu từ đâu: vẽ giao diện, hay phân tích xem có những trang nào và ai được vào?

Mục tiêu: Phân tích được chức năng thành sitemap và hệ thống route; xây dựng được route lồng nhau, route group, route động và layout dùng chung; dựng được giao diện responsive bằng Tailwind CSS và shadcn/ui.

Nội dung:

  • Ý chính 1 - Từ sơ đồ chức năng đến route: sitemap, bảng ánh xạ chức năng ↔ route ↔ vai trò.
  • Ý chính 2 - Routing của App Router: route lồng nhau, route group, route động, loading, error, not-found.
  • Ý chính 3 - Layout dùng chung và cây component: layout quản trị, layout khách, metadata.
  • Ý chính 4 - Tailwind CSS và shadcn/ui: utility class, responsive, component có sẵn; từ Figma đến mã.

Kết quả cần đạt: Khung route và layout của LHU Food Web (quản trị và khách) với dữ liệu giả; nhóm có sơ đồ chức năng web, sitemap và bảng ánh xạ route.

CLO liên quan: CLO1.

📚 2. Học liệu chính ▼

2.1. Từ sơ đồ chức năng đến route

Phân tích trước khi code (CLO1): mỗi chức năng trong sơ đồ chức năng thành một hoặc vài trang; mỗi trang có đường dẫn, vai trò được vào, và dữ liệu lấy từ đâu.

2.2. Routing của App Router

app/
  layout.tsx                 layout gốc
  (shop)/                    route group: không xuất hiện trong URL
    layout.tsx               header cho khách
    menu/page.tsx            /menu
    product/[id]/page.tsx    /product/12   (route động)
  admin/
    layout.tsx               sidebar quản trị
    page.tsx                 /admin        (dashboard)
    products/page.tsx        /admin/products
    orders/page.tsx          /admin/orders
  not-found.tsx              trang 404

Route động đọc tham số qua params. Từ Next.js 15, params là Promise nên phải await:

// app/(shop)/product/[id]/page.tsx
import { notFound } from 'next/navigation';
import { mockProducts } from '@/lib/mock';

export default async function ProductPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const product = mockProducts.find((p) => p.id === Number(id));
  if (!product) notFound();               // hiển thị not-found.tsx
  return <h1 className="text-2xl font-bold">{product.name}</h1>;
}
  • loading.tsx: giao diện chờ trong lúc trang đang tải dữ liệu (dùng ở bài 03).
  • error.tsx: giao diện khi trang lỗi; bắt buộc là Client Component.
  • Điều hướng bằng <Link href="/menu"> (tải trước, không tải lại toàn trang); trong Client Component có thể dùng useRouter().

2.3. Layout dùng chung và cây component

// app/admin/layout.tsx
import Link from 'next/link';

const MENU = [
  { href: '/admin', label: 'Tổng quan' },
  { href: '/admin/orders', label: 'Màn hình quầy' },
  { href: '/admin/products', label: 'Món ăn' },
];

export default function AdminLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="flex min-h-screen">
      <aside className="hidden w-60 bg-blue-950 p-4 text-white md:block">
        <p className="mb-6 font-bold">LHU Food · Quản trị</p>
        <nav className="space-y-1">
          {MENU.map((m) => (
            <Link key={m.href} href={m.href} className="block rounded px-3 py-2 hover:bg-blue-800">{m.label}</Link>
          ))}
        </nav>
      </aside>
      <main className="flex-1 bg-slate-50 p-6">{children}</main>
    </div>
  );
}
  • Layout giữ nguyên khi chuyển giữa các trang con (sidebar không vẽ lại); mỗi khu vực có layout riêng.
  • Tiêu đề trang: export const metadata = { title: 'Món ăn | LHU Food' } trong page.tsx hoặc layout.tsx.
  • Cây component (layout → trang → thành phần như ProductCard, OrderTable) là một phần phân tích thành phần ở CLO1; vẽ lại cho các trang chính của nhóm.

2.4. Tailwind CSS và shadcn/ui

Tailwind CSS viết giao diện bằng utility class ngay trong JSX: p-4 (padding), text-xl, bg-blue-950, grid grid-cols-1 md:grid-cols-3 (1 cột trên điện thoại, 3 cột từ màn hình vừa). Tiền tố sm:, md:, lg: áp dụng từ kích thước đó trở lên (mobile-first).

npx shadcn@latest init            # cấu hình shadcn/ui cho dự án
npx shadcn@latest add button card table dialog

shadcn/ui chép mã nguồn component vào components/ui/ của dự án (không phải thư viện cài sẵn), nên nhóm sửa được theo nhận diện LHU. Dùng Card cho thẻ món, Table cho danh sách quản trị, Dialog cho xác nhận.

Từ Figma đến mã bằng vibe coding: đưa ảnh thiết kế, bảng route và AGENTS.md cho AI; yêu cầu dùng component shadcn/ui có sẵn và class Tailwind, không viết CSS riêng. Kiểm tra: màu, khoảng cách khớp thiết kế; responsive ở 3 kích thước; không có thư viện UI lạ.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (2 tiết): Khung giao diện LHU Food Web

  1. Cài shadcn/ui và thêm button, card, table.
  2. Tạo cây thư mục như mục 2.2 với dữ liệu giả trong lib/mock.ts.
  3. Layout quản trị có sidebar (ẩn trên điện thoại, hiện từ md), layout khách có header.
  4. Trang /menu dạng lưới thẻ món bằng Card; trang /product/[id] với notFound() khi sai mã.
  5. Lập bảng ánh xạ route – chức năng – vai trò – API cho các trang vừa tạo.

✍️ Thực hành không hướng dẫn (1,5 tiết): Danh sách quầy

Tạo /counters (danh sách quầy dạng thẻ) và /counters/[id] (chi tiết quầy) với dữ liệu giả, dùng layout khách; responsive 1 cột (điện thoại), 2 cột (máy tính bảng), 3 cột (máy tính).

Hoàn thành khi: route động hoạt động, mã quầy sai hiện trang 404; ảnh chụp ở 3 kích thước màn hình; prompt ghi trong PROMPTS.md.

🆘 4. Góc trợ giúp và mở rộng ▼

Lỗi kiểu dữ liệu params: từ Next.js 15, params và searchParams là Promise; khai báo Promise<{ id: string }> và await. Mã AI sinh theo phiên bản cũ thường thiếu bước này.

Class Tailwind không có tác dụng: kiểm tra file CSS toàn cục đã được import trong app/layout.tsx; tên class phải viết đầy đủ trong mã (không ghép chuỗi động như `bg-${color}-500`).

Hai trang cùng đường dẫn: route group không đổi URL, nên (shop)/menu và (admin)/menu xung đột. Đặt tên trang khác nhau.

Kiến thức mở rộng: Parallel Routes và Intercepting Routes (mở chi tiết món dạng modal mà vẫn có URL riêng).
