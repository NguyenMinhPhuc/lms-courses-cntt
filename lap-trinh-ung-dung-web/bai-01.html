BÀI 01 - Ứng dụng web hiện đại với Next.js & khởi động dự án (5 tiết: 2 LT / 3 TH)

Bạn đã viết được ứng dụng React chạy trong trình duyệt. Nhưng trang thực đơn LHU Food cần hiện ngay khi mở, được Google tìm thấy, còn trang quản trị của căn tin lại cần tương tác nhiều và chỉ quản lý mới được vào. Một framework làm được cả hai việc đó như thế nào?

Mục tiêu: So sánh được các mô hình render web; giải thích được vai trò của Next.js App Router; phân tích được phạm vi web của LHU Food từ SRS; lập được kế hoạch Sprint 1 và phân vai cho nhóm.

Nội dung:

  • Ý chính 1 - Mô hình render web: CSR, SSR, SSG, ISR và React Server Components; khi nào cần một framework như Next.js.
  • Ý chính 2 - Next.js App Router: thư mục app/, page.tsx, layout.tsx, Server Component mặc định, "use client".
  • Ý chính 3 - Phân tích phạm vi web của LHU Food: actor, user story web trong SRS, kiến trúc Next.js ↔ API ↔ SQL Server.
  • Ý chính 4 - Lập kế hoạch dự án và vibe coding: Product Backlog, kế hoạch sprint, board công việc; AGENTS.md cho dự án Next.js.

Kết quả cần đạt: Dự án lhu-food-web chạy được, có repo và AGENTS.md; nhóm có danh sách story web, kế hoạch Sprint 1 trên board và bảng phân vai.

CLO liên quan: CLO1, CLO4.

2.1. Các mô hình render web

Mô hình HTML được tạo ở đâu, khi nào Phù hợp trong LHU Food
CSR (React SPA đã học)Trình duyệt tải JavaScript rồi mới vẽ giao diệnPhần tương tác nhiều: giỏ hàng, màn hình quầy
SSRServer tạo HTML cho từng requestTrang đơn của tôi, dữ liệu theo người dùng
SSG / ISRTạo sẵn HTML lúc build; ISR làm mới định kỳTrang giới thiệu, thực đơn làm mới vài chục giây một lần
React Server ComponentsComponent chạy trên server, chỉ gửi kết quả xuống trình duyệt, không gửi mãMặc định cho mọi trang; chỉ phần cần tương tác mới chạy ở trình duyệt

Next.js là framework React cho phép kết hợp các mô hình trên trong cùng một ứng dụng: trang thực đơn render trên server (tải nhanh, tốt cho tìm kiếm), trang quản trị có các "đảo" tương tác chạy ở trình duyệt.

2.2. Next.js App Router

npx create-next-app@latest lhu-food-web --ts --tailwind --eslint --app --import-alias "@/*"
cd lhu-food-web
npm run dev          # mở http://localhost:3000

Mỗi thư mục trong app/ là một đoạn đường dẫn; file page.tsx là trang, layout.tsx bọc các trang con:

app/
  layout.tsx        bố cục gốc (thẻ <html>, <body>)
  page.tsx          /
  menu/
    page.tsx        /menu
  admin/
    page.tsx        /admin
// app/page.tsx: Server Component (mặc định), chạy trên server
export default function HomePage() {
  return (
    <main className="mx-auto max-w-4xl p-6">
      <h1 className="text-3xl font-bold text-blue-900">LHU Food</h1>
      <p className="mt-2 text-slate-600">Đặt món căn tin, nhận món không cần xếp hàng.</p>
    </main>
  );
}
  • Server Component (mặc định): chạy trên server, đọc dữ liệu được, không dùng useState, sự kiện onClick.
  • Client Component: file bắt đầu bằng "use client", dùng được state và sự kiện; chỉ dùng cho phần cần tương tác.
  • Next.js thay đổi nhanh giữa các phiên bản. Kiểm tra phiên bản bằng npx next --version và đọc tài liệu đúng phiên bản trên nextjs.org. Học phần dùng App Router; không trộn với Pages Router (thư mục pages/).

2.4. Lập kế hoạch dự án và vibe coding

Sắp xếp công việc (CLO4): chọn story web từ Product Backlog dùng chung (kế hoạch Agile LHU Food), ước lượng story point, đặt Sprint Goal, đưa vào board (GitHub Projects hoặc Jira) với cột Cần làm, Đang làm, Chờ review, Xong. Mỗi thẻ có người phụ trách và liên kết tới Pull Request.

File quy ước cho AI (AGENTS.md, chép sang .github/copilot-instructions.md):

# LHU Food Web - Quy ước dự án
## Công nghệ
- Next.js App Router (thư mục app/), TypeScript, Tailwind CSS + shadcn/ui.
- KHÔNG dùng Pages Router, KHÔNG kết nối SQL Server; dữ liệu lấy qua API (biến API_URL).
## Quy ước
- Server Component mặc định; chỉ thêm "use client" khi cần state hoặc sự kiện.
- Gọi API tập trung trong lib/api.ts; kiểu dữ liệu trong lib/types.ts.
- Chuỗi hiển thị tiếng Việt có dấu; không thêm thư viện khi nhóm chưa đồng ý.

Lỗi AI hay mắc với Next.js: trộn mã Pages Router (getServerSideProps), dùng hook trong Server Component, quên "use client" hoặc thêm tràn lan. Mỗi đoạn mã AI sinh phải được bạn hiểu và giải thích được; prompt chính ghi vào PROMPTS.md.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): Khởi tạo LHU Food Web

  1. Cài Node.js bản LTS; tạo dự án lhu-food-web bằng lệnh ở mục 2.2; chạy npm run dev.
  2. Sửa app/page.tsx thành trang chủ LHU Food; tạo thêm app/menu/page.tsx và app/admin/page.tsx (nội dung tạm).
  3. Tạo repo GitHub, viết AGENTS.md theo mẫu, commit đầu tiên.
  4. Mở tài liệu API mẫu tại <địa chỉ API>/docs, thử GET /categories và GET /products.

✍️ Thực hành không hướng dẫn (1 tiết): Hồ sơ cá nhân nhiều trang

Tạo ứng dụng Next.js "Hồ sơ cá nhân" có trang chủ, /gioi-thieu, /du-an, /lien-he, dùng chung một layout có thanh điều hướng.

Hoàn thành khi: 4 trang chạy được, điều hướng bằng Link, đẩy lên GitHub cá nhân, có ít nhất một prompt trong PROMPTS.md.

Nộp bài

👥 Thử thách nhóm (0,5 tiết + ở nhà): Khởi động phần web của đồ án

  • Dùng chung nhóm và đề tài với đồ án di động; tạo repo web của nhóm, mời giảng viên.
  • Chọn các story web từ backlog, lập bảng phạm vi (khu vực, actor, story, mức bắt buộc/cơ bản).
  • Kế hoạch Sprint 1: Sprint Goal, story đã ước lượng, board công việc có người phụ trách từng thẻ.
  • Bảng phân vai phần web (quản trị, màn hình quầy, web khách, kiểm thử, báo cáo).

🆘 4. Góc trợ giúp và mở rộng ▼

Lỗi "You're importing a component that needs useState…": bạn dùng hook trong Server Component. Tách phần tương tác ra một file riêng có "use client" ở dòng đầu.

Cổng 3000 đã bị dùng: chạy npm run dev -- -p 3001; API mẫu chạy ở máy khác nên không xung đột.

AI sinh mã có getServerSideProps hoặc thư mục pages/: đó là Pages Router; nhắc AI đọc AGENTS.md và yêu cầu viết theo App Router.

Kiến thức mở rộng: Đọc mục "Rendering" trong tài liệu Next.js để so sánh cách Next.js quyết định render tĩnh hay động cho từng route khi build.
