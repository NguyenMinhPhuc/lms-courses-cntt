BÀI 03 - Server Components & lấy dữ liệu từ API (5 tiết: 1 LT / 4 TH) · Checkpoint Sprint 1

Trang thực đơn đang hiện 10 món giả. Hôm nay nó lấy món thật từ API của căn tin, ngay trên server, trước khi trình duyệt nhận HTML. Và trước khi demo, nhóm phải chứng minh trang đó đúng yêu cầu bằng test case, không phải bằng câu "em chạy thử thấy được".

Mục tiêu: Phân biệt được Server Component và Client Component; lấy được dữ liệu từ API mẫu với cache phù hợp; xử lý được trạng thái tải và lỗi; viết và chạy được test case từ tiêu chí nghiệm thu; trình bày được kết quả Sprint 1 bằng báo cáo theo mẫu.

Nội dung:

  • Ý chính 1 - Server và Client Component: chạy ở đâu, gửi gì xuống trình duyệt, ranh giới "use client".
  • Ý chính 2 - Lấy dữ liệu từ API: fetch trong Server Component, biến môi trường, kiểu TypeScript, cache và revalidate.
  • Ý chính 3 - Trạng thái tải và lỗi: loading.tsx, Suspense, error.tsx.
  • Ý chính 4 - Kiểm thử và báo cáo sprint: test case từ tiêu chí nghiệm thu, báo cáo sprint theo mẫu, Sprint Review và kế hoạch Sprint 2.

Kết quả cần đạt: Trang thực đơn và chi tiết món lấy dữ liệu thật; nhóm hoàn thành Checkpoint Sprint 1 với test case có kết quả, báo cáo sprint 1 và kế hoạch Sprint 2.

CLO liên quan: CLO1, CLO2, CLO3, CLO4.

📚 2. Học liệu chính ▼

2.1. Server Component và Client Component

Server Component (mặc định)Client Component ("use client")
Chạy ở đâuServer (lúc build hoặc mỗi request)Server lần đầu (HTML) rồi trình duyệt
Dùng đượcasync/await, biến môi trường bí mật, gọi API trực tiếpuseState, useEffect, sự kiện, API trình duyệt
Gửi xuống trình duyệtChỉ kết quả, không gửi mãMã JavaScript của component
Ví dụ LHU FoodTrang thực đơn, chi tiết mónNút "Thêm vào giỏ", bộ lọc có hiệu ứng

Quy tắc: trang để là Server Component, chỉ tách phần nhỏ cần tương tác thành Client Component. Ranh giới "use client" và lý do chọn là nội dung "thiết kế component" trong báo cáo (CLO1).

2.2. Lấy dữ liệu từ API mẫu

Địa chỉ API đặt trong .env.local (không commit). Biến không có tiền tố NEXT_PUBLIC_ chỉ đọc được ở server, trình duyệt không thấy:

# .env.local
API_URL=http://<địa-chỉ-API-mẫu>:3000
// lib/types.ts: theo định dạng trả về của API mẫu (xem /docs)
export type Category = { id: number; name: string; productCount: number };
export type Product = {
  id: number; categoryId: number; categoryName: string; name: string;
  description: string | null; price: number; imageUrl: string | null;
  isAvailable: boolean; stock: number;
};

// lib/api.ts: chỉ dùng ở server
import 'server-only';

export async function apiGet<T>(path: string, revalidate = 30): Promise<T> {
  const res = await fetch(`${process.env.API_URL}${path}`, { next: { revalidate } });
  if (!res.ok) throw new Error(`API ${path} trả về ${res.status}`);
  return res.json() as Promise<T>;
}
// app/(shop)/menu/page.tsx
import Link from 'next/link';
import { apiGet } from '@/lib/api';
import type { Category, Product } from '@/lib/types';

type Props = { searchParams: Promise<{ category?: string; q?: string }> };

export default async function MenuPage({ searchParams }: Props) {
  const { category, q } = await searchParams;
  const query = new URLSearchParams({ pageSize: '50' });
  if (category) query.set('categoryId', category);
  if (q) query.set('keyword', q);

  const [categories, products] = await Promise.all([
    apiGet<Category[]>('/categories', 300),          // danh mục ít đổi: 5 phút
    apiGet<Product[]>(`/products?${query}`, 30),     // tồn kho đổi thường xuyên: 30 giây
  ]);

  return (
    <main className="mx-auto max-w-5xl p-6">
      <form action="/menu" className="mb-4">
        <input name="q" defaultValue={q} placeholder="Tìm món…" className="w-full rounded border px-3 py-2" />
      </form>
      <nav className="mb-4 flex gap-2 overflow-x-auto">
        {categories.map((c) => (
          <Link key={c.id} href={`/menu?category=${c.id}`} className="rounded-full border px-3 py-1">{c.name}</Link>
        ))}
      </nav>
      {products.length === 0 ? (
        <p className="text-slate-500">Không tìm thấy món phù hợp.</p>
      ) : (
        <ul className="grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3">
          {products.map((p) => (
            <li key={p.id} className="rounded-xl border bg-white p-4">
              <Link href={`/product/${p.id}`} className="font-bold">{p.name}</Link>
              <p>{p.price.toLocaleString('vi-VN')} đ</p>
            </li>
          ))}
        </ul>
      )}
    </main>
  );
}
  • Form tìm kiếm dùng phương thức GET bình thường nên không cần JavaScript phía client; kết quả nằm trong URL (/menu?q=com), chia sẻ được.
  • Cache: từ Next.js 15, fetch không tự cache; { next: { revalidate: 30 } } cho phép dùng lại kết quả 30 giây rồi làm mới. Chọn thời gian theo mức thay đổi của dữ liệu.
  • imageUrl của API là đường dẫn tương đối (/uploads/...), có thể rỗng; ghép với API_URL và có ảnh thay thế khi không có ảnh.

2.3. Trạng thái tải và lỗi

// app/(shop)/menu/loading.tsx: hiện ngay trong lúc trang chờ API
export default function Loading() {
  return <p className="p-6 text-slate-500">Đang tải thực đơn…</p>;
}

// app/(shop)/menu/error.tsx: bắt buộc là Client Component
'use client';
export default function MenuError({ reset }: { error: Error; reset: () => void }) {
  return (
    <div className="p-6">
      <p>Không tải được thực đơn. Vui lòng thử lại.</p>
      <button onClick={reset} className="mt-2 rounded bg-blue-900 px-4 py-2 text-white">Thử lại</button>
    </div>
  );
}

loading.tsx dùng cơ chế streaming: layout và khung trang hiện ngay, phần dữ liệu đến sau. Có thể bọc riêng từng khối chậm bằng <Suspense fallback={...}> để phần nhanh không phải chờ phần chậm. Không hiển thị thông báo kỹ thuật của lỗi cho người dùng.

Test case từ tiêu chí nghiệm thu (CLO2). Mỗi tiêu chí trong SRS (mục 4.7) thành ít nhất một test case có kết quả mong đợi đo được:

Báo cáo sprint (CLO3), 1–2 trang, đúng định dạng ở trang Đánh giá học phần:

  1. Sprint Goal và kết quả: đạt/chưa đạt, link demo.
  2. Story đã hoàn thành (bảng: mã story, người phụ trách, PR).
  3. Phân tích thành phần của sprint (sơ đồ, bảng ánh xạ route) – có số hình, chú thích.
  4. Kiểm thử: số test case, số đạt, lỗi tìm thấy và đã sửa.
  5. Kế hoạch so với thực tế (story point cam kết và hoàn thành), nguyên nhân chênh lệch.
  6. Kế hoạch sprint sau và bài học rút ra (Retrospective).

Sprint Review và kế hoạch Sprint 2 (CLO4): demo cho giảng viên, nhận góp ý, cập nhật backlog; chọn story Sprint 2 theo năng lực thực tế của Sprint 1 (velocity).

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): Thực đơn với dữ liệu thật

  1. Tạo .env.local, lib/types.ts, lib/api.ts (cài npm install server-only).
  2. Trang /menu lấy danh mục và món từ API mẫu, lọc theo danh mục, tìm kiếm qua searchParams.
  3. Trang /product/[id] gọi GET /products/:id, hiện "Hết món" khi isAvailable sai hoặc stock bằng 0.
  4. Thêm loading.tsx, error.tsx; thử tắt mạng hoặc đổi API_URL sai.
  5. Viết và chạy 5 test case theo bảng mẫu, ghi kết quả.

✍️ Thực hành không hướng dẫn (1,5 tiết): Quầy với dữ liệu thật

Chuyển trang /counters (bài 02) sang lấy dữ liệu từ GET /counters, có trạng thái tải, lỗi, rỗng; chọn thời gian revalidate phù hợp và giải thích.

Hoàn thành khi: trang chạy với API mẫu; nộp 5 test case (có trường hợp lỗi API) kèm kết quả chạy.

🆘 4. Góc trợ giúp và mở rộng ▼

process.env.API_URL là undefined: biến đặt sai file (phải là .env.local ở gốc dự án) hoặc chưa khởi động lại npm run dev sau khi sửa.

Lỗi "server-only cannot be imported from a Client Component": bạn gọi lib/api.ts trong file có "use client". Lấy dữ liệu ở Server Component cha rồi truyền xuống qua props.

Dữ liệu không cập nhật sau khi sửa trên API: đang dùng kết quả cache; chờ hết thời gian revalidate hoặc giảm thời gian khi phát triển.

Kiến thức mở rộng: generateStaticParams để tạo sẵn trang chi tiết món khi build; generateMetadata để đặt tiêu đề trang theo tên món.

Tự đánh giá: Mỗi test case của nhóm có truy vết được tới một tiêu chí nghiệm thu trong SRS, và có kết quả chạy thật không?
