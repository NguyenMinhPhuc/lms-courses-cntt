BÀI 11 - Triển khai lên Windows Server của Khoa & hoàn thiện báo cáo (5 tiết: 1 LT / 4 TH)

"Trên máy em chạy được mà thầy." Đến Demo Day, câu này không còn giá trị: web của nhóm phải chạy trên server của Khoa, mở được từ máy bất kỳ trong phòng, đăng nhập được, nhận đơn realtime từ điện thoại. Song song, báo cáo đồ án phải đi từ một thư mục ảnh chụp màn hình thành một tài liệu 30–50 trang đúng quy định.

Mục tiêu: Triển khai được ứng dụng Next.js cùng backend nhóm lên Windows Server; cấu hình đúng biến môi trường, cookie, CORS cho môi trường triển khai; viết được tài liệu triển khai; hoàn thiện được báo cáo đồ án đúng quy định định dạng; đối chiếu được kế hoạch với tiến độ thực tế.

Nội dung:

  • Ý chính 1 - Build production: next build, chế độ standalone, biến môi trường theo môi trường.
  • Ý chính 2 - Chạy trên Windows Server: dịch vụ nền, reverse proxy và HTTPS theo bộ phận hỗ trợ; cookie Secure, CORS, kiểm tra sau triển khai.
  • Ý chính 3 - Báo cáo kỹ thuật: cấu trúc báo cáo đồ án, quy định định dạng, hình/bảng, trích dẫn IEEE, minh chứng.
  • Ý chính 4 - Tổng kết kế hoạch: burndown, velocity, kế hoạch so với thực tế, bài học quản lý công việc.

Kết quả cần đạt: Web và backend nhóm chạy trên server Khoa, qua được danh sách kiểm tra sau triển khai; có README triển khai; có bản nháp báo cáo đồ án đủ 7 chương.

CLO liên quan: CLO1, CLO3, CLO4.

2.1. Build production và chế độ standalone

Máy trong phòng ──HTTPS──▶ Reverse proxy (server Khoa) ──▶ Next.js :3001 ──▶ API nhóm :3000 ──▶ SQL Server
Điện thoại (app) ─────────────────────────────────────────────────────────────▶ API nhóm (REST + Socket.IO)
Trình duyệt quầy ──Socket.IO (wss)────────────────────────────────────────────▶ API nhóm

Chế độ standalone gom mã chạy và các gói cần thiết vào .next/standalone, chạy bằng node server.js mà không cần cài lại node_modules đầy đủ trên server.

// next.config.ts (bổ sung)
const nextConfig = {
  output: 'standalone',
  experimental: {
    serverActions: {
      bodySizeLimit: '3mb',
      allowedOrigins: ['<ten-mien-web-nhom>'],   // khi chạy sau reverse proxy có tên miền khác Host
    },
  },
};
# PowerShell trên server (hoặc máy build), trong thư mục dự án
npm ci
$env:NEXT_PUBLIC_SOCKET_URL = 'https://<dia-chi-api-nhom>'   # ghi cứng vào mã lúc build
npm run build
Copy-Item -Recurse public .next\standalone\public
Copy-Item -Recurse .next\static .next\standalone\.next\static

# Chạy thử
$env:PORT = '3001'; $env:HOSTNAME = '0.0.0.0'
$env:API_URL = 'http://localhost:3000'; $env:SITE_URL = 'https://<ten-mien-web-nhom>'
node .next\standalone\server.js

NEXT_PUBLIC_SOCKET_URLBuildĐược chép thẳng vào JavaScript gửi xuống trình duyệt. Đổi giá trị phải build lại.
API_URL, SITE_URL, COOKIE_SECUREChạyChỉ server đọc; đặt trong cấu hình dịch vụ hoặc file môi trường trên server, không commit.

Nếu web và API cùng nằm trên một server, API_URL trỏ về http://localhost:<cổng API> (Next.js gọi API từ server, không qua mạng ngoài). Trình duyệt chỉ cần tới API cho kết nối Socket.IO.

2.2. Chạy trên Windows Server của Khoa

Giống Chương 11 giáo trình di động: mỗi nhóm được cấp quyền trên server và có bộ phận hỗ trợ triển khai. Các thao tác cần quyền quản trị (đăng ký dịch vụ nền, mở cổng firewall, cấu hình reverse proxy, chứng chỉ HTTPS) làm theo hướng dẫn hoặc với sự hỗ trợ của bộ phận này. Bài học mô tả những gì cần đạt và cách kiểm tra.

ViệcYêu cầuAi làm
Dịch vụ nềnWeb tự chạy lại khi server khởi động lại hoặc tiến trình bị dừngNhóm, theo công cụ bộ phận hỗ trợ chỉ định
Reverse proxy, HTTPSTên miền trỏ tới cổng của web; bật hỗ trợ WebSocket nếu socket đi qua proxyBộ phận hỗ trợ
FirewallMở đúng cổng cần thiết (gửi yêu cầu kèm số cổng)Bộ phận hỗ trợ
CORS của APICho phép địa chỉ web của nhóm kết nối Socket.IONhóm (cấu hình backend)

Cookie Secure. Bài 05 bật secure khi NODE_ENV=production. Trình duyệt không lưu cookie Secure qua HTTP thường, nên nếu server chưa có HTTPS thì đăng nhập "thành công" nhưng bị đẩy về /login ngay. Tách thành biến riêng để kiểm soát:

// lib/session.ts và proxy.ts
secure: process.env.COOKIE_SECURE !== 'false',   // mặc định bật; chỉ tắt tạm khi server chưa có HTTPS

// app/api/health/route.ts: kiểm tra nhanh sau triển khai
export async function GET() {
  const api = await fetch(`${process.env.API_URL}/health`, { cache: 'no-store' }).then((r) => r.ok).catch(() => false);
  return Response.json({ web: 'ok', api: api ? 'ok' : 'down', time: new Date().toISOString() },
                       { status: api ? 200 : 503 });
}

Tắt COOKIE_SECURE là cấu hình tạm cho môi trường học tập; ghi rõ trong báo cáo, giống cách giáo trình di động xử lý HTTP không mã hóa.

Danh sách kiểm tra sau triển khai (ghi kết quả vào chương Triển khai của báo cáo):

README triển khai trong repo, đủ để một người khác làm lại: yêu cầu (phiên bản Node.js, cổng), danh sách biến môi trường (không ghi giá trị bí mật), lệnh build, cách chạy dịch vụ, cách cập nhật phiên bản mới, cách kiểm tra (/api/health), người liên hệ. Cập nhật phiên bản: build lại, chép thư mục standalone mới, khởi động lại dịch vụ, chạy lại danh sách kiểm tra.

Lỗi trình bày hay gặp và cách sửa trong Word:

  • Tiêu đề gõ tay số và in đậm: dùng Heading 1/2/3 có đánh số tự động, rồi chèn mục lục tự động (References → Table of Contents).
  • Hình không số, không chú thích: dùng Insert Caption ("Hình 3.2. Ma trận phân quyền"), nhắc tới hình trong văn bản bằng Cross-reference trước khi hình xuất hiện; danh mục hình sinh tự động.
  • Ảnh chụp màn hình mờ, cả màn hình: cắt đúng vùng cần nói, chữ trong ảnh đọc được khi in.
  • Dán cả trang mã: chỉ trích đoạn ngắn minh họa quyết định, có chú thích; mã đầy đủ để ở repo hoặc phụ lục.
  • Liệt kê mà không giải thích: mỗi hình, bảng cần một đoạn trả lời "điều này cho thấy gì, vì sao chọn như vậy".
  • Trích dẫn thiếu: tài liệu chính thức (Next.js, NestJS, OWASP…) trích theo IEEE, số thứ tự trong ngoặc vuông [1] tại chỗ dùng.
  • Không khai báo dùng AI: mục "Sử dụng AI" ghi công cụ, việc dùng AI làm, cách đã kiểm chứng (theo quy định trang Đánh giá).

🆘 4. Góc trợ giúp và mở rộng ▼

Trang hiện nhưng mất CSS, ảnh: chưa chép public và .next/static vào thư mục standalone.

Đăng nhập xong bị đẩy về /login: cookie Secure qua HTTP. Dùng HTTPS, hoặc tạm đặt COOKIE_SECURE=false và ghi chú trong báo cáo.

Server Action báo lỗi "Invalid Server Actions request" sau reverse proxy: header Origin khác Host. Thêm tên miền vào serverActions.allowedOrigins, hoặc nhờ bộ phận hỗ trợ chuyển tiếp đúng header Host.

Màn hình quầy không kết nối socket trên server: NEXT_PUBLIC_SOCKET_URL vẫn là địa chỉ máy phát triển (phải build lại); CORS của API chưa có địa chỉ web; proxy chưa bật WebSocket.

Kiến thức mở rộng: tự động build và triển khai bằng GitHub Actions khi merge vào nhánh chính; giám sát lỗi phía trình duyệt bằng công cụ thu thập lỗi.
