BÀI 06 - Server Actions, bảng dữ liệu & màn hình quầy (5 tiết: 1 LT / 4 TH) · Checkpoint Sprint 2

11 giờ 30, quầy căn tin có 20 đơn chờ. Hai nhân viên cùng bấm "Bắt đầu làm" một đơn. Một khách vừa hủy đơn mà bếp đã nấu xong. Màn hình quầy không chỉ là một bảng dữ liệu đẹp: nó phải đúng trình tự nghiệp vụ, phản hồi tức thì và báo lỗi rõ ràng khi hai người tranh nhau một đơn.

Mục tiêu: Thực hiện được thao tác ghi dữ liệu bằng Server Actions với useActionState, revalidatePath và useOptimistic; xây dựng được bảng dữ liệu có lọc, sắp xếp, phân trang theo URL; xây dựng được màn hình quầy chuyển trạng thái đúng trình tự; kiểm thử được luồng "khách đặt → nhân viên xử lý"; báo cáo được kết quả Sprint 2.

Nội dung:

  • Ý chính 1 - Server Actions: useActionState, revalidatePath, xử lý lỗi, cập nhật lạc quan với useOptimistic.
  • Ý chính 2 - Bảng dữ liệu: TanStack Table, lọc và phân trang qua tham số URL.
  • Ý chính 3 - Màn hình quầy: đơn theo trạng thái, chuyển trạng thái đúng trình tự, hủy kèm lý do, xử lý 409.
  • Ý chính 4 - Kiểm thử luồng và báo cáo Sprint 2: test case theo tiêu chí nghiệm thu, velocity, Checkpoint Sprint 2.

Kết quả cần đạt: Màn hình quầy (US-S02, S03, S06, S07) và bảng món cho nhân viên (US-S04) chạy với API mẫu; nhóm demo được luồng đặt món trên web → nhân viên xử lý và hoàn thành Checkpoint Sprint 2.

📚 2. Học liệu chính ▼

2.1. Server Actions

Server Action là hàm async có chỉ thị 'use server', chạy trên server nhưng được gọi từ form hoặc Client Component. Không cần tự viết Route Handler cho từng thao tác ghi. Mỗi Server Action là một endpoint công khai, nên luôn kiểm tra quyền và dữ liệu bên trong nó.

// app/admin/orders/actions.ts
'use server';
import { revalidatePath } from 'next/cache';
import { z } from 'zod';
import { requireRole } from '@/lib/dal';
import { apiAuth, ApiError } from '@/lib/api';

export type NextStatus = 'preparing' | 'ready' | 'completed';
export type ActionResult = { ok: boolean; message?: string };

export async function advanceStatus(orderId: number, status: NextStatus): Promise<ActionResult> {
  await requireRole('staff', 'admin');                       // kiểm tra quyền ở chính Server Action
  try {
    await apiAuth(`/orders/${orderId}/status`, { method: 'PATCH', body: JSON.stringify({ status }) });
    return { ok: true };
  } catch (e) {
    if (e instanceof ApiError && e.status === 409)
      return { ok: false, message: `Đơn #${orderId} đã được cập nhật bởi người khác` };
    return { ok: false, message: 'Không cập nhật được trạng thái, vui lòng thử lại' };
  } finally {
    revalidatePath('/admin/orders');                         // vẽ lại trang với dữ liệu mới
  }
}

const cancelSchema = z.object({
  orderId: z.coerce.number().int().positive(),
  reason: z.string().trim().min(3, 'Nhập lý do hủy (tối thiểu 3 ký tự)').max(200, 'Lý do tối đa 200 ký tự'),
});

// Dùng với useActionState: nhận state trước và FormData
export async function staffCancel(_prev: ActionResult, formData: FormData): Promise<ActionResult> {
  await requireRole('staff', 'admin');
  const parsed = cancelSchema.safeParse(Object.fromEntries(formData));
  if (!parsed.success) return { ok: false, message: parsed.error.issues[0].message };
  try {
    await apiAuth(`/orders/${parsed.data.orderId}/staff-cancel`, {
      method: 'POST', body: JSON.stringify({ reason: parsed.data.reason }),
    });
  } catch (e) {
    if (e instanceof ApiError && e.status === 409) return { ok: false, message: 'Đơn đã sẵn sàng hoặc đã hoàn tất, không hủy được' };
    return { ok: false, message: 'Không hủy được đơn, vui lòng thử lại' };
  }
  revalidatePath('/admin/orders');
  return { ok: true, message: 'Đã hủy đơn và báo cho khách' };
}
  • useActionState(action, initialState) (từ react) trả về [state, formAction, isPending]: hiện thông báo lỗi và vô hiệu nút khi đang gửi.
  • revalidatePath xóa cache của trang để lần render sau lấy dữ liệu mới. Không cần tự gọi lại API ở client.
  • useOptimistic hiện ngay kết quả mong đợi trong lúc chờ server; nếu Server Action thất bại, giao diện tự trở về dữ liệu thật sau khi trang được làm mới.

2.2. Bảng dữ liệu với TanStack Table

Trang /admin/products cho nhân viên xem cả món ngừng bán (includeUnavailable=true) và bật/tắt "còn bán" (US-S04). Lọc và phân trang đặt trong URL (?q=com&page=2) để Server Component gọi API đúng trang, tải lại hoặc gửi link vẫn giữ nguyên bộ lọc. TanStack Table lo phần hiển thị và sắp xếp cột trên trang hiện tại.

// app/admin/products/page.tsx (Server Component)
const PAGE_SIZE = 20;
type Props = { searchParams: Promise<{ q?: string; page?: string }> };

export default async function ProductsPage({ searchParams }: Props) {
  await requireRole('staff', 'admin');
  const { q = '', page = '1' } = await searchParams;
  const query = new URLSearchParams({ includeUnavailable: 'true', page, pageSize: String(PAGE_SIZE) });
  if (q) query.set('keyword', q);
  const products = await apiAuth<Product[]>(`/products?${query}`);
  return <ProductTable data={products} page={Number(page)} q={q} hasNext={products.length === PAGE_SIZE} />;
}
// app/admin/products/product-table.tsx   (npm install @tanstack/react-table)
'use client';
import { useState } from 'react';
import Link from 'next/link';
import { flexRender, getCoreRowModel, getSortedRowModel, useReactTable,
         type ColumnDef, type SortingState } from '@tanstack/react-table';
import type { Product } from '@/lib/types';
import { toggleAvailability } from './actions';

const columns: ColumnDef<Product>[] = [
  { accessorKey: 'name', header: 'Tên món' },
  { accessorKey: 'categoryName', header: 'Danh mục' },
  { accessorKey: 'price', header: 'Giá', cell: (c) => `${c.getValue<number>().toLocaleString('vi-VN')} đ` },
  { accessorKey: 'stock', header: 'Tồn' },
  { id: 'available', header: 'Còn bán', cell: ({ row }) => (
      <form action={toggleAvailability.bind(null, row.original.id, !row.original.isAvailable)}>
        <button className="underline">{row.original.isAvailable ? 'Đang bán' : 'Ngừng bán'}</button>
      </form>) },
];

export function ProductTable({ data, page, q, hasNext }:
  { data: Product[]; page: number; q: string; hasNext: boolean }) {
  const [sorting, setSorting] = useState<SortingState>([]);
  const table = useReactTable({ data, columns, state: { sorting }, onSortingChange: setSorting,
    getCoreRowModel: getCoreRowModel(), getSortedRowModel: getSortedRowModel() });
  const href = (p: number) => `?${new URLSearchParams({ q, page: String(p) })}`;
  return (
    <>
      <table className="w-full text-sm">
        <thead>{table.getHeaderGroups().map((g) => (
          <tr key={g.id}>{g.headers.map((h) => (
            <th key={h.id} onClick={h.column.getToggleSortingHandler()} className="cursor-pointer text-left">
              {flexRender(h.column.columnDef.header, h.getContext())}
              {{ asc: ' ▲', desc: ' ▼' }[h.column.getIsSorted() as string] ?? ''}
            </th>))}</tr>))}
        </thead>
        <tbody>{table.getRowModel().rows.map((r) => (
          <tr key={r.id}>{r.getVisibleCells().map((c) => (
            <td key={c.id}>{flexRender(c.column.columnDef.cell, c.getContext())}</td>))}</tr>))}
        </tbody>
      </table>
      <nav className="mt-3 flex gap-3">
        {page > 1 && <Link href={href(page - 1)}>← Trang trước</Link>}
        {hasNext && <Link href={href(page + 1)}>Trang sau →</Link>}
      </nav>
    </>
  );
}

API mẫu trả về mảng, không có tổng số dòng: còn trang sau khi số phần tử bằng pageSize. toggleAvailability là Server Action gọi PATCH /products/:id/availability, kiểm tra quyền staff và revalidatePath('/admin/products'). Với shadcn/ui, có thể dùng mẫu "Data Table" (npx shadcn@latest add table) dựng sẵn trên TanStack Table.

2.3. Màn hình quầy

Phân tích nghiệp vụ (CLO1). Trạng thái đơn chỉ đi một chiều theo quy tắc BR-15:

pending ──"Bắt đầu làm"──▶ preparing ──"Đã xong"──▶ ready ──"Đã giao"──▶ completed
   │ khách hủy (US-C08)         │
   └── nhân viên hủy kèm lý do (US-S07) ──▶ cancelled

Trang /admin/orders là Server Component gọi GET /orders/staff (mặc định trả đơn pending, preparing, ready trong ngày), chia thành ba cột. Lọc trạng thái (US-S06) qua tham số ?status=. Mỗi đơn là một Client Component nhỏ:

// app/admin/orders/order-card.tsx
'use client';
import { useOptimistic, useState, useTransition } from 'react';
import { advanceStatus, type NextStatus } from './actions';

type StaffOrder = { orderId: number; status: string; note: string | null; createdAt: string;
                    customerName: string; total: number; summary: string };

const NEXT: Record<string, { to: NextStatus; label: string } | undefined> = {
  pending: { to: 'preparing', label: 'Bắt đầu làm' },
  preparing: { to: 'ready', label: 'Đã xong' },
  ready: { to: 'completed', label: 'Đã giao' },
};
const LABEL: Record<string, string> = {
  pending: 'Chờ xác nhận', preparing: 'Đang chuẩn bị', ready: 'Sẵn sàng', completed: 'Hoàn tất', cancelled: 'Đã hủy',
};

export function OrderCard({ order }: { order: StaffOrder }) {
  const [status, setOptimisticStatus] = useOptimistic(order.status);
  const [isPending, startTransition] = useTransition();
  const [error, setError] = useState('');
  const next = NEXT[status];

  const onAdvance = () => next && startTransition(async () => {
    setError('');
    setOptimisticStatus(next.to);                       // hiện ngay, chưa chờ server
    const result = await advanceStatus(order.orderId, next.to);
    if (!result.ok) setError(result.message ?? '');
  });

  return (
    <article className="rounded-xl border bg-white p-3">
      <p className="font-bold">#{order.orderId} · {order.customerName}</p>
      <p>{order.summary}</p>
      {order.note && <p className="text-amber-700">Ghi chú: {order.note}</p>}
      <p className="text-sm">Trạng thái: <strong>{LABEL[status]}</strong></p>
      {next && <button onClick={onAdvance} disabled={isPending}
        className="mt-2 rounded bg-blue-900 px-3 py-1 text-white">{next.label}</button>}
      {error && <p role="alert" className="text-sm text-red-600">{error}</p>}
    </article>
  );
}
  • Trạng thái hiện bằng chữ, không chỉ bằng màu (người mù màu vẫn đọc được).
  • Nút "Hủy đơn" chỉ hiện với đơn pending/preparing, mở hộp thoại nhập lý do dùng useActionState(staffCancel, { ok: false }).
  • Xung đột 409: khi hai nhân viên cùng bấm, API chỉ nhận người đầu; người sau thấy thông báo và danh sách được làm mới nhờ revalidatePath.
  • Tạm thời làm mới danh sách mỗi 15 giây bằng một Client Component gọi router.refresh() trong setInterval. Bài 09 thay bằng Socket.IO để đơn mới hiện ngay lập tức.

🆘 4. Góc trợ giúp và mở rộng ▼

Bấm nút xong dữ liệu không đổi: quên revalidatePath hoặc đường dẫn truyền vào khác đường dẫn trang (ví dụ /admin/order thay vì /admin/orders).

Lỗi "An optimistic state update occurred outside a transition": gọi hàm cập nhật của useOptimistic ngoài startTransition hoặc ngoài form action.

Bảng báo lỗi hydration khi sắp xếp: định dạng ngày giờ bằng toLocaleString() cho kết quả khác nhau giữa server và trình duyệt. Truyền rõ 'vi-VN' và múi giờ, hoặc định dạng sẵn ở Server Component.

Đơn mới không hiện: GET /orders/staff chỉ trả đơn trong ngày; kiểm tra giờ của máy chủ API và tham số date.

Kiến thức mở rộng: revalidateTag để làm mới theo nhóm dữ liệu thay vì theo đường dẫn; âm báo khi có đơn mới bằng Web Audio API (cần người dùng tương tác trước).
