BÀI 10 - Kiểm thử ứng dụng web, hiệu năng & accessibility (5 tiết: 2 LT / 3 TH)

Ba sprint qua, nhóm đã viết gần 50 test case và chạy tay từng cái. Mỗi lần sửa một dòng mã, chạy lại hết mất cả buổi, nên không ai chạy lại. Hôm nay máy làm việc đó: bấm một lệnh, 30 giây sau biết ngay chức năng nào vừa hỏng. Và câu hỏi khó hơn: AI viết test cho bạn trong một phút, nhưng làm sao biết test đó thật sự kiểm tra được gì?

Mục tiêu: Lập được kế hoạch kiểm thử và ma trận truy vết yêu cầu – test case – kết quả; thực hiện được kiểm thử đơn vị, component và đầu-cuối; kiểm chứng được giá trị của test bằng đột biến thủ công; đo và cải thiện được hiệu năng, SEO, accessibility; lập được báo cáo kiểm thử.

Nội dung:

  • Ý chính 1 - Kế hoạch kiểm thử và ma trận truy vết: chọn mức kiểm thử cho từng yêu cầu, truy vết tới tiêu chí nghiệm thu.
  • Ý chính 2 - Vitest và Testing Library: kiểm thử hàm, schema, component, Server Action với API giả.
  • Ý chính 3 - Playwright: kịch bản đầu-cuối nhiều vai trò, báo cáo HTML, đột biến thủ công để kiểm chứng test do AI sinh.
  • Ý chính 4 - Hiệu năng, SEO và accessibility: Lighthouse, Core Web Vitals, next/image, metadata, sitemap, nhãn form, bàn phím, tương phản.

Kết quả cần đạt: Dự án có bộ test tự động chạy bằng một lệnh, một kịch bản Playwright cho luồng đặt món, số đo Lighthouse trước và sau tối ưu; nhóm có bản nháp báo cáo kiểm thử.

CLO liên quan: CLO2.

2.2. Vitest và Testing Library

npm install -D vitest @vitejs/plugin-react jsdom vite-tsconfig-paths \
  @testing-library/react @testing-library/dom @testing-library/user-event

// vitest.config.mts
import { defineConfig } from 'vitest/config';
import react from '@vitejs/plugin-react';
import tsconfigPaths from 'vite-tsconfig-paths';

export default defineConfig({
  plugins: [tsconfigPaths(), react()],        // hiểu alias @/ của Next.js
  test: { environment: 'jsdom', exclude: ['e2e/**', 'node_modules/**'] },
});

// package.json → "scripts": { "test": "vitest run", "test:watch": "vitest" }
// lib/cart-store.test.ts: kiểm thử đơn vị, mỗi test gắn với một tiêu chí
import { beforeEach, describe, expect, it } from 'vitest';
import { useCart, cartTotal } from './cart-store';

const com = { id: 1, name: 'Cơm gà xối mỡ', price: 35000, isAvailable: true, stock: 10 } as any;

describe('Giỏ hàng (US-C01, US-C02)', () => {
  beforeEach(() => useCart.getState().clear());

  it('thêm cùng một món hai lần thì một dòng, số lượng 2', () => {
    useCart.getState().add(com);
    useCart.getState().add(com);
    expect(useCart.getState().items).toEqual([{ productId: 1, name: 'Cơm gà xối mỡ', price: 35000, quantity: 2 }]);
  });

  it('giảm số lượng về 0 thì xóa món', () => {
    useCart.getState().add(com);
    useCart.getState().setQuantity(1, 0);
    expect(useCart.getState().items).toHaveLength(0);
  });

  it('tổng tiền bằng tổng giá × số lượng', () => {
    expect(cartTotal([{ productId: 1, name: 'A', price: 35000, quantity: 2 }, { productId: 2, name: 'B', price: 15000, quantity: 1 }]))
      .toBe(85000);
  });
});
// components/add-to-cart-button.test.tsx: kiểm thử component
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { expect, it } from 'vitest';
import { AddToCartButton } from './add-to-cart-button';
import { useCart } from '@/lib/cart-store';

it('món hết hàng: nút ghi "Hết món" và không bấm được (US-G03)', async () => {
  render(<AddToCartButton product={{ id: 2, name: 'Bún bò', price: 40000, isAvailable: true, stock: 0 } as any} />);
  const button = screen.getByRole('button', { name: 'Hết món' });   // tìm như người dùng thấy
  expect((button as HTMLButtonElement).disabled).toBe(true);   // hoặc toBeDisabled() nếu cài @testing-library/jest-dom
  await userEvent.click(button);
  expect(useCart.getState().items).toHaveLength(0);
});
// app/(shop)/checkout/actions.test.ts: Server Action với API giả
import { afterEach, expect, it, vi } from 'vitest';
vi.mock('server-only', () => ({}));                                   // gói này chặn mọi môi trường ngoài server
vi.mock('@/lib/session', () => ({ getAccessToken: async () => 'token-gia' }));
import { placeOrder } from './actions';

afterEach(() => vi.unstubAllGlobals());

it('API trả 409 thì báo "Có món đã hết hoặc không đủ số lượng" (US-C04)', async () => {
  vi.stubGlobal('fetch', vi.fn(async () => new Response('{}', { status: 409 })));
  const result = await placeOrder({ items: [{ productId: 1, quantity: 99 }] });
  expect(result).toEqual({ ok: false, message: 'Có món đã hết hoặc không đủ số lượng' });
});

it('giỏ rỗng bị từ chối ngay ở server, không gọi API', async () => {
  const fetchMock = vi.fn();
  vi.stubGlobal('fetch', fetchMock);
  const result = await placeOrder({ items: [] });
  expect(result.ok).toBe(false);
  expect(fetchMock).not.toHaveBeenCalled();
});

Tìm phần tử bằng getByRole và tên hiển thị, không bằng class CSS: test vừa kiểm chức năng vừa kiểm luôn accessibility (nút không có tên thì không tìm được). Đặt tên test bằng tiếng Việt, theo tiêu chí nghiệm thu, để kết quả chạy dán thẳng vào báo cáo.

2.3. Playwright và kiểm chứng test do AI sinh

npm init playwright@latest        # chọn thư mục e2e, TypeScript

// playwright.config.ts (phần chính)
export default defineConfig({
  testDir: './e2e',
  use: { baseURL: 'http://localhost:3000', trace: 'on-first-retry' },
  webServer: { command: 'npm run build && npm run start', url: 'http://localhost:3000', reuseExistingServer: true },
  reporter: [['html', { open: 'never' }]],
});
// e2e/order-flow.spec.ts: hai vai trò, hai phiên trình duyệt độc lập
import { test, expect, type Page } from '@playwright/test';

async function login(page: Page, email: string, password: string) {
  await page.goto('/login');
  await page.getByLabel('Email').fill(email);
  await page.getByLabel('Mật khẩu').fill(password);
  await page.getByRole('button', { name: 'Đăng nhập' }).click();
}

test('khách đặt món, nhân viên nhận và chuyển sang Đang chuẩn bị (US-C04, S02, S03)', async ({ browser }) => {
  const customer = await (await browser.newContext()).newPage();
  const staff = await (await browser.newContext()).newPage();
  await login(customer, process.env.E2E_CUSTOMER_EMAIL!, process.env.E2E_CUSTOMER_PASSWORD!);
  await login(staff, process.env.E2E_STAFF_EMAIL!, process.env.E2E_STAFF_PASSWORD!);
  await expect(staff).toHaveURL(/\/admin\/orders/);

  const note = `E2E ${Date.now()}`;                         // dữ liệu riêng để tìm đúng đơn
  await customer.goto('/menu');
  await customer.getByRole('button', { name: 'Thêm vào giỏ' }).first().click();
  await customer.goto('/checkout');
  await customer.getByLabel('Ghi chú').fill(note);
  await customer.getByRole('button', { name: 'Đặt món' }).click();
  await expect(customer).toHaveURL(/\/orders\/\d+/);

  const card = staff.getByRole('article').filter({ hasText: note });
  await expect(card).toBeVisible({ timeout: 5000 });          // realtime: không tải lại trang
  await card.getByRole('button', { name: 'Bắt đầu làm' }).click();
  await expect(card).toContainText('Đang chuẩn bị');
});
  • Tài khoản thử đặt trong biến môi trường (.env.test, không commit); chạy trên CSDL thử, không chạy trên CSDL đang demo.
  • Chạy npx playwright test, xem báo cáo bằng npx playwright show-report. Ảnh chụp báo cáo HTML là minh chứng cho báo cáo kiểm thử.
  • npx playwright codegen localhost:3000 ghi lại thao tác thành mã: tiện để bắt đầu, nhưng phải sửa lại cách tìm phần tử theo vai trò và nhãn.

Đột biến thủ công (mutation): test do AI sinh có giá trị không? AI viết test rất nhanh, nhưng hay viết test "luôn đạt": kiểm tra lại đúng cái mã vừa làm, hoặc không có expect nào có ý nghĩa. Cách kiểm chứng: cố ý làm hỏng mã, chạy lại test.

Đột biến "lọt" nghĩa là chưa có test nào kiểm tra hành vi đó: viết thêm test, rồi hoàn tác đột biến. Ghi bảng đột biến vào báo cáo kiểm thử như bằng chứng bộ test có giá trị.

2.4. Hiệu năng, SEO và accessibility

Đo trên bản production (npm run build && npm start), cửa sổ ẩn danh, bằng Lighthouse trong Chrome DevTools. Bản npm run dev chậm hơn nhiều và không phản ánh thực tế.

// SEO: tiêu đề theo tên món
// app/(shop)/product/[id]/page.tsx
export async function generateMetadata({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const p = await apiGet<Product>(`/products/${id}`, 60);
  return { title: `${p.name} - LHU Food`, description: p.description ?? `Giá ${p.price.toLocaleString('vi-VN')} đ` };
}

// app/sitemap.ts: danh sách trang công khai cho công cụ tìm kiếm (không đưa /admin vào)
export default async function sitemap() {
  const products = await apiGet<Product[]>('/products?pageSize=100', 3600);
  return [{ url: `${process.env.SITE_URL}/menu` },
          ...products.map((p) => ({ url: `${process.env.SITE_URL}/product/${p.id}` }))];
}

Accessibility (khả năng tiếp cận): mọi người dùng được, kể cả người dùng bàn phím, trình đọc màn hình, người nhìn kém.

  • Mỗi ô nhập có <label>; lỗi gắn với ô bằng aria-describedby; thông báo chung có role="alert".
  • Dùng được hoàn toàn bằng bàn phím: Tab đi đúng thứ tự, thấy rõ ô đang được chọn, hộp thoại giữ tiêu điểm bên trong (shadcn/ui đã làm sẵn).
  • Tương phản chữ/nền tối thiểu 4,5:1; trạng thái không chỉ dùng màu; ảnh món có alt là tên món.
  • Kiểm tự động thêm bằng @axe-core/playwright trong kịch bản E2E; vẫn phải thử tay bằng bàn phím.

Báo cáo kiểm thử (CLO2) gồm: kế hoạch (phạm vi, mức, công cụ, môi trường, dữ liệu thử); ma trận truy vết; kết quả (số test, đạt, không đạt, ảnh báo cáo Vitest và Playwright); bảng đột biến; lỗi tìm được và cách khắc phục (liên kết thẻ trên board); số đo Lighthouse trước và sau tối ưu. Báo cáo này là Chương 5 của báo cáo đồ án.

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): Test tự động và đo Lighthouse

  1. Cài Vitest; viết test cho giỏ hàng, registerSchema (biên), AddToCartButton, placeOrder với API giả; chạy npm test.
  2. Cài Playwright; viết order-flow.spec.ts với hai phiên; xem báo cáo HTML.
  3. Thử ba đột biến ở bảng mục 2.3, ghi kết quả, hoàn tác.
  4. Đo Lighthouse trang /menu trên bản production; sửa ảnh (next/image, kích thước), thêm generateMetadata; đo lại, ghi bảng trước/sau.

✍️ Thực hành không hướng dẫn (1 tiết): 5 test có giá trị

Chọn một module bạn phụ trách (ví dụ quản lý quầy, hủy đơn, báo cáo). Viết 5 test tự động ở mức phù hợp, mỗi test truy vết tới một tiêu chí nghiệm thu. Được dùng AI để sinh test, nhưng phải kiểm chứng bằng ít nhất 3 đột biến thủ công.

Hoàn thành khi: nộp link repo, ảnh kết quả chạy test, bảng truy vết 5 test và bảng đột biến (đột biến nào lọt thì đã viết thêm test gì).

🆘 4. Góc trợ giúp và mở rộng ▼

Lỗi "This module cannot be imported from a Client Component module" khi chạy Vitest: file được test có import 'server-only'. Thêm vi.mock('server-only', () => ({})) ở đầu file test.

Test giỏ hàng ảnh hưởng lẫn nhau: store Zustand dùng chung giữa các test; gọi clear() trong beforeEach.

Playwright báo không tìm thấy phần tử dù trang có hiển thị: tên nút hoặc nhãn trong test khác chữ trên giao diện; thiếu <label> cho ô nhập. Sửa giao diện cho có nhãn là sửa luôn một lỗi accessibility.

Điểm Lighthouse dao động mỗi lần đo: đo 3 lần lấy trung vị, cùng máy, cùng chế độ (Mobile/Desktop), tắt tiện ích trình duyệt.

Kiến thức mở rộng: chạy test tự động trên GitHub Actions mỗi khi mở Pull Request; công cụ đột biến tự động Stryker cho JavaScript.

Tự đánh giá: Nếu xóa một dòng quan trọng bất kỳ trong module của bạn, có ít nhất một test chuyển sang đỏ không?
