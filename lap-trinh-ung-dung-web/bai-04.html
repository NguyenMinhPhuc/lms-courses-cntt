BÀI 04 - Client Components, trạng thái & form (5 tiết: 1 LT / 4 TH)

Thực đơn đã có món thật, nhưng khách vẫn chưa làm được gì ngoài nhìn. Hôm nay trang web bắt đầu "phản hồi": bấm thêm món thì giỏ hàng tăng, tải lại trang giỏ vẫn còn, điền sai email thì báo lỗi ngay dưới ô. Và câu hỏi khó hơn: kiểm tra dữ liệu ở trình duyệt rồi thì server có cần kiểm tra lại không?

Mục tiêu: Phân tích được phần nào của trang cần chạy phía client; xây dựng được giỏ hàng có lưu trạng thái; xây dựng được form kiểm tra dữ liệu ở cả client và server bằng một schema Zod dùng chung; gọi được API ghi dữ liệu và xử lý lỗi 400/409; thiết kế được test case giá trị biên cho form.

Nội dung:

  • Ý chính 1 - Client Component và "đảo tương tác": state, sự kiện, hook; giữ phần chạy ở trình duyệt nhỏ nhất.
  • Ý chính 2 - Trạng thái giỏ hàng: Zustand, lưu vào localStorage, tránh lỗi hydration.
  • Ý chính 3 - Form có kiểm tra dữ liệu: React Hook Form + Zod, một schema dùng cho cả form và Server Action.
  • Ý chính 4 - Ghi dữ liệu và kiểm thử form: đặt món qua API mẫu, hiển thị lỗi 400/409, bảng giá trị biên.

Kết quả cần đạt: Web có giỏ hàng (US-C01, C02), form đăng ký (US-G04) và trang đặt món (US-C04) chạy với API mẫu; mỗi form có bảng giá trị biên và test case kèm kết quả.

CLO liên quan: CLO1, CLO2.

📚 2. Học liệu chính ▼

2.1. Client Component và "đảo tương tác"

Trang chi tiết món vẫn là Server Component (lấy dữ liệu trên server, như bài 03). Chỉ nút "Thêm vào giỏ" cần biết người dùng bấm, nên chỉ nút đó là Client Component. Phần còn lại của trang không gửi JavaScript xuống trình duyệt.

// components/add-to-cart-button.tsx
'use client';
import { useCart } from '@/lib/cart-store';
import type { Product } from '@/lib/types';

export function AddToCartButton({ product }: { product: Product }) {
  const add = useCart((s) => s.add);
  const soldOut = !product.isAvailable || product.stock === 0;
  return (
    <button disabled={soldOut} onClick={() => add(product)}
      className="rounded bg-blue-900 px-4 py-2 text-white disabled:bg-slate-300">
      {soldOut ? 'Hết món' : 'Thêm vào giỏ'}
    </button>
  );
}

// app/(shop)/product/[id]/page.tsx (Server Component) chỉ cần:
//   <AddToCartButton product={product} />
  • Props truyền từ Server sang Client Component phải tuần tự hóa được (số, chuỗi, mảng, object thường). Không truyền hàm hay đối tượng Date.
  • Đặt "use client" ở lá của cây component, không đặt ở layout hay page. Một "use client" ở trên cao kéo cả nhánh con xuống trình duyệt.
  • Khi phân tích thành phần (CLO1), ghi rõ component nào chạy ở client và lý do: cần state, sự kiện hay API trình duyệt.

2.2. Trạng thái giỏ hàng với Zustand

Giỏ hàng được dùng ở nhiều nơi: nút thêm món, biểu tượng giỏ trên header, trang giỏ hàng. Dùng một store chung thay vì truyền props qua nhiều tầng. Middleware persist lưu giỏ vào localStorage nên tải lại trang vẫn còn.

// lib/cart-store.ts   (npm install zustand)
'use client';
import { create } from 'zustand';
import { persist } from 'zustand/middleware';
import type { Product } from './types';

export type CartItem = { productId: number; name: string; price: number; quantity: number };

type CartState = {
  items: CartItem[];
  add: (p: Product) => void;
  setQuantity: (productId: number, quantity: number) => void;
  clear: () => void;
};

export const useCart = create<CartState>()(
  persist(
    (set) => ({
      items: [],
      add: (p) => set((s) => {
        const found = s.items.find((i) => i.productId === p.id);
        return found
          ? { items: s.items.map((i) => i.productId === p.id ? { ...i, quantity: i.quantity + 1 } : i) }
          : { items: [...s.items, { productId: p.id, name: p.name, price: p.price, quantity: 1 }] };
      }),
      setQuantity: (productId, quantity) => set((s) => ({
        items: quantity <= 0
          ? s.items.filter((i) => i.productId !== productId)          // về 0 thì xóa (US-C02)
          : s.items.map((i) => i.productId === productId ? { ...i, quantity } : i),
      })),
      clear: () => set({ items: [] }),
    }),
    { name: 'lhu-food-cart' },
  ),
);

export const cartTotal = (items: CartItem[]) => items.reduce((t, i) => t + i.price * i.quantity, 0);

Lỗi hydration: server không có localStorage nên HTML từ server luôn có giỏ rỗng; trình duyệt đọc được giỏ 3 món. Hai bản HTML khác nhau thì React báo lỗi "Hydration failed". Cách xử lý: chỉ hiển thị số liệu giỏ sau khi component đã gắn vào trình duyệt.

// components/cart-badge.tsx
'use client';
import { useEffect, useState } from 'react';
import { useCart } from '@/lib/cart-store';

export function CartBadge() {
  const [mounted, setMounted] = useState(false);
  const count = useCart((s) => s.items.reduce((n, i) => n + i.quantity, 0));
  useEffect(() => setMounted(true), []);
  return <span className="rounded-full bg-amber-400 px-2 text-sm">{mounted ? count : 0}</span>;
}

Giỏ hàng chỉ lưu productId, tên, giá để hiển thị. Giá tính tiền thật luôn do backend lấy từ CSDL lúc đặt (tiêu chí US-C04), nên sửa localStorage cũng không đổi được giá.

2.3. Form với React Hook Form + Zod

Kiểm tra ở trình duyệt giúp người dùng sửa lỗi nhanh, nhưng ai cũng tắt được JavaScript hoặc gửi request thẳng tới server. Vì vậy server luôn kiểm tra lại. Viết schema Zod một lần trong lib/schemas.ts và dùng cho cả hai phía.

// lib/schemas.ts   (npm install zod react-hook-form @hookform/resolvers)
import { z } from 'zod';

export const registerSchema = z.object({
  fullName: z.string().trim().min(2, 'Họ tên tối thiểu 2 ký tự').max(100, 'Họ tên tối đa 100 ký tự'),
  email: z.string().trim().toLowerCase().email('Email không đúng định dạng'),
  password: z.string().min(8, 'Mật khẩu tối thiểu 8 ký tự'),
  confirm: z.string(),
}).refine((d) => d.password === d.confirm, { path: ['confirm'], message: 'Mật khẩu nhập lại không khớp' });

export type RegisterInput = z.infer<typeof registerSchema>;
// app/(shop)/register/actions.ts: Server Action, chạy trên server
'use server';
import { registerSchema, type RegisterInput } from '@/lib/schemas';

export type ActionResult = { ok: boolean; message?: string };

export async function registerAction(input: RegisterInput): Promise<ActionResult> {
  const parsed = registerSchema.safeParse(input);               // kiểm tra lại ở server
  if (!parsed.success) return { ok: false, message: parsed.error.issues[0].message };

  const { confirm, ...body } = parsed.data;
  const res = await fetch(`${process.env.API_URL}/auth/register`, {
    method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body),
  });
  if (res.status === 409) return { ok: false, message: 'Email đã được sử dụng' };
  if (!res.ok) return { ok: false, message: 'Đăng ký chưa thành công, vui lòng thử lại' };
  return { ok: true };
}
// app/(shop)/register/register-form.tsx
'use client';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { useRouter } from 'next/navigation';
import { useState } from 'react';
import { registerSchema, type RegisterInput } from '@/lib/schemas';
import { registerAction } from './actions';

export function RegisterForm() {
  const router = useRouter();
  const [serverError, setServerError] = useState('');
  const { register, handleSubmit, formState: { errors, isSubmitting } } =
    useForm<RegisterInput>({ resolver: zodResolver(registerSchema) });

  const onSubmit = async (data: RegisterInput) => {
    const result = await registerAction(data);
    if (result.ok) router.push('/login?registered=1');
    else setServerError(result.message ?? '');
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-3">
      <label className="block">Họ tên
        <input {...register('fullName')} className="w-full rounded border px-3 py-2" />
      </label>
      {errors.fullName && <p className="text-sm text-red-600">{errors.fullName.message}</p>}
      {/* email, password, confirm: tương tự */}
      {serverError && <p role="alert" className="text-red-600">{serverError}</p>}
      <button disabled={isSubmitting} className="rounded bg-blue-900 px-4 py-2 text-white">
        {isSubmitting ? 'Đang gửi…' : 'Đăng ký'}
      </button>
    </form>
  );
}
  • Server Action là hàm async trong file 'use server'; Client Component gọi nó như hàm bình thường, Next.js tự tạo request POST. Bài 06 học kỹ hơn.
  • Lỗi hiện dưới từng ô, bằng tiếng Việt, gắn với nhãn của ô (tiêu chí US-G04). Lỗi từ server (409) hiện ở một chỗ chung có role="alert".
  • Nút gửi bị vô hiệu khi đang gửi để tránh gửi hai lần.

2.4. Đặt món qua API mẫu và kiểm thử form

POST /orders cần đăng nhập. Bài 05 mới làm đăng nhập, nên hôm nay lấy tạm một access token ở trang /docs của API mẫu (đăng nhập bằng tài khoản thử, chép accessToken) và đọc qua một hàm duy nhất. Bài 05 chỉ cần sửa hàm này để đọc từ cookie.

// lib/session.ts: TẠM THỜI cho bài 04, bài 05 thay bằng cookie
import 'server-only';
export async function getAccessToken() {
  return process.env.DEV_ACCESS_TOKEN;   // token hết hạn sau 15 phút: lấy lại ở /docs khi gặp 401
}

// app/(shop)/checkout/actions.ts
'use server';
import { z } from 'zod';
import { getAccessToken } from '@/lib/session';

const orderSchema = z.object({
  items: z.array(z.object({ productId: z.number().int().positive(), quantity: z.number().int().min(1).max(50) }))
          .min(1, 'Giỏ hàng đang trống'),
  note: z.string().trim().max(200, 'Ghi chú tối đa 200 ký tự').optional(),
});

export async function placeOrder(input: z.infer<typeof orderSchema>) {
  const parsed = orderSchema.safeParse(input);
  if (!parsed.success) return { ok: false as const, message: parsed.error.issues[0].message };

  const res = await fetch(`${process.env.API_URL}/orders`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${await getAccessToken()}` },
    body: JSON.stringify(parsed.data),
  });
  if (res.status === 409) return { ok: false as const, message: 'Có món đã hết hoặc không đủ số lượng' };
  if (res.status === 401) return { ok: false as const, message: 'Bạn cần đăng nhập để đặt món' };
  if (!res.ok) return { ok: false as const, message: 'Đặt món chưa thành công, vui lòng thử lại' };
  const order: { orderId: number } = await res.json();
  return { ok: true as const, orderId: order.orderId };
}

Trang /checkout (Client Component) lấy items từ useCart, gửi kèm ghi chú; thành công thì clear() giỏ và chuyển tới /orders/{orderId}. API trả lỗi theo dạng { statusCode, message, error }; với lỗi 400, message có thể là mảng chi tiết từng trường.

Phân tích giá trị biên (CLO2). Mỗi ràng buộc trong schema cho ít nhất hai test case: ngay dưới biên (sai) và đúng biên (đạt).

🆘 4. Góc trợ giúp và mở rộng ▼

Lỗi "useState only works in Client Components": file dùng hook nhưng thiếu 'use client' ở dòng đầu. Thêm vào component lá, không thêm vào page.

Lỗi "Hydration failed" ở biểu tượng giỏ hàng: HTML server (giỏ rỗng) khác HTML trình duyệt (giỏ có món). Dùng cờ mounted như mục 2.2.

Form không báo lỗi gì khi bấm gửi: quên resolver: zodResolver(schema) hoặc tên trong register('...') không khớp tên trường của schema.

Đặt món trả 401: token tạm đã hết hạn (15 phút). Lấy token mới ở /docs rồi khởi động lại npm run dev. Bài 05 sẽ bỏ hẳn bước này.

Kiến thức mở rộng: useTransition để giữ giao diện phản hồi khi chờ Server Action; hộp thoại xác nhận của shadcn/ui (AlertDialog) trước khi xóa món khỏi giỏ.

Tự đánh giá: Nếu xóa toàn bộ phần kiểm tra ở trình duyệt, form của bạn có còn từ chối dữ liệu sai không?
