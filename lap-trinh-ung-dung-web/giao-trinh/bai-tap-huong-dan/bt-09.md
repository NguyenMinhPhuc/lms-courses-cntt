## Bài tập hướng dẫn theo dự án LHU Food

**Nhiệm vụ:** chuyển màn hình quầy từ làm mới định kỳ sang Socket.IO có xác thực; bổ sung backend nhóm để đồng bộ nhiều nhân viên; vẽ sơ đồ tuần tự; kiểm thử realtime; hoàn thành Checkpoint Sprint 3.

- **Tài liệu dùng kèm:** SRS mục 4.6 (US-SYS01), 4.7 (tiêu chí US-S02, S03), 5.9 (F08.1 kết nối và xác thực socket), 5.10 (F09.1–F09.2); giáo trình di động Chương 9 (Socket.IO trong NestJS).
- **User story:** US-S02, US-S03, US-SYS01.
- **Thời lượng gợi ý:** 1,5 tiết trên lớp, 1 tiết Checkpoint.

### Chuẩn bị môi trường

```bash
git checkout main && git pull
git checkout -b feature/realtime-counter
npm install socket.io-client
```

Thêm `NEXT_PUBLIC_SOCKET_URL` vào `.env.local` và `.env.example`. Kiểm tra backend nhóm dùng `socket.io` v4 (`npm ls socket.io`). Chuẩn bị điện thoại cài ứng dụng di động của nhóm, trỏ tới cùng backend.

### Các bước triển khai

**Bước 1. Backend.** Gateway đưa `admin` vào room `staff`; phát `order:updated` sau đổi trạng thái và hủy đơn; mở CORS cho địa chỉ web (mục 9.3.3).

**Bước 2. Route Handler.** `/api/socket-token` (mục 9.2.2), thêm vào `matcher` của `proxy.ts`.

**Bước 3. Màn hình quầy.** `OrdersRealtime` (mục 9.3.1) ở đầu `/admin/orders`; xóa bộ hẹn giờ 15 giây.

**Bước 4. Sơ đồ tuần tự.** Vẽ luồng đặt món – xử lý và luồng xung đột 409, lưu file nguồn và ảnh trong `docs/`.

**Bước 5. Kiểm thử.** Chạy TC-51…TC-56 với hai cửa sổ web và một điện thoại; ghi kết quả vào `docs/test/sprint-3-realtime.md`.

**Bước 6. Checkpoint Sprint 3.** Demo quản trị và màn hình quầy realtime (web và mobile cùng backend); nộp phân tích module quản trị, ERD quản trị, danh mục thủ tục, sơ đồ tuần tự, test case và kết quả, báo cáo Sprint 3, kế hoạch Sprint 4.

### Vibe coding

```text
Đọc AGENTS.md. Tạo app/admin/orders/orders-realtime.tsx là Client Component dùng socket.io-client v4.
Tạo socket trong useEffect, dọn bằng socket.disconnect(). Option auth là HÀM gọi fetch('/api/socket-token')
rồi cb({ token }). Khi connect: router.refresh(); khi order:new và order:updated: router.refresh();
khi connect_error: setTimeout 3 giây rồi socket.connect(). Hiển thị trạng thái kết nối bằng chữ trong
phần tử aria-live="polite". KHÔNG đọc token từ document.cookie hay localStorage,
KHÔNG chèn dữ liệu sự kiện trực tiếp vào danh sách đơn.
```

Kiểm tra kết quả AI:

- Socket được tạo trong `useEffect` và có hàm dọn dẹp; tạo ngoài `useEffect` gây nhiều kết nối trùng, nhận mỗi sự kiện nhiều lần.
- `auth` là hàm, không phải object cố định chứa token.
- Có xử lý `connect_error` để kết nối lại; thiếu thì màn hình "chết" sau khi token hết hạn.
- Thử TC-53 bằng chế độ Offline của DevTools để chắc chắn đơn lỡ được bù.

### Kiểm tra và hoàn thành
