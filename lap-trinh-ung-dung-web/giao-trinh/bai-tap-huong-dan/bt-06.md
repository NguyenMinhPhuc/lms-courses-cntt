## Bài tập hướng dẫn theo dự án LHU Food

**Nhiệm vụ:** xây màn hình quầy và bảng món cho nhân viên bằng Server Actions; kiểm thử luồng khách đặt → nhân viên xử lý; hoàn thành Checkpoint Sprint 2.

- **Tài liệu dùng kèm:** SRS mục 4.7 (tiêu chí US-S02, S03, C08), mục 6.1 (sơ đồ trạng thái, BR-15), mục 8 (`/orders/staff`, `/orders/:id/status`, `/orders/:id/staff-cancel`, `/products/:id/availability`); Kế hoạch Agile (velocity, release burndown).
- **User story:** US-S02, US-S03, US-S04, US-S06, US-S07.
- **Thời lượng gợi ý:** 1,5 tiết trên lớp, 1 tiết Checkpoint.

### Chuẩn bị môi trường

```bash
git checkout main && git pull
git checkout -b feature/counter-screen
npm install @tanstack/react-table
npx shadcn@latest add table badge alert-dialog
```

Đăng nhập được bằng tài khoản staff của API mẫu (Chương 5). Chuẩn bị một cửa sổ ẩn danh để đăng nhập tài khoản khác cùng lúc.

### Các bước triển khai

**Bước 1. Server Actions.** `app/admin/orders/actions.ts` với `advanceStatus`, `staffCancel` (mục 6.1.2).

**Bước 2. Màn hình quầy.** Trang `/admin/orders` ba cột; `OrderCard` (mục 6.3.3); `CancelForm` trong `AlertDialog` (mục 6.1.3); lọc `?status=`; Client Component làm mới mỗi 15 giây bằng `router.refresh()`.

**Bước 3. Bảng món.** Trang `/admin/products` (mục 6.2), Server Action `toggleAvailability`.

**Bước 4. Kiểm thử luồng.** Chạy TC-31…TC-37 với hai trình duyệt, ghi kết quả vào `docs/test/sprint-2-luong.md`; xác nhận tồn kho ở TC-35 bằng Swagger.

**Bước 5. Velocity.** Cập nhật bảng velocity Sprint 1–2 từ board.

**Bước 6. Checkpoint Sprint 2.** Demo luồng đặt món → xử lý; nộp ma trận phân quyền, sơ đồ trạng thái, test case có kết quả, báo cáo Sprint 2, kế hoạch Sprint 3 và bản nháp báo cáo vai trò cá nhân.

### Vibe coding

```text
Đọc AGENTS.md và app/admin/orders/actions.ts. Tạo app/admin/orders/order-card.tsx là Client Component:
nhận order (orderId, status, note, customerName, summary), dùng useOptimistic cho status và
useTransition; nút hiển thị theo bảng pending→"Bắt đầu làm", preparing→"Đã xong", ready→"Đã giao";
bấm thì gọi advanceStatus trong startTransition, lỗi hiện trong <p role="alert">.
Trạng thái hiển thị bằng chữ tiếng Việt. KHÔNG gọi fetch trực tiếp tới API, KHÔNG cho chuyển ngược trạng thái.
```

Kiểm tra kết quả AI:

- `setOptimisticStatus` được gọi trong `startTransition` (thiếu sẽ có cảnh báo của React).
- Server Action có `requireRole`; AI hay bỏ qua vì "trang đã được bảo vệ".
- Không có nút chuyển ngược trạng thái hay nhảy cóc (`pending` → `ready`).
- Thử TC-34 thật bằng hai cửa sổ để thấy thông báo xung đột.
