## Bài tập hướng dẫn theo dự án LHU Food

**Nhiệm vụ:** bổ sung vai trò admin, khóa tài khoản và quản trị danh mục vào backend của nhóm; xây trang quản lý danh mục trên web; chuyển web sang backend nhóm và chạy kiểm thử hồi quy.

- **Tài liệu dùng kèm:** SRS mục 5.12 (M11, F11.1–F11.4), 6 (BR-16), 7 (dữ liệu), 8 (các endpoint `/admin`); giáo trình di động Chương 5 (DatabaseService), Chương 6 (RolesGuard), Chương 7 (script theo phiên bản).
- **User story:** US-A01, US-A03, US-A04 (phần backend).
- **Thời lượng gợi ý:** 1,5 tiết trên lớp, phần chuyển backend làm ở nhà.

### Chuẩn bị môi trường

```bash
# Repo backend của nhóm
git checkout main && git pull
git checkout -b feature/admin-module

# Repo web
git checkout main && git pull
git checkout -b feature/team-backend
```

Backend nhóm chạy được trên máy (`npm run start:dev`), mở được Swagger tại `/api`; có quyền chạy script trên CSDL của nhóm bằng SSMS.

### Các bước triển khai

**Bước 1. Bảng năm tầng.** Điền bảng mục 7.1.1 cho các story quản trị nhóm làm; ghi khoảng trống của backend hiện tại (mục 7.1.2) vào `docs/phan-tich-quan-tri.md`.

**Bước 2. Script.** Viết `database/20-admin.sql` (mục 7.2.2 và 7.3.1). Chạy **hai lần liên tiếp** để chứng minh chạy lại không lỗi. Viết script seed tạo tài khoản admin đầu tiên.

**Bước 3. Thử thủ tục.** Trong SSMS: tạo danh mục trùng tên (50409), xóa danh mục còn món (50409), tự khóa chính mình (50400).

**Bước 4. API.** `AdminCategoriesController`, `CategoryDto`; cập nhật `RolesGuard` và `AuthService` (mục 7.4.2, 7.4.3). Thử trên Swagger bằng token admin (thành công) và token staff (403).

**Bước 5. Trang web.** `/admin/categories`: danh sách, thêm, sửa, xóa có xác nhận, gọi backend nhóm.

**Bước 6. Chuyển backend.** Lập bảng so khớp hợp đồng (mục 7.5.1), sửa backend hoặc thêm hàm chuyển đổi; đổi `API_URL`; chạy lại test case Sprint 1–2 và ghi kết quả.

### Vibe coding

```text
Backend NestJS dùng DatabaseService.execute(procedureName, params) để gọi stored procedure (mssql).
Tạo AdminCategoriesController tại route admin/categories: @UseGuards(AuthGuard, RolesGuard), @Roles(['admin']),
POST tạo, PUT :id sửa, DELETE :id xóa (204); mỗi phương thức gọi đúng một thủ tục
sp_Category_Create / sp_Category_Update / sp_Category_Delete với tham số có kiểu sql.NVarChar, sql.Int.
DTO CategoryDto dùng class-validator (2–100 ký tự) và @ApiProperty.
KHÔNG viết câu SQL trong controller, KHÔNG dùng ORM, KHÔNG tự bắt lỗi 50409 (DatabaseService đã chuyển).
```

Kiểm tra kết quả AI:

- Không có câu `SELECT/INSERT/DELETE` ghép chuỗi trong mã TypeScript; mọi truy cập CSDL qua thủ tục.
- Thủ tục dùng `THROW` với mã 50400/50404/50409; AI hay dùng `RAISERROR` hoặc mã khác khiến API trả 500.
- Script đổi cấu trúc có kiểm tra trước; AI hay viết `ALTER TABLE ... ADD` trần, chạy lần hai sẽ lỗi.
- `@ActorId` lấy từ `req.user.sub`, không từ body.

### Kiểm tra và hoàn thành

- ☐ `20-admin.sql` chạy hai lần liên tiếp không lỗi; có script seed admin.
- ☐ Swagger có nhóm "Admin - Categories"; token staff nhận 403.
- ☐ Web chạy trên backend nhóm; bảng hồi quy Sprint 1–2 có kết quả, lỗi hồi quy có thẻ trên board.
- ☐ `docs/` có bảng năm tầng, ERD phần quản trị, danh mục stored procedure.
