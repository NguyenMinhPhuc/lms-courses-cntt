BÀI 09 - Màn hình quầy thời gian thực với Socket.IO (5 tiết: 1 LT / 4 TH) · Checkpoint Sprint 3

Màn hình quầy đang tự tải lại 15 giây một lần. Giờ cao điểm, 15 giây là đủ để ba sinh viên đứng chờ trước quầy mà nhân viên chưa thấy đơn. Hôm nay đơn đặt từ điện thoại hiện lên màn hình quầy trong chưa đầy một giây, kèm tiếng "ting". Hai nhân viên đứng hai đầu quầy luôn thấy cùng một danh sách.

Mục tiêu: Tích hợp được Socket.IO vào Client Component có xác thực; xử lý được kết nối lại và token hết hạn; phân tích được luồng realtime giữa web, mobile và backend bằng sơ đồ tuần tự; kiểm thử được realtime với nhiều phiên; báo cáo được kết quả Sprint 3 và điều chỉnh kế hoạch Sprint 4.

Nội dung:

  • Ý chính 1 - Socket.IO trong Next.js: chỉ chạy ở Client Component, lấy token kết nối từ server, kết nối lại.
  • Ý chính 2 - Màn hình quầy realtime: order:new kèm âm báo, order:updated đồng bộ nhiều nhân viên, làm mới dữ liệu khi kết nối lại.
  • Ý chính 3 - Sơ đồ tuần tự: luồng realtime web và mobile trên cùng backend.
  • Ý chính 4 - Kiểm thử realtime và báo cáo Sprint 3: nhiều tab, mất mạng, token hết hạn; kế hoạch Sprint 4.

Kết quả cần đạt: Màn hình quầy nhận đơn mới ngay lập tức (US-S02) và đồng bộ trạng thái giữa các nhân viên (US-S03); nhóm demo được web và mobile cùng chạy trên backend nhóm và hoàn thành Checkpoint Sprint 3.

CLO liên quan: CLO1, CLO2, CLO3, CLO4.

📚 2. Học liệu chính ▼

2.1. Socket.IO trong Next.js

Hai quy tắc của Chương 9 giáo trình di động vẫn giữ nguyên trên web: socket chỉ để báo tin (mọi thao tác ghi vẫn qua REST API và stored procedure), và lưu trước, gửi sau. Điểm khác trên web:

  • Kết nối socket sống trong trình duyệt, nên chỉ tạo trong Client Component, trong useEffect, và đóng khi component bị gỡ.
  • Access token nằm trong cookie httpOnly (bài 05), JavaScript không đọc được. Client xin token qua một Route Handler cùng tên miền. Token chỉ được giữ trong bộ nhớ của kết nối, không ghi vào localStorage.
  • Server từ chối kết nối khi token sai hoặc hết hạn (lỗi connect_error), và trong trường hợp này client không tự kết nối lại. Phải xin token mới rồi gọi socket.connect().
// app/api/socket-token/route.ts: trả access token hiện tại cho kết nối socket
import { getCurrentUser } from '@/lib/dal';
import { getAccessToken } from '@/lib/session';

export async function GET() {
  const user = await getCurrentUser();                       // backend xác minh token
  if (!user || (user.role !== 'staff' && user.role !== 'admin')) return Response.json({}, { status: 401 });
  return Response.json({ token: await getAccessToken() }, { headers: { 'Cache-Control': 'no-store' } });
}
// Thêm '/api/socket-token' vào matcher của proxy.ts để access token hết hạn được làm mới trước khi tới đây
# .env.local: địa chỉ socket không phải bí mật nên được dùng NEXT_PUBLIC_
NEXT_PUBLIC_SOCKET_URL=http://<địa-chỉ-backend-nhóm>:3000

npm install socket.io-client      # cùng phiên bản chính với server (v4)

2.2. Màn hình quầy realtime

Danh sách đơn vẫn do Server Component lấy từ GET /orders/staff (bài 06). Client Component dưới đây chỉ lắng nghe sự kiện, và khi có tin thì gọi router.refresh() để Server Component lấy lại danh sách. Dữ liệu luôn đến từ API, socket chỉ là "chuông báo".

// app/admin/orders/orders-realtime.tsx
'use client';
import { useEffect, useRef, useState } from 'react';
import { useRouter } from 'next/navigation';
import { io } from 'socket.io-client';

type Conn = 'connecting' | 'online' | 'offline';
const LABEL: Record<Conn, string> = { connecting: 'Đang kết nối…', online: 'Đang nhận đơn trực tiếp', offline: 'Mất kết nối, đang thử lại…' };

export function OrdersRealtime() {
  const router = useRouter();
  const [conn, setConn] = useState<Conn>('connecting');
  const [lastOrder, setLastOrder] = useState<number | null>(null);
  const soundOn = useRef(false);

  useEffect(() => {
    const socket = io(process.env.NEXT_PUBLIC_SOCKET_URL!, {
      transports: ['websocket'],
      // auth dạng hàm: được gọi lại ở MỖI lần (kết nối lại), nên luôn có token mới
      auth: (cb) => {
        fetch('/api/socket-token', { cache: 'no-store' })
          .then((r) => (r.ok ? r.json() : { token: '' }))
          .then((d) => cb({ token: d.token }));
      },
    });

    socket.on('connect', () => { setConn('online'); router.refresh(); });   // bù các đơn lỡ khi mất kết nối
    socket.on('disconnect', () => setConn('offline'));
    socket.on('connect_error', () => {
      setConn('offline');
      setTimeout(() => socket.connect(), 3000);              // token bị từ chối: tự thử lại
    });
    socket.on('order:new', (e: { orderId: number }) => {
      setLastOrder(e.orderId);
      if (soundOn.current) beep();
      router.refresh();
    });
    socket.on('order:updated', () => router.refresh());     // nhân viên khác vừa đổi trạng thái

    return () => { socket.disconnect(); };
  }, [router]);

  return (
    <div className="flex items-center gap-3">
      <p aria-live="polite" className="text-sm">{LABEL[conn]}{lastOrder && ` · Đơn mới nhất #${lastOrder}`}</p>
      <button onClick={() => { soundOn.current = true; beep(); }} className="rounded border px-2 py-1 text-sm">
        Bật âm báo
      </button>
    </div>
  );
}

function beep() {
  const ctx = new AudioContext();
  const osc = ctx.createOscillator();
  osc.frequency.value = 880;
  osc.connect(ctx.destination);
  osc.start();
  osc.stop(ctx.currentTime + 0.2);
}
  • Bỏ bộ hẹn giờ 15 giây của bài 06; đặt <OrdersRealtime /> ở đầu trang /admin/orders.
  • Âm báo cần người dùng bấm trước: trình duyệt chặn phát âm thanh khi chưa có tương tác, nên có nút "Bật âm báo" ở đầu ca.
  • Trạng thái kết nối hiện bằng chữ, có aria-live: nhân viên biết khi nào màn hình không còn "trực tiếp".
  • Ở chế độ phát triển, React Strict Mode chạy useEffect hai lần. Thấy kết nối rồi ngắt ngay một lần là bình thường, nhờ hàm dọn dẹp socket.disconnect().
  • Backend nhóm cần bổ sung (nếu làm theo Chương 9 di động): gateway cho cả admin vào room staff; phát toStaff('order:updated', { orderId, status }) sau khi đổi trạng thái hoặc hủy đơn. API mẫu của giảng viên đã làm sẵn hai việc này.

2.3. Sơ đồ tuần tự: web và mobile trên cùng backend

Sơ đồ tuần tự là phần phân tích bắt buộc của Checkpoint 3 (CLO1). Nó cho thấy ai gọi ai, theo thứ tự nào, qua kênh nào (REST hay socket):

2.4. Kiểm thử realtime và báo cáo Sprint 3

Realtime không kiểm được bằng một trình duyệt. Chuẩn bị: hai cửa sổ web (một thường, một ẩn danh) đăng nhập hai tài khoản staff, một điện thoại chạy ứng dụng di động của nhóm đăng nhập customer.

🆘 4. Góc trợ giúp và mở rộng ▼

Kết nối bị từ chối liên tục: mở /api/socket-token trên trình duyệt xem có trả token không; kiểm tra backend dùng cùng JWT_SECRET cho REST và socket; phiên bản socket.io-client cùng phiên bản chính với server.

Lỗi CORS khi kết nối socket: khác với REST, socket kết nối thẳng từ trình duyệt tới backend. Thêm địa chỉ web (ví dụ http://localhost:3001) vào cấu hình CORS của gateway Socket.IO.

Nhận mỗi sự kiện hai lần: tạo socket ngoài useEffect hoặc thiếu socket.disconnect() ở hàm dọn dẹp, nên mỗi lần render thêm một kết nối.

Nhân viên không nhận order:new nhưng khách vẫn nhận order:status: tài khoản chưa được đưa vào room staff (kiểm tra vai trò, đặc biệt admin), hoặc backend phát vào sai tên room.

Kiến thức mở rộng: "vé kết nối" (socket ticket) sống 30 giây do backend cấp, thay cho việc đưa access token xuống trình duyệt; Redis adapter để Socket.IO chạy trên nhiều máy chủ.

Tự đánh giá: Rút dây mạng màn hình quầy trong một phút giờ cao điểm. Khi cắm lại, nhân viên có thấy đủ mọi đơn không? Test case nào của nhóm chứng minh điều đó?
