BÀI 05 - Xác thực, phân quyền & bảo mật web (5 tiết: 2 LT / 3 TH)

Một sinh viên gõ thẳng /admin/products vào thanh địa chỉ. Menu quản trị đã bị ẩn, nhưng trang vẫn mở ra và nút "Xóa món" vẫn bấm được. Ẩn menu không phải là phân quyền. Hôm nay ta làm đăng nhập thật, giữ token ở nơi JavaScript không đọc được, và kiểm tra quyền ở mọi lớp.

Mục tiêu: Phân tích được yêu cầu phân quyền theo vai trò thành ma trận; triển khai được đăng nhập bằng JWT của backend với cookie httpOnly; bảo vệ được route bằng proxy và kiểm tra lại quyền ở server; nhận diện được các lỗ hổng web phổ biến; kiểm thử được các tình huống truy cập trái phép.

Nội dung:

  • Ý chính 1 - Luồng xác thực web: đăng nhập qua Server Action, access/refresh token trong cookie httpOnly, Secure, SameSite.
  • Ý chính 2 - Phân quyền theo vai trò: ma trận vai trò × chức năng, proxy.ts chặn route, kiểm tra lại ở server.
  • Ý chính 3 - Làm mới token và đăng xuất: gọi API kèm token từ server, refresh khi access token hết hạn.
  • Ý chính 4 - Bảo mật web và test case: XSS, CSRF, CORS, lộ biến NEXT_PUBLIC_*, open redirect, OWASP Top 10.

Kết quả cần đạt: Web đăng nhập được bằng tài khoản của API mẫu (US-G05, US-S01), khu quản trị chỉ mở cho đúng vai trò, đăng xuất thu hồi token (US-C13); nhóm có ma trận phân quyền và bộ test case truy cập trái phép kèm kết quả.

CLO liên quan: CLO1, CLO2.

📚 2. Học liệu chính ▼

2.1. Luồng xác thực và cookie httpOnly

Trình duyệt ──form──▶ Server Action (Next.js) ──POST /auth/login──▶ API
           ◀─Set-Cookie: access_token, refresh_token (httpOnly)───┘
Các request sau: trình duyệt tự gửi cookie ▶ Next.js đọc cookie ▶ gọi API với
                 Authorization: Bearer <access_token>

Ứng dụng di động lưu token bằng SecureStore. Trên web, nơi tương đương là cookie httpOnly: trình duyệt tự gửi kèm mỗi request nhưng JavaScript trong trang không đọc được, nên một đoạn mã XSS không lấy cắp được token. Không lưu token trong localStorage.

// lib/session.ts: thay bản tạm của bài 04
import 'server-only';
import { cookies } from 'next/headers';

const base = {
  httpOnly: true,                                   // JavaScript không đọc được
  secure: process.env.NODE_ENV === 'production',    // chỉ gửi qua HTTPS khi chạy thật
  sameSite: 'lax' as const,                         // không gửi kèm request POST từ trang khác
  path: '/',
};

export type Tokens = { accessToken: string; refreshToken: string };

export async function setAuthCookies(t: Tokens) {
  const c = await cookies();
  c.set('access_token', t.accessToken, { ...base, maxAge: 14 * 60 });          // JWT sống 15 phút
  c.set('refresh_token', t.refreshToken, { ...base, maxAge: 7 * 24 * 3600 });  // 7 ngày
}

export async function getAccessToken() {
  return (await cookies()).get('access_token')?.value;
}

export async function clearAuthCookies() {
  const c = await cookies();
  c.delete('access_token');
  c.delete('refresh_token');
}
// app/(shop)/login/actions.ts
'use server';
import { redirect } from 'next/navigation';
import { z } from 'zod';
import { setAuthCookies } from '@/lib/session';

const loginSchema = z.object({
  email: z.string().trim().email('Email không đúng định dạng'),
  password: z.string().min(1, 'Nhập mật khẩu'),
  next: z.string().optional(),
});

export async function loginAction(_prev: { message: string }, formData: FormData) {
  const parsed = loginSchema.safeParse(Object.fromEntries(formData));
  if (!parsed.success) return { message: parsed.error.issues[0].message };

  const res = await fetch(`${process.env.API_URL}/auth/login`, {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email: parsed.data.email, password: parsed.data.password }),
  });
  if (res.status === 401) return { message: 'Email hoặc mật khẩu không đúng' };   // thông báo chung (BR-03)
  if (res.status === 403) return { message: 'Tài khoản đã bị khóa' };
  if (!res.ok) return { message: 'Đăng nhập chưa thành công, vui lòng thử lại' };

  const data: { accessToken: string; refreshToken: string; role: string } = await res.json();
  await setAuthCookies(data);

  const next = parsed.data.next;
  const safeNext = next?.startsWith('/') && !next.startsWith('//') ? next : null;  // chặn open redirect
  redirect(safeNext ?? (data.role === 'customer' ? '/menu' : '/admin/orders'));
}

Trang /login dùng useActionState(loginAction, { message: '' }) và <form action={formAction}> có ô ẩn next. Vì form gửi thẳng tới Server Action, nó vẫn chạy được khi JavaScript chưa tải xong. Cookie chỉ được ghi trong Server Action, Route Handler hoặc proxy, không ghi được khi đang render Server Component.

2.2. Ma trận phân quyền và bảo vệ route

Phân tích trước (CLO1). Từ SRS (US-S01, US-A01) lập ma trận vai trò × chức năng. Mỗi ô "✔" phải có test case chứng minh được phép, mỗi ô "✘" phải có test case chứng minh bị chặn.

Lớp 1 – proxy.ts (kiểm tra nhanh, chuyển hướng sớm). Từ Next.js 16, file middleware.ts đổi tên thành proxy.ts và hàm xuất ra tên là proxy; Next.js 15 dùng tên cũ, nội dung giống nhau. Kiểm tra bằng npx next --version.

// proxy.ts (gốc dự án, cạnh thư mục app)   npm install jose
import { NextResponse, type NextRequest } from 'next/server';
import { decodeJwt } from 'jose';

const RULES: { prefix: string; roles: string[] }[] = [
  { prefix: '/admin/orders', roles: ['staff', 'admin'] },
  { prefix: '/admin', roles: ['admin'] },
  { prefix: '/checkout', roles: ['customer', 'staff', 'admin'] },
  { prefix: '/orders', roles: ['customer', 'staff', 'admin'] },
  { prefix: '/profile', roles: ['customer', 'staff', 'admin'] },
];

export async function proxy(req: NextRequest) {
  const rule = RULES.find((r) => req.nextUrl.pathname.startsWith(r.prefix));
  if (!rule) return NextResponse.next();

  let access = req.cookies.get('access_token')?.value;
  const refresh = req.cookies.get('refresh_token')?.value;
  let res = NextResponse.next();

  if (!access && refresh) {                                   // access hết hạn: làm mới (mục 2.3)
    const r = await fetch(`${process.env.API_URL}/auth/refresh`, {
      method: 'POST', headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ refreshToken: refresh }),
    });
    if (r.ok) {
      const t = await r.json();
      access = t.accessToken;
      req.cookies.set('access_token', t.accessToken);          // trang đang mở đọc được token mới
      res = NextResponse.next({ request: req });
      const opts = { httpOnly: true, secure: process.env.NODE_ENV === 'production', sameSite: 'lax' as const, path: '/' };
      res.cookies.set('access_token', t.accessToken, { ...opts, maxAge: 14 * 60 });
      res.cookies.set('refresh_token', t.refreshToken, { ...opts, maxAge: 7 * 24 * 3600 });
    }
  }

  if (!access) {
    const login = new URL('/login', req.url);
    login.searchParams.set('next', req.nextUrl.pathname);
    return NextResponse.redirect(login);
  }
  const { role } = decodeJwt(access) as { role: string };      // chỉ đọc, KHÔNG xác minh chữ ký
  if (!rule.roles.includes(role)) return NextResponse.rewrite(new URL('/forbidden', req.url));
  return res;
}

export const config = { matcher: ['/admin/:path*', '/checkout', '/orders/:path*', '/profile'] };

Lớp 2 – kiểm tra lại ở server. proxy chỉ đọc vai trò trong token mà không xác minh chữ ký (Next.js không giữ khóa bí mật của backend), nên nó chỉ để chuyển hướng sớm. Năm 2025, Next.js từng có lỗ hổng cho phép bỏ qua hoàn toàn middleware bằng một header đặc biệt (CVE-2025-29927). Ứng dụng nào chỉ dựa vào middleware đều bị mở toang. Vì vậy mỗi trang và mỗi Server Action nhạy cảm tự kiểm tra lại qua một lớp truy cập dữ liệu (Data Access Layer):

// lib/dal.ts
import 'server-only';
import { cache } from 'react';
import { redirect, forbidden } from 'next/navigation';
import { getAccessToken } from './session';

export type User = { userId: number; fullName: string; email: string; role: 'customer' | 'staff' | 'admin' };

// Backend xác minh chữ ký token; cache() để mỗi request chỉ gọi API một lần
export const getCurrentUser = cache(async (): Promise<User | null> => {
  const token = await getAccessToken();
  if (!token) return null;
  const res = await fetch(`${process.env.API_URL}/users/me`, {
    headers: { Authorization: `Bearer ${token}` }, cache: 'no-store',
  });
  return res.ok ? res.json() : null;
});

export async function requireRole(...roles: User['role'][]) {
  const user = await getCurrentUser();
  if (!user) redirect('/login');
  if (!roles.includes(user.role)) forbidden();     // hoặc redirect('/forbidden') nếu chưa bật forbidden()
  return user;
}

// app/admin/products/page.tsx
//   export default async function Page() { await requireRole('admin'); ... }

Lớp 3 – API. Backend trả 403 khi token không đủ quyền, và trả 404 khi khách xem đơn của người khác. Ba lớp có ba nhiệm vụ khác nhau: proxy cho trải nghiệm (chuyển hướng sớm), DAL bảo vệ trang và Server Action, API bảo vệ dữ liệu. Ẩn menu theo vai trò chỉ là giao diện, không được tính là phân quyền.

2.3. Gọi API kèm token, làm mới token và đăng xuất

Bổ sung vào lib/api.ts một hàm gọi API có xác thực. Hàm chỉ chạy ở server nên token không bao giờ xuống trình duyệt.

// lib/api.ts (thêm)
import { getAccessToken } from './session';

export class ApiError extends Error {
  constructor(public status: number, message: string) { super(message); }
}

export async function apiAuth<T>(path: string, init: RequestInit = {}): Promise<T> {
  const res = await fetch(`${process.env.API_URL}${path}`, {
    ...init,
    cache: 'no-store',                                        // dữ liệu riêng của từng người: không cache
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${await getAccessToken()}`, ...init.headers },
  });
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new ApiError(res.status, Array.isArray(body.message) ? body.message.join(', ') : body.message ?? 'Lỗi API');
  }
  return res.json() as Promise<T>;
}
  • Làm mới token: cookie access_token hết hạn sau 14 phút (sớm hơn JWT 1 phút). Lần vào trang được bảo vệ kế tiếp, proxy thấy chỉ còn refresh_token nên gọi POST /auth/refresh và ghi cặp token mới. Refresh thất bại (hết hạn, bị thu hồi, tài khoản bị khóa) thì chuyển về /login.
  • Không cache dữ liệu riêng: đơn của tôi, hồ sơ, màn hình quầy luôn dùng cache: 'no-store'. Nếu cache, người sau có thể thấy dữ liệu của người trước.
// app/actions/logout.ts
'use server';
import { cookies } from 'next/headers';
import { redirect } from 'next/navigation';
import { clearAuthCookies } from '@/lib/session';

export async function logoutAction() {
  const refreshToken = (await cookies()).get('refresh_token')?.value;
  if (refreshToken) {
    await fetch(`${process.env.API_URL}/auth/logout`, {           // thu hồi ở server (US-C13)
      method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ refreshToken }),
    }).catch(() => {});
  }
  await clearAuthCookies();
  redirect('/login');
}
// Header: <form action={logoutAction}><button>Đăng xuất</button></form>
// Nút đăng xuất phía client gọi useCart.getState().clear() trước khi gửi form (xóa giỏ hàng).

Header là Server Component gọi getCurrentUser() để hiện "Xin chào, Nguyễn Văn A" và menu theo vai trò; khách vãng lai thấy nút "Đăng nhập".

🆘 4. Góc trợ giúp và mở rộng ▼

proxy.ts không chạy: file phải nằm ở gốc dự án (hoặc trong src/ nếu dùng thư mục src), cùng cấp với app. Next.js 15 thì đặt tên middleware.ts và xuất hàm middleware. Kiểm tra lại matcher.

Lỗi "Cookies can only be modified in a Server Action or Route Handler": bạn gọi cookies().set trong Server Component. Chuyển việc ghi cookie vào Server Action hoặc proxy.

Đăng nhập xong vẫn bị đẩy về /login: trên môi trường chạy bằng HTTP (không HTTPS), cookie có secure: true sẽ không được lưu. Kiểm tra NODE_ENV; khi triển khai lên server Khoa phải dùng HTTPS.

forbidden() báo lỗi: hàm này cần bật experimental.authInterrupts trong next.config.ts. Nếu không muốn bật, dùng redirect('/forbidden').

Kiến thức mở rộng: Auth.js (NextAuth) khi cần đăng nhập bằng Google hoặc Microsoft của trường; Content Security Policy (CSP) để giảm rủi ro XSS.

Tự đánh giá: Mỗi ô "✘" trong ma trận phân quyền của nhóm bạn đã có một test case chứng minh bị chặn ở API chưa, hay chỉ bị chặn ở giao diện?
