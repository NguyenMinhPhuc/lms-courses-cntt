2.1. Khi nào cần 'use client'?

  • Khái niệm: Trong App Router, mọi component mặc định là Server Component. Chỉ thị 'use client' ở dòng đầu file đánh dấu ranh giới: file đó và mọi thứ nó import sẽ được gửi xuống trình duyệt.
  • Chi tiết kỹ thuật / Lý thuyết:
    • Bắt buộc 'use client' khi component dùng hook (useState, useEffect, useReducer…), sự kiện (onClick, onChange) hoặc Browser API (window, localStorage).
    • Đặt ranh giới càng sâu càng tốt (ở component lá). Trang chi tiết sự kiện vẫn là Server Component, chỉ khối chọn vé là Client Component.
    • File custom hook (hooks/useDebounce.ts) không cần 'use client' vì nó chỉ được gọi bên trong Client Component.
  • 💡 Ví dụ thực tế (Real-world Example):

    Trang /events/[id] hiển thị tiêu đề, mô tả, ảnh (tĩnh – Server Component, tốt cho SEO) và nhúng <TicketQuantitySelector /> (tương tác – Client Component). Người dùng nhận HTML nhanh, chỉ phần chọn vé tải thêm JavaScript.

2.2. useState và useReducer: quản lý state cục bộ

  • Khái niệm: useState phù hợp state đơn giản (số, chuỗi, mảng nhỏ). useReducer phù hợp khi state có nhiều hành động phụ thuộc lẫn nhau, ví dụ giỏ hàng nhiều loại vé.
  • Chi tiết kỹ thuật / Lý thuyết:
    • Luôn cập nhật bất biến (immutable): tạo mảng/đối tượng mới bằng map, filter, spread, không sửa trực tiếp.
    • Dùng dạng hàm setX(prev => ...) khi giá trị mới phụ thuộc giá trị cũ.
    • Với useReducer, khai báo hành động bằng discriminated union để TypeScript kiểm tra payload theo từng type.
// features/cart/cartReducer.ts
export interface CartItem {
  id: string;
  name: string;
  price: number;
  quantity: number;
}

export type CartAction =
  | { type: 'ADD_ITEM'; payload: CartItem }
  | { type: 'UPDATE_QUANTITY'; payload: { id: string; quantity: number } }
  | { type: 'REMOVE_ITEM'; payload: { id: string } }
  | { type: 'CLEAR' };

export function cartReducer(state: CartItem[], action: CartAction): CartItem[] {
  switch (action.type) {
    case 'ADD_ITEM': {
      const existing = state.find((item) => item.id === action.payload.id);
      if (existing) {
        return state.map((item) =>
          item.id === action.payload.id ? { ...item, quantity: item.quantity + action.payload.quantity } : item,
        );
      }
      return [...state, action.payload];
    }
    case 'UPDATE_QUANTITY':
      return state.map((item) =>
        item.id === action.payload.id ? { ...item, quantity: Math.max(0, action.payload.quantity) } : item,
      );
    case 'REMOVE_ITEM':
      return state.filter((item) => item.id !== action.payload.id);
    case 'CLEAR':
      return [];
  }
}

2.3. useEffect: Side Effect, Dependency Array và Cleanup

  • Khái niệm: useEffect dùng để đồng bộ component với hệ thống bên ngoài: hẹn giờ, đăng ký sự kiện window, gọi API, WebSocket. Nó chạy sau khi render.
  • Chi tiết kỹ thuật / Lý thuyết:
    • Mảng phụ thuộc quyết định khi nào effect chạy lại: thiếu phụ thuộc → dữ liệu cũ (stale); đưa vào một object/hàm tạo mới mỗi lần render → chạy liên tục.
    • Vòng lặp vô tận xảy ra khi effect gọi setState làm thay đổi chính phụ thuộc của nó.
    • Memory Leak xảy ra khi effect tạo setInterval, listener hay request mà không dọn dẹp. Luôn trả về hàm cleanup.
    • Không dùng effect để tính dữ liệu suy ra được từ props/state – tính trực tiếp khi render.
// ❌ Sai: effect dùng để tính toán + lặp vô tận khi filters là object mới mỗi render
const [visible, setVisible] = useState<EventItem[]>([]);
useEffect(() => {
  setVisible(events.filter((e) => e.price <= filters.maxPrice));
}, [events, filters]);

// ✅ Đúng: tính trực tiếp khi render (bọc useMemo nếu danh sách lớn)
const visibleEvents = events.filter((e) => e.price <= filters.maxPrice);

// ✅ Effect có cleanup: đếm ngược thời gian giữ ghế 10 phút
useEffect(() => {
  const timer = setInterval(() => {
    setSecondsLeft((s) => (s > 0 ? s - 1 : 0));
  }, 1000);
  return () => clearInterval(timer); // dọn dẹp khi rời trang → không rò rỉ bộ nhớ
}, []);

2.4. useMemo, useCallback và tối ưu re-render

  • Khái niệm: useMemo ghi nhớ giá trị tính toán; useCallback ghi nhớ tham chiếu hàm. Cả hai chỉ tính lại khi phụ thuộc thay đổi.
  • Chi tiết kỹ thuật / Lý thuyết:
    • useMemo dùng cho phép tính tốn kém (lọc/sắp xếp hàng nghìn sự kiện, tổng tiền giỏ hàng lớn).
    • useCallback có ý nghĩa khi hàm được truyền xuống component con bọc memo, hoặc nằm trong mảng phụ thuộc của useEffect ở component con.
    • Đừng bọc mọi thứ: phép tính rẻ không cần useMemo. Bài thực hành dùng useMemo cho tổng tiền để luyện cú pháp.
// Tối ưu tính tổng tiền giỏ hàng
const totalAmount = useMemo(() => {
  return cartItems.reduce((sum, item) => sum + item.price * item.quantity, 0);
}, [cartItems]);

// Hàm ổn định truyền cho component con – tránh effect con chạy lại liên tục
const handleFilterChange = useCallback((next: EventFilters) => {
  setFilters(next);
}, []);

Component chọn vé hoàn chỉnh (Guided Practice):

// components/features/TicketQuantitySelector.tsx
'use client';

import { useMemo, useState } from 'react';
import { Button } from 'antd';

interface TicketOption {
  id: string;
  name: string;
  price: number;
  quantity: number;
  max: number; // số vé còn lại cho phép mua
}

const INITIAL_TICKETS: TicketOption[] = [
  { id: 'early', name: 'Early Bird', price: 350000, quantity: 0, max: 10 },
  { id: 'vip', name: 'Vé VIP', price: 1000000, quantity: 0, max: 5 },
  { id: 'svip', name: 'Vé SVIP', price: 2500000, quantity: 0, max: 2 },
];

const vnd = new Intl.NumberFormat('vi-VN', { style: 'currency', currency: 'VND' });

export default function TicketQuantitySelector() {
  const [tickets, setTickets] = useState<TicketOption[]>(INITIAL_TICKETS);

  const handleIncrease = (id: string) =>
    setTickets((prev) => prev.map((t) => (t.id === id && t.quantity < t.max ? { ...t, quantity: t.quantity + 1 } : t)));

  const handleDecrease = (id: string) =>
    setTickets((prev) => prev.map((t) => (t.id === id && t.quantity > 0 ? { ...t, quantity: t.quantity - 1 } : t)));

  const { totalAmount, totalTickets } = useMemo(
    () => ({
      totalAmount: tickets.reduce((sum, t) => sum + t.price * t.quantity, 0),
      totalTickets: tickets.reduce((sum, t) => sum + t.quantity, 0),
    }),
    [tickets],
  );

  return (
    <section>
      {tickets.map((t) => (
        <div key={t.id} className="ticket-row">
          <span>{t.name} – {vnd.format(t.price)}</span>
          <Button onClick={() => handleDecrease(t.id)} disabled={t.quantity === 0}>−</Button>
          <strong>{t.quantity}</strong>
          <Button onClick={() => handleIncrease(t.id)} disabled={t.quantity === t.max}>+</Button>
        </div>
      ))}
      <p>Tổng: {totalTickets} vé · {vnd.format(totalAmount)}</p>
      <Button type="primary" disabled={totalTickets === 0}>Thanh toán</Button>
    </section>
  );
}

2.5. State Lifting và kỹ thuật Debounce

  • Khái niệm: State Lifting là chuyển state lên component cha chung gần nhất khi hai hay nhiều component con cần cùng dữ liệu. Debounce là trì hoãn cập nhật cho tới khi người dùng ngừng gõ một khoảng thời gian.
  • Chi tiết kỹ thuật / Lý thuyết:
    • Sơ đồ ghế và khung tổng tiền là hai component anh em → state selectedSeats phải nằm ở cha, con nhận dữ liệu qua props và báo thay đổi qua callback.
    • Debounce 200ms cho ô tìm kiếm: gõ "concert" chỉ kích hoạt lọc 1 lần thay vì 7 lần.
// hooks/useDebounce.ts
import { useEffect, useState } from 'react';

export function useDebounce<T>(value: T, delay: number): T {
  const [debouncedValue, setDebouncedValue] = useState(value);
  useEffect(() => {
    const handler = setTimeout(() => setDebouncedValue(value), delay);
    return () => clearTimeout(handler);
  }, [value, delay]);
  return debouncedValue;
}

// components/features/EventFilterBar.tsx
'use client';

import { useEffect, useState } from 'react';
import { useDebounce } from '@/hooks/useDebounce';

export type PriceRange = 'all' | 'free' | 'under-500k' | 'over-500k';

export interface EventFilters {
  keyword: string;
  priceRange: PriceRange;
  date: string; // 'YYYY-MM-DD' hoặc ''
}

interface EventFilterBarProps {
  onFilterChange: (filters: EventFilters) => void; // cha phải truyền hàm ổn định (useCallback/setState)
}

export default function EventFilterBar({ onFilterChange }: EventFilterBarProps) {
  const [searchKeyword, setSearchKeyword] = useState('');
  const [priceRange, setPriceRange] = useState<PriceRange>('all');
  const [selectedDate, setSelectedDate] = useState('');
  const debouncedKeyword = useDebounce(searchKeyword, 200);

  useEffect(() => {
    onFilterChange({ keyword: debouncedKeyword, priceRange, date: selectedDate });
  }, [debouncedKeyword, priceRange, selectedDate, onFilterChange]);

  return (
    <div className="filter-bar">
      <input value={searchKeyword} onChange={(e) => setSearchKeyword(e.target.value)} placeholder="Tìm sự kiện..." />
      <select value={priceRange} onChange={(e) => setPriceRange(e.target.value as PriceRange)}>
        <option value="all">Mọi mức giá</option>
        <option value="free">Miễn phí</option>
        <option value="under-500k">Dưới 500.000 ₫</option>
        <option value="over-500k">Từ 500.000 ₫</option>
      </select>
      <input type="date" value={selectedDate} onChange={(e) => setSelectedDate(e.target.value)} />
    </div>
  );
}

Bẫy thường gặp: Nếu component cha truyền onFilterChange={(f) => setFilters(f)} (hàm mới mỗi lần render), effect trong EventFilterBar sẽ chạy lại sau mỗi lần cha render, cha lại setFilters một object mới… và vòng lặp không dừng. Hãy truyền thẳng setFilters hoặc bọc bằng useCallback.

📌 Tóm tắt & điểm cần nhớ

  • 🔹 'use client' là ranh giới: chỉ thêm khi cần hook, sự kiện hoặc Browser API; đặt ở component lá để trang vẫn là Server Component.
  • 🔹 useState vs useReducer: state đơn giản dùng useState; nhiều hành động liên quan (giỏ hàng) dùng useReducer với discriminated union. Luôn cập nhật bất biến.
  • 🔹 useEffect chỉ để đồng bộ với bên ngoài: khai báo đủ phụ thuộc, luôn cleanup timer/listener; dữ liệu suy ra được thì tính khi render.
  • 🔹 useMemo ghi nhớ giá trị, useCallback ghi nhớ hàm: dùng khi có lý do (tính toán nặng, hàm truyền xuống con/effect), không bọc tràn lan.
  • 🔹 State Lifting & Debounce: dữ liệu dùng chung đặt ở cha gần nhất; debounce 200ms cho ô tìm kiếm để giao diện không giật.
  • 🔹 AI debug có kiểm soát: yêu cầu AI giải thích nguyên nhân theo dependency array, không chấp nhận giải pháp tắt cảnh báo ESLint.

// components/features/SeatBooking.tsx – khung gợi ý cho nhóm
'use client';

import { useState } from 'react';

const ROWS = ['A', 'B', 'C', 'D', 'E'] as const;
const COLS = 8;
const MAX_SEATS = 6;
const SEAT_PRICE = 300000;
const SOLD_SEATS = new Set(['A3', 'A4', 'C5', 'D1', 'E8']);

type SeatStatus = 'available' | 'selected' | 'sold';

function SeatMatrixPicker({ selectedSeats, onToggle }: { selectedSeats: string[]; onToggle: (id: string) => void }) {
  const getStatus = (id: string): SeatStatus =>
    SOLD_SEATS.has(id) ? 'sold' : selectedSeats.includes(id) ? 'selected' : 'available';

  return (
    <div className="seat-grid">
      {ROWS.map((row) =>
        Array.from({ length: COLS }, (_, i) => {
          const id = `${row}${i + 1}`;
          const status = getStatus(id);
          return (
            <button key={id} type="button" className={`seat seat--${status}`}
              disabled={status === 'sold'} onClick={() => onToggle(id)}>
              {id}
            </button>
          );
        }),
      )}
    </div>
  );
}

export default function SeatBooking() {
  const [selectedSeats, setSelectedSeats] = useState<string[]>([]);
  const [warning, setWarning] = useState('');

  const handleToggle = (id: string) => {
    if (selectedSeats.includes(id)) {
      setSelectedSeats(selectedSeats.filter((s) => s !== id));
      setWarning('');
    } else if (selectedSeats.length >= MAX_SEATS) {
      setWarning(`Mỗi lần chỉ được chọn tối đa ${MAX_SEATS} ghế.`);
    } else {
      setSelectedSeats([...selectedSeats, id]);
      setWarning('');
    }
  };

  return (
    <section>
      <SeatMatrixPicker selectedSeats={selectedSeats} onToggle={handleToggle} />
      <p>Ghế đã chọn: {selectedSeats.join(', ') || 'chưa có'}</p>
      <p>Thành tiền: {(selectedSeats.length * SEAT_PRICE).toLocaleString('vi-VN')} ₫</p>
      {warning && <p role="alert">{warning}</p>}
    </section>
  );
}

❓ Kiểm tra nhanh (Self-Assessment)

Câu 1: Sự khác biệt về mục đích giữa useMemo và useCallback là gì?

  • A. useMemo dùng cho Server Component, useCallback dùng cho Client Component
  • B. useMemo chạy trước render, useCallback chạy sau render
  • C. useMemo thay thế useState, useCallback thay thế useEffect
  • D. useMemo ghi nhớ giá trị tính toán, useCallback ghi nhớ tham chiếu hàm
👉 Bấm vào đây để xem Đáp án & Giải thích Đáp án đúng: D
Giải thích: useMemo trả về kết quả đã ghi nhớ (ví dụ tổng tiền); useCallback trả về cùng một hàm giữa các lần render cho tới khi phụ thuộc đổi. Cả hai chỉ chạy trong Client Component.

Câu 2: Đoạn code useEffect(() => { setCount(count + 1); }, [count]); gây ra vấn đề gì?

  • A. Memory leak do thiếu cleanup
  • B. Vòng lặp re-render vô tận vì effect thay đổi chính phụ thuộc của nó
  • C. Effect không bao giờ chạy
  • D. Lỗi biên dịch TypeScript
👉 Bấm vào đây để xem Đáp án & Giải thích Đáp án đúng: B
Giải thích: Mỗi lần effect chạy, count tăng → component render lại → count trong mảng phụ thuộc đổi → effect chạy tiếp, không có điểm dừng.

Câu 3: Sơ đồ chọn ghế và khung tổng tiền là hai component anh em cùng cần danh sách ghế đã chọn. Giải pháp phù hợp nhất ở mức bài học này là gì?

  • A. Mỗi component giữ một bản useState riêng và tự đồng bộ bằng useEffect
  • B. Lưu danh sách ghế vào biến toàn cục ngoài component
  • C. Nâng state selectedSeats lên component cha chung và truyền xuống qua props/callback
  • D. Đọc danh sách ghế từ DOM bằng document.querySelectorAll
👉 Bấm vào đây để xem Đáp án & Giải thích Đáp án đúng: C
Giải thích: Đây là State Lifting: một nguồn dữ liệu duy nhất ở cha, hai con luôn hiển thị nhất quán. Đồng bộ hai state bằng effect dễ lệch dữ liệu và render thừa.

Câu 4: Trường hợp nào KHÔNG cần thêm 'use client'?

  • A. Component hiển thị tiêu đề và mô tả sự kiện từ props, không có tương tác
  • B. Component có nút onClick tăng số lượng vé
  • C. Component đọc localStorage để lấy danh sách yêu thích
  • D. Component dùng useState để lưu từ khóa tìm kiếm
👉 Bấm vào đây để xem Đáp án & Giải thích Đáp án đúng: A
Giải thích: Component chỉ hiển thị dữ liệu nên để là Server Component. Sự kiện, Browser API và hook đều yêu cầu Client Component.
