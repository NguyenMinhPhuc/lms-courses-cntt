BÀI 11 - Hoàn thiện project và quản lý mã nguồn với GitHub (5 tiết: 1,5 LT / 3,5 TH)

Bốn người, bốn máy, bốn phiên bản main.py gửi qua Zalo: "main_final.py", "main_final_2.py", "main_final_thật_sự.py". Ghép lại thì mất hàm của nhau. GitHub giải quyết đúng chuyện này, và lịch sử commit cũng cho thấy ai đã làm phần nào.

Mục tiêu: Ghép được các hàm của thành viên thành chương trình hoàn chỉnh và kiểm thử tích hợp với dữ liệu thường, biên và sai; lưu được mã nguồn lên GitHub bằng các thao tác cơ bản (tạo repository, commit, push); viết được README và kịch bản demo.

Nội dung:

  • Ý chính 1 - Ghép code và kiểm thử tích hợp: danh sách kiểm thử theo từng chức năng.
  • Ý chính 2 - GitHub cơ bản: repository, clone, commit, push bằng GitHub Desktop; thông điệp commit rõ ràng.
  • Ý chính 3 - README.md: giới thiệu dự án, cách chạy, thành viên và vai trò, khai báo dùng AI.
  • Ý chính 4 - Rà soát cùng AI và kịch bản demo: AI góp ý, từng thành viên giải thích được phần mình.

Kết quả cần đạt: Repository của nhóm trên GitHub có mã nguồn chạy được, lịch sử commit của mọi thành viên, README hoàn chỉnh và bản nháp kịch bản demo.

CLO liên quan: CLO1, CLO3.

📚 2. Học liệu chính ▼

2.1. Ghép code và kiểm thử tích hợp

Mỗi hàm chạy đúng khi thử riêng chưa chắc chạy đúng khi ghép. Kiểm thử tích hợp là chạy cả chương trình qua menu, theo từng chức năng, với 5 loại dữ liệu:

Loại dữ liệuVí dụ với chức năng "Thêm khoản chi"
Bình thường50000, danh mục "Ăn uống"
Giá trị biên1 đồng; đúng bằng ngân sách còn lại
Sai kiểu"năm mươi nghìn", để trống
Ngoài khoảng-20000, 0
Chưa có dữ liệuchọn Thống kê khi danh sách còn rỗng

Ghi kết quả vào bảng kiểm thử (dữ liệu, mong đợi, thực tế, đạt/chưa đạt). Lỗi tìm được giao lại cho người viết hàm đó sửa; đây là lúc lời chú thích và docstring ở bài 09 phát huy tác dụng.

2.2. GitHub cơ bản

  • Git lưu lịch sử thay đổi của mã nguồn; GitHub (github.com) là nơi lưu repository trên mạng để cả nhóm dùng chung.
  • Repository (repo): thư mục dự án có lịch sử. Commit: một lần lưu thay đổi kèm thông điệp. Push: đẩy các commit lên GitHub. Pull: lấy thay đổi mới của bạn cùng nhóm về máy.

Các bước với GitHub Desktop (desktop.github.com):

  1. Trưởng nhóm tạo repository trên github.com (tick Add a README file), vào Settings → Collaborators mời các thành viên.
  2. Mỗi thành viên mở GitHub Desktop, File → Clone repository, chọn repo của nhóm.
  3. Mở thư mục bằng VS Code, viết code phần mình.
  4. Quay lại GitHub Desktop: bấm Fetch/Pull origin để lấy code mới nhất, ghi thông điệp ở ô Summary, bấm Commit to main, rồi Push origin.

Thông điệp commit nói rõ đã làm gì: Thêm hàm thong_ke_theo_danh_muc, Sửa lỗi chia cho 0 khi chưa có khoản chi. Tránh update, sửa, final. Mỗi người commit phần mình phụ trách: lịch sử commit là minh chứng cho CLO3. Lệnh Git trong Terminal (git add, git commit -m "...", git push) làm cùng việc, bạn sẽ học kỹ ở các học phần sau.

2.3. README.md

README là trang đầu tiên người khác thấy khi mở repository. Viết bằng Markdown (# tiêu đề, - gạch đầu dòng, ![mô tả](docs/anh.png) chèn ảnh):

# Quản lý chi tiêu sinh viên

Chương trình dòng lệnh ghi lại và thống kê chi tiêu cá nhân.

## Thành viên và vai trò
- Nguyễn Văn A: nhap_lieu.py, chức năng Thêm khoản chi
- Trần Thị B: chức năng Thống kê, lưu đồ
- ...

## Cách chạy
Python 3.10+. Mở thư mục dự án, chạy: python main.py

## Ảnh chụp màn hình
![Menu chính](docs/menu.png)

## Khai báo sử dụng AI
Dùng ChatGPT để brainstorm chức năng và giải thích lỗi; chi tiết trong NHAT-KY-PROMPT.md.

2.4. Rà soát cùng AI và kịch bản demo

"Đây là chương trình Python của nhóm sinh viên năm nhất (dán code). Liệt kê các trường hợp nhập liệu có thể làm chương trình dừng hoặc cho kết quả sai, kèm số dòng. Không viết lại code."

Kịch bản demo 3 phút: chức năng nào chạy trước, dùng dữ liệu nào (chuẩn bị sẵn để không phải nghĩ khi đứng trước lớp), cố ý nhập sai một lần để cho thấy chương trình không dừng.

Tập vấn đáp trong nhóm: mỗi người hỏi người khác 2 câu về phần không phải của mình. Nếu cả nhóm chỉ một người hiểu toàn bộ code, buổi Showcase sẽ lộ ra ngay.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1 tiết): repository của nhóm

  1. Trưởng nhóm tạo repository, mời thành viên; mọi người clone về máy.
  2. Mỗi người thêm một dòng tên mình vào README, commit, push; lần lượt pull để thấy thay đổi của nhau.
  3. Đưa các file .py, thư mục docs/ (lưu đồ) lên repository.

👥 Làm việc nhóm (2,5 tiết): ghép, kiểm thử, hoàn thiện

  • Ghép code; chạy kiểm thử tích hợp với 5 loại dữ liệu cho từng chức năng; sửa lỗi và commit.
  • Cập nhật lưu đồ cho khớp code; chạy ruff check.
  • Viết README theo mẫu mục 2.3; viết kịch bản demo; tập vấn đáp chéo.

Nộp: link repository, bảng kiểm thử tích hợp, bản nháp kịch bản demo. Hoàn thành khi: mỗi thành viên có ít nhất 2 commit có nội dung code; không dữ liệu xấu nào trong bảng kiểm thử làm chương trình dừng.

🆘 4. Góc trợ giúp và mở rộng ▼

Push bị từ chối (rejected): trên GitHub đã có commit mới của bạn khác. Bấm Pull origin trước rồi push lại.

Xung đột (conflict): hai người sửa cùng một đoạn trong cùng một file. GitHub Desktop sẽ báo file xung đột; mở bằng VS Code, chọn giữ phần nào (Accept Current/Incoming/Both), lưu, rồi commit. Cách phòng tránh: mỗi người làm ở file hoặc hàm riêng như bảng phân công.

Không thấy nút Push: chưa được trưởng nhóm thêm vào Collaborators, hoặc chưa đăng nhập GitHub trong GitHub Desktop.

Kiến thức mở rộng: nhánh (branch) và Pull Request để review code trước khi ghép; file .gitignore để bỏ qua thư mục __pycache__.

Tự đánh giá: Mở tab History trong GitHub Desktop: nhìn lịch sử commit, người ngoài có biết ai làm phần nào không?
