BÀI 09 - Tổ chức mã nguồn và chuẩn PEP 8 (5 tiết: 1,5 LT / 3,5 TH)

Code được đọc nhiều hơn được viết. Ba tuần nữa, chính bạn đọc lại hàm f(a, b, c) và không nhớ nó làm gì; bạn cùng nhóm thì càng không. Mini Project sắp bắt đầu, và code của mỗi người phải để người khác đọc hiểu được.

Mục tiêu: Giải thích được phạm vi của biến cục bộ và toàn cục; áp dụng được quy tắc đặt tên và trình bày theo PEP 8; viết được docstring cho hàm và module; refactor được code cho dễ đọc mà không làm đổi kết quả, có dùng công cụ Ruff.

Nội dung:

  • Ý chính 1 - Phạm vi biến: biến cục bộ, biến toàn cục, lỗi UnboundLocalError; truyền tham số và return thay cho biến toàn cục.
  • Ý chính 2 - PEP 8: snake_case, hằng số viết hoa, thụt lề 4 dấu cách, khoảng trắng, độ dài dòng; Ruff trong VS Code.
  • Ý chính 3 - Docstring và chú thích: mô tả hàm làm gì; chú thích giải thích "vì sao".
  • Ý chính 4 - Refactor có kiểm soát: đổi tên, bỏ số ma thuật, chạy lại để chắc kết quả không đổi; refactor cùng AI.

Kết quả cần đạt: Student Dashboard bản hoàn chỉnh theo PEP 8, mọi hàm có docstring, ruff check không còn cảnh báo, kèm bảng các thay đổi khi refactor.

CLO liên quan: CLO1.

📚 2. Học liệu chính ▼

2.1. Phạm vi biến (scope)

  • Biến cục bộ (local): tạo bên trong hàm (kể cả tham số), chỉ dùng được trong hàm đó, mất đi khi hàm kết thúc.
  • Biến toàn cục (global): tạo ngoài mọi hàm; hàm đọc được, nhưng nếu hàm gán cho tên đó thì Python coi đó là biến cục bộ mới.
tong = 0


def cong_diem(d):
    tong = tong + d      # lỗi ở dòng này
    return tong


cong_diem(8)
# UnboundLocalError: cannot access local variable 'tong'
#                    where it is not associated with a value

Cách đúng: đưa dữ liệu vào qua tham số và lấy ra bằng return: def cong_diem(tong, d): return tong + d, gọi tong = cong_diem(tong, 8). Từ khóa global giúp "chạy được" nhưng làm hàm phụ thuộc vào biến bên ngoài, khó kiểm thử; học phần này không dùng global.

2.2. PEP 8 và công cụ Ruff

PEP 8 là hướng dẫn trình bày mã Python chính thức. Những quy tắc dùng nhiều nhất:

Quy tắcĐúngChưa đúng
Tên biến, hàm: chữ thường nối gạch dướidiem_tb, tinh_diem_tb()DiemTB, tinhDiem()
Hằng số: chữ hoaNGUONG_DAT = 4.0nguong = 4.0 rồi không đổi
Thụt lề 4 dấu cách4 dấu cách mỗi cấp2 dấu cách, trộn Tab
Khoảng trắng quanh toán tử, sau dấu phẩyx = a * 0.3 + b, f(a, b)x=a*0.3+b, f(a,b)
Mỗi lệnh một dòng; dòng không quá 79 ký tựif x >= 4: xuống dòng rồi lệnhif x>=4: print("Dat")
2 dòng trống giữa các hàm cấp ngoài cùngnhư code mẫu bài 08các hàm dính liền nhau

Ruff (cài extension Ruff trong VS Code, hoặc pip install ruff): ruff check ten_file.py tìm lỗi và vi phạm như nhiều lệnh trên một dòng, biến không dùng, import thừa; ruff format ten_file.py tự sửa khoảng trắng, thụt lề, xuống dòng. Công cụ không đặt lại tên giúp bạn: f(a, b, c) sau khi format vẫn là f(a, b, c).

2.3. Docstring và chú thích

  • Docstring là chuỗi ba dấu nháy ngay dưới dòng def (hoặc đầu file), mô tả hàm làm gì, nhận gì, trả về gì. VS Code hiện docstring khi rê chuột vào tên hàm; help(xep_loai) cũng in ra nó.
  • Chú thích # giải thích vì sao, không lặp lại code. Tốt: # trọng số theo đề cương: 30-30-40. Thừa: # cộng 1 vào i cho dòng i += 1.
def thong_ke(diem_list):
    """Trả về (thấp nhất, cao nhất, trung bình) của một list điểm khác rỗng."""
    return min(diem_list), max(diem_list), sum(diem_list) / len(diem_list)

2.4. Refactor có kiểm soát

Refactor là sửa cấu trúc code cho dễ đọc, dễ sửa mà không đổi kết quả. Quy trình: chạy và ghi kết quả trước → sửa một chỗ nhỏ → chạy lại, so kết quả → lặp lại → cuối cùng chạy ruff check.

# TRƯỚC
def f(a,b,c):
  x=a*0.3+b*0.3+c*0.4
  if x>=4: print("Dau")
  else: print("Rot")
  return x
# SAU
NGUONG_DAT = 4.0


def tinh_diem_tb(qt, gk, ck):
    """Trả về điểm học phần theo trọng số 30-30-40."""
    return qt * 0.3 + gk * 0.3 + ck * 0.4


def ket_qua(diem):
    """Trả về "Đậu" nếu diem đạt NGUONG_DAT, ngược lại "Rớt"."""
    if diem >= NGUONG_DAT:
        return "Đậu"
    return "Rớt"

Các thay đổi: tên có nghĩa; số 4 "ma thuật" thành hằng số NGUONG_DAT; tách một hàm làm hai việc (tính và in) thành hai hàm, mỗi hàm một việc; hàm trả về chuỗi thay vì in; thêm docstring; trình bày theo PEP 8.

"Refactor đoạn code sau theo PEP 8, giữ nguyên chức năng. Liệt kê từng thay đổi và lý do. Không thêm thư viện hay tính năng mới. [dán code]" Sau đó chạy lại cả bản cũ và bản AI đề xuất với cùng dữ liệu; chỉ nhận thay đổi giữ đúng kết quả.

💡 3. Hoạt động & Thực hành trên lớp ▼

🧑‍🏫 Thực hành có hướng dẫn (1,5 tiết): refactor một chương trình "xấu"

  1. Chạy ví dụ UnboundLocalError ở mục 2.1, sửa bằng tham số và return.
  2. Cài extension Ruff; mở chương trình "xấu" giảng viên cung cấp, chạy ruff check và đọc từng cảnh báo.
  3. Ghi kết quả chạy với 3 bộ dữ liệu, rồi refactor từng bước theo mục 2.4, chạy lại sau mỗi bước.
  4. Nhờ AI đề xuất refactor; lập bảng: thay đổi của AI, nhận hay không, lý do.

🆘 4. Góc trợ giúp và mở rộng ▼

Lệnh ruff báo "not recognized": extension Ruff trong VS Code vẫn hoạt động (gạch chân và Format Document); muốn dùng lệnh trong Terminal thì cài pip install ruff.

Refactor xong chương trình chạy khác trước: quay lại bản trước (vì vậy nên sửa từng bước nhỏ và lưu bản cũ), so từng thay đổi để tìm chỗ làm đổi kết quả.

Ruff báo F401 ... imported but unused: có import mà không dùng; xóa dòng đó.

Kiến thức mở rộng: gợi ý kiểu dữ liệu (type hints) def tinh_diem_tb(qt: float, gk: float, ck: float) -> float:; bật Format on Save trong VS Code để tự format mỗi lần lưu.

Tự đánh giá: Đưa file của bạn cho một bạn khác đọc 2 phút, không giải thích. Bạn ấy có nói đúng từng hàm làm gì không?
